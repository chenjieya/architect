决策树是最"讲人话"的机器学习算法——因为它做决策的方式，和你生活中做选择的方式几乎一模一样。

## 1. 一句话理解

**把决策过程写成一棵"不断提问"的树，一路 if-else 走到叶子，得到答案。**

比如相亲筛选：

```text
颜值高吗？
├── 否 → 看房？有房 → 通过 / 无房 → 待定
└── 是 → 看车？有车 → 通过 / 无车 → 待定
```

每一个"问题"就是树的一个分叉，最后落到哪个"结论"就是叶子节点。

## 2. 树的三个部分

| 概念     | 对应相亲例子     | 作用               |
| -------- | ---------------- | ------------------ |
| 根节点   | "颜值高吗"       | 最顶层、第一个问题 |
| 内部节点 | "有房吗""有车吗" | 中间的分支判断     |
| 叶子节点 | "通过 / 待定"    | 最终的分类结果     |

> 决策树既能做**分类**（结果是"通过/不通过"），也能做**回归**（结果是"预测价格 200 万"），后者叫回归树。

## 3. 关键问题：每个节点该问什么

树的结构不是拍脑袋定的，而是靠数据"算"出来的。核心是**每一步都挑一个能把数据"分得最干净"的特征来提问**。

衡量"分得干净不干净"的指标有两个主流方案：

- **信息增益**：基于"信息熵"——一个集合越乱，熵越大。好的问题是"问完之后，两边都变得更确定（熵大幅下降）"。下降得越多，说明这个特征越值得先问。
- **基尼系数**：另一个衡量"不纯度"的指标，思路类似——分完两边越"纯"（同类聚在一起）越好。CART 树常用它。

**大白话**：先问那个"答案最能区分结果"的问题，再往下逐层细化。就像老师先把"及格/不及格"区分开，再在不及格里细分"差一点/差很多"。

## 4. 一个例子：银行放贷

| 月收入（元） | 有房 | 有逾期记录 | 是否放贷 |
| ------------ | ---- | ---------- | -------- |
| 30000        | 是   | 否         | 是       |
| 20000        | 否   | 否         | 是       |
| 8000         | 否   | 是         | 否       |
| 12000        | 是   | 是         | 否       |

决策树可能长成："有逾期记录？→ 是 → 不放贷；否 → 月收入 ≥ 20000？→ 是 → 放贷 / 否 → 不放贷"。整棵树的判断规则完全透明，任何一个结果都能追溯到"为什么"。

## 5. 优点与局限

**优点**：

- **可解释**：规则一目了然，能讲清楚"为什么这么判"，适合风控、医疗等需要解释的行业。
- **无需太多预处理**：对数据尺度不敏感，类别特征、缺失值都好处理。
- **既能分类又能回归**。

**局限**：

- **容易过拟合**：树长得太深，会把训练数据里的"噪音"也背下来，换新数据就不准。
- **对数据变化敏感**：训练数据稍微一变，树结构可能大不相同。
- **单棵树能力有限**：准确率往往不如集成方法。

**补救办法**：**剪枝**（限制树深、限制叶子数、限制分裂样本量），或引入**随机森林、梯度提升树（GBDT）**等集成方法——"多棵树投票/接力"，大幅提升稳定性，代价是解释性下降。

## 6. 总结

- 决策树 = **用 if-else 递归地把数据越分越纯**，最终得到分类或回归结果。
- 关键是"每一步挑最能区分结果的特征来提问"（信息增益 / 基尼系数）。
- 优点是**可解释、直观**，缺点是**容易过拟合**，常靠剪枝或集成来救。
