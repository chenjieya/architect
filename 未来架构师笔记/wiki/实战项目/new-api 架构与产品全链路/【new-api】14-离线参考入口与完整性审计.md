### 1.2 本次结论与新的项目方向

**原来的 14 篇足够帮助理解整体架构，但不够直接支撑脱离仓库的重新实现。此次补充后，它们与 14—21 篇、离线附件共同构成 ModelDock 的参考基线。** 它不是已经完成的 ModelDock PRD、数据库迁移脚本或兼容性认证。

用户已确认：产品名为 **ModelDock**；另起 Python 后端项目，不在此 Go 仓库上二开；参考 new-api 的业务逻辑、数据建模和前端样式。前端是否继续使用 React、Python 框架、主数据库、支付平台、第一版支持的模型均未确认。不得把本资料中的候选方案写成用户已批准的技术决策。

new-api 是参考项目，QuantumNous 是上游组织；ModelDock 是用户计划的新产品。不要把参考项目的实现、演示数据、名称与新产品的实际能力混在一起。

双链按唯一文件名解析，目录不必放在 C 盘。用 Obsidian 打开包含这两个目录的共同根目录。纯文本 AI 工具先读取本页与 20，再按文件名定位附件。源码快照为 `.txt`，便于只读检索；部分阅读器不能内嵌打开它，可交给文本编辑器或开发工具读取。

### 1.7 已知边界，未来不要靠猜补齐

- 本次没有运行原应用、连接支付沙箱、调用模型，也没有验证真实数据库迁移。数据库资料是静态声明与实现解释，不是生产数据库快照。
- OpenAPI 文件不覆盖每个新路由，部分管理响应 schema 不完整；已同时保存路由声明、控制器和前端类型作为离线补充。精确行为有冲突时以对应实现为证据，并在新项目契约中明确选择。
- 原生插件动态路由受插件元数据与配置影响；静态路由清单不是运行时所有有效 URL 的穷举。所有厂商的最新协议、报价、退款政策均不在本资料承诺范围。
- 只有四张原始演示截图，未生成其他页面的“伪原图”；移动端、暗色、弹窗的外观依据样式和组件代码，未做运行截图比对。
- 源码附件是精选证据集合，不是可编译工程，不能用其 build 结果声称原项目兼容。
- 独立使用 Python 不等于自动改变已有素材的授权条件；附件完整保留上游 LICENSE、NOTICE 和源码署名，实际复用范围应单独确认。此处只记录来源，不作法律结论。
