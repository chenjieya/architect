## 1. 数组结构

JavaScript 确实有 Array，它是带特殊索引和 length 行为的对象，不等于普通类数组对象。语言规范不承诺底层连续或不连续；引擎可能为稠密数组使用高效存储，也可能切换表示。

### 1.1 思路与过程

1. 数组把索引和元素联系起来，但 JavaScript 的数组规范描述的是可观察行为，并不规定物理地址布局。普通类数组对象即使有数字属性与 length，也不自动获得 Array 的全部行为。

2. 连续数组模型下，按有效下标访问通常是常数步；按值找元素最坏需要扫描全部；头部插删通常需要搬移后面的元素。尾部追加可能触发扩容，因此通常分析摊还成本。

3. 稀疏数组的空槽与值为 undefined 的已有属性不同，一些遍历方法会跳过空槽。length 也不能直接用来推断精确内存大小。数组变量可以保存对象引用，但不应直接把语言层引用理解为裸内存地址。

### 1.2 适用条件与容易出错的地方

按下标访问、按值搜索、尾部追加、头部删除是不同操作。普通对象 {0:1,1:2} 不是 Array；可用 Array.isArray 判断。new Array(3) 创建三个空槽，和 [undefined,undefined,undefined] 不完全相同。

### 1.4 规范核对

JavaScript 数组的索引与长度行为按语言规范定义，底层物理存储不是规范承诺。参见 [ECMAScript 数组对象规范](https://tc39.es/ecma262/multipage/indexed-collections.html)。
