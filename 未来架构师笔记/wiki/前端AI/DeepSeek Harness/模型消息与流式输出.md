DeepSeek Harness 不把模型回复简单当成一整段字符串。它把模型消息拆成更细的结构：消息、内容块、流式片段。

这样做是为了支持更复杂的 Agent 场景：模型可能一边输出文字，一边输出推理内容，还可能生成工具调用。

## 1. Message 是什么

`Message` 是一条对话消息。它有三个关键部分：

| 字段      | 含义                            |
| --------- | ------------------------------- |
| `role`    | 谁说的：system、user、assistant |
| `content` | 这条消息里包含哪些内容块        |
| `source`  | 这条消息从哪里来                |

普通聊天里，一条消息往往就是一段文本。但 Agent 场景更复杂，所以 `content` 是一个内容块数组。

## 2. 内容块是什么

内容块就是消息里的“积木块”。官方文档列出的核心块包括：

| 内容块        | 用途                               |
| ------------- | ---------------------------------- |
| `text`        | 普通可见文本                       |
| `reasoning`   | 模型推理内容，和最终可见文本区分开 |
| `image`       | 图片附件                           |
| `tool-call`   | 模型要求调用工具                   |
| `tool-result` | 工具返回给模型的结果               |

这样一条 assistant 消息就不一定只有文本。它可能是：

```text
assistant message
  -> text block
  -> tool-call block
```

Agent 循环看到 `tool-call` 后，就会进入 [[工具调用与执行流水线]]。

## 3. StreamChunk 是什么

模型流式输出时，不是一次性返回完整消息，而是一小块一小块返回。DeepSeek Harness 把这些原始流式片段叫 `StreamChunk`。

常见片段包括：

- `block-start`：一个内容块开始了。
- `text-delta`：文本增量。
- `reasoning-delta`：推理增量。
- `tool-call-delta`：工具调用参数的增量。
- `block-end`：一个内容块组装完成。
- `usage`：模型用量。
- `finish`：本次流结束。

可以把它理解成拼积木：`delta` 是一块块零件，`block-end` 是一个完整积木拼好了。

## 4. 为什么要保留流式片段

如果只关心最终答案，保留完整 `assistant/message` 似乎就够了。但 DeepSeek Harness 还保留 `assistant/chunk`，原因是：

- UI 要实时显示模型正在输出。
- 工具调用参数可能是流式拼出来的。
- 回放时要尽量还原当时看到的过程。
- 用量和结束原因也来自流式协议。

这和 [[会话日志与可回放上下文]] 的原则一致：重要的模型过程要能记录和重建。

## 5. 适配器的作用

不同模型提供方的流式协议可能不完全一样。适配器负责把具体提供方的响应转换成 DeepSeek Harness 统一的 `StreamChunk`。

上层 Agent 循环不应该关心某个模型接口具体怎么返回，它只消费统一协议。

```text
DeepSeek API / 其他模型 API
  -> LLM 适配器
  -> 统一 StreamChunk
  -> Agent 循环
  -> 会话日志和 UI
```

这就是能力服务思想在模型层的体现：模型提供方可以替换，但 Agent 循环面对的是统一接口。

## 6. 和流式返回基础知识的关系

[[【LLM】流式返回信息]] 更偏向解释 SSE 这类通用流式通信。本文讲的是 DeepSeek Harness 内部如何把流式返回抽象成内容块和消息。

可以这样区分：

```text
SSE：网络上怎么一点点传数据
StreamChunk：Harness 内部怎么表达模型一点点吐出的内容
Message / ContentBlock：最终怎么形成可记录、可回放的对话结构
```

## 7. 一句话记忆

DeepSeek Harness 的模型层不是“字符串进、字符串出”，而是：

```text
流式片段 -> 内容块 -> 消息 -> 会话日志 -> 下一次模型请求
```

这套结构让文本、推理、图片、工具调用可以放进同一个 Agent 生命周期里处理。
