模型答得不好怎么办？传统做法是"重新问一遍"，但这样上下文全丢了。时间旅行（Time Travel）利用检查点，让你**从历史某一刻重新开始**，既能复现问题，也能改一个输入再跑。

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1793426549774_时间旅行.svg)

## 1. 两种模式

| 模式       | 本质                         | 适用                   |
| ---------- | ---------------------------- | ---------------------- |
| **Replay** | 从某个检查点的状态原样重跑   | 复现问题、刷新模型输出 |
| **Fork**   | 先改检查点状态，再从该点重跑 | 修正输入、换一条分支   |

区别只有一句：**Fork 在 Replay 之前多了一步 `update_state`。**

## 2. 手动模式

```python
from langgraph.checkpoint.memory import InMemorySaver
from langchain_core.runnables import RunnableConfig

checkpointer = InMemorySaver()
config: RunnableConfig = {"configurable": {"thread_id": "time-travel"}}
graph = build_graph().compile(checkpointer=checkpointer)
```

### 2.1 查看历史检查点

```python
history = list(graph.get_state_history(config))

for i, state in enumerate(history):
    cid = state.config["configurable"]["checkpoint_id"]
    parent = state.parent_config["configurable"]["checkpoint_id"] if state.parent_config else None
    print(i, cid, parent)
```

历史是倒序的：越靠前越新。通常需要的是"某个节点执行前"的那一个检查点。

### 2.2 Replay

```python
await graph.ainvoke(input=None, config=after_start, context=context)
```

关键点：`input=None`。传了新输入就不是回放，而是在旧状态上继续追加。回放会重新执行后续所有节点，因此节点里的副作用必须幂等。

### 2.3 Fork

```python
from langgraph.graph import START

fork_config = graph.update_state(
    config=before_start,
    values={"messages": [HumanMessage("太阳距离地球有多远")]},
    as_node=START,
)

await graph.ainvoke(input=None, config=fork_config, context=context)
```

`update_state` 会生成一个新的检查点，`as_node` 表示"这条更新是谁写的"。从新检查点继续运行，就得到一条和原历史分叉的轨迹。

### 2.4 最佳实践

- **刷新 AI 输出**：找到 AI 结果之前（模型节点之后）的检查点，直接 Replay。
- **修改内容**：找到内容产出节点的上一个检查点，用 `as_node` 指定该节点，改状态后再 Replay。
- **不要改历史**：更新总是生成新检查点，原轨迹不会被破坏。

## 3. Agent Server 模式

原理相同，只是历史存在服务端：用 `client.threads.get_history` 查，用 `client.threads.update_state` 改，用 `client.runs.wait(checkpoint=...)` 从指定检查点继续。

```python
history = await client.threads.get_history(thread_id, limit=20)

result = await client.runs.wait(
    thread_id=thread_id,
    assistant_id=assistant_id,
    input=None,
    checkpoint=after_start,
)
```

Fork：

```python
updated = await client.threads.update_state(
    thread_id,
    values={"messages": [{"role": "user", "content": "月球到地球距离是多少？"}]},
    checkpoint=before_start,
    as_node=START,
)

result = await client.runs.wait(
    thread_id=thread_id,
    assistant_id=assistant_id,
    input=None,
    checkpoint=updated["checkpoint"],
)
```

## 4. 子图为什么不支持时间旅行

时间旅行依赖"能看到并锁定某个检查点"，而子图的检查点边界与父图绑定，无法单独定位到某次子图调用的某一刻。因此需要精确回放的流程不要拆进子图，见 [[【实战】Assistant API 与子图]]。

## 5. 选修：copy 魔法

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1793426549776_时间旅行_魔法.svg)

部分可视化工具会把回放显示成新增一条分支，看起来像"历史没接上"。可以用 `as_node="__copy__"` 先复制一个检查点，再从副本运行：

```python
copy_config = graph.update_state(after_start, values=None, as_node="__copy__")
await graph.ainvoke(input=None, config=copy_config, context=context)
```

Fork 也可以配合 `__copy__`，把"更新值 + 指定来源节点"一起写进去。它属于绕开界面展示 bug 的技巧，不是必须项。
