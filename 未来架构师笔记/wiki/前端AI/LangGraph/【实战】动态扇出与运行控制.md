编译后的图结构是固定的，但**分支数量**可以运行时决定：有一百条资料就并行跑一百个处理节点。这就是动态扇出，典型形态是 **map-reduce**。

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1793426565607_30-dynamic-fanout-mapreduce.png)

## 1. 动态扇出：Send

静态边只能连两个节点，动态扇出用 `Send` 把"要分发到哪个节点、带什么状态"作为列表返回：

```python
from langgraph.types import Send

def fan_out(state):
    return [Send("worker", {"item": item}) for item in state["items"]]

builder.add_conditional_edges("planner", fan_out, ["worker"])
```

每个 `Send` 都会创建一个独立的并行分支，携带自己的输入状态。它们会在同一个超步里并行执行，结束后统一合并回主状态。

### 1.1 合并：需要能并发的 Reducer

因为多个 worker 会同时写回结果，累加类字段必须使用追加式 Reducer：

```python
class State(TypedDict):
    items: list[str]
    results: Annotated[list[str], operator.add]

def worker(state):
    return {"results": [f"处理完成：{state['item']}"]}
```

如果还用默认的覆盖式 Reducer，最终只会留下最后一个分支的结果。Reducer 规则见 [[【基础】状态与 Reducer]]。

### 1.2 什么时候用

- 批量处理：一堆文档、一批链接、一组子任务；
- 多角度生成：同一问题派给多个角色，最后汇总；
- 并行检索：多个数据源同时查。

分支之间不要互相依赖，否则就该拆成串行的超步。

## 2. 运行取消

取消是 **Agent Server 独有**的能力。用户不想等了、任务超时、前端断开，都应该主动停掉，而不是让服务端空跑。

```python
run = await client.runs.create(
    thread_id=thread_id,
    assistant_id=assistant_id,
    input={"messages": [{"role": "user", "content": "你好"}]},
)

await client.runs.cancel(
    thread_id=thread_id,
    run_id=run["run_id"],
    action="interrupt",  # 默认值
    wait=True,
)
```

- `action="interrupt"`：停止运行，保留 Run 记录与已产生的检查点，可后续恢复。
- `action="rollback"`：停止并回滚到本次运行之前的状态。
- `wait=True`：等取消真正完成再返回，避免前端状态与后端不一致。

## 3. 多任务策略

同一个线程里，前一个 Run 还没结束，用户又发了新消息，怎么处理？`multitask_strategy` 有四种：

| 策略              | Run A        | Run B               | A 已产生的状态 |
| ----------------- | ------------ | ------------------- | -------------- |
| `enqueue`（默认） | 继续完成     | 排队等待            | 保留           |
| `reject`          | 继续完成     | 拒绝创建            | 保留           |
| `interrupt`       | 被中断       | 立即接替执行        | 保留已提交部分 |
| `rollback`        | 被中断并删除 | 从 A 之前的状态执行 | 回滚并删除     |

```python
run1 = await client.runs.create(
    thread_id=thread_id, assistant_id=assistant_id,
    input={"messages": [{"role": "user", "content": "你好！"}]},
)

await asyncio.sleep(1)

run2 = await client.runs.create(
    thread_id=thread_id, assistant_id=assistant_id,
    input={"messages": [{"role": "user", "content": "hello！"}]},
    multitask_strategy="rollback",
)
```

### 3.1 怎么选

- **聊天产品**：常用 `interrupt`，用户改主意时立刻响应新的输入。
- **严格顺序的任务流**：`enqueue`，保证前一个任务完整执行。
- **不允许并发的后台任务**：`reject`，直接告诉用户"正在处理"。
- **实验/重来**：`rollback`，把半成品全部撤掉。
