LangGraph 的节点里通常会调用模型，而模型只会"文本进、文本出"。所以本节先把两件事打牢：**怎么统一接入不同厂商的模型**，以及**怎么用统一的消息结构表达多轮对话、图片、音频和工具调用**。

## 1. 供应商怎么选

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1793426484340_供应商.svg)

| 方案                | 推理成本               | 开发成本 | 运维成本 | 服务器成本 | 适用场景       |
| ------------------- | ---------------------- | -------- | -------- | ---------- | -------------- |
| 聚合商              | 自有模型低，三方模型高 | 低       | 低       | 无         | 中小型企业     |
| 源头厂商 + 自建网关 | 低                     | 低       | 低       | 高         | 大中型企业     |
| 源头厂商、无网关    | 低                     | 中       | 高       | 无         | 学习与快速原型 |

接入时通常只需要两样东西：**API Key** 和 **环境变量**。用 `pydantic-settings` 把 Key、默认模型等配置从 `.env` 读进一个 Settings 对象，业务代码就不必关心密钥来源。

## 2. 统一模型入口

`langchain` 用 `init_chat_model` 抹平不同厂商的差异，对外只暴露一套调用方式：

```python
from langchain.chat_models import init_chat_model

model = init_chat_model(
    model_provider="anthropic",
    model="claude-sonnet-4-5",
)

response = await model.ainvoke("你好")
```

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1793426484343_model.svg)

返回值是 `AIMessage`，常用字段：

| 字段                | 含义                                         |
| ------------------- | -------------------------------------------- |
| `text`              | 回复正文                                     |
| `tool_calls`        | 模型请求调用的工具列表                       |
| `content_blocks`    | 结构化内容块（文本、推理、图片、工具调用等） |
| `additional_kwargs` | 厂商额外字段                                 |
| `usage_metadata`    | token 消耗统计                               |

### 2.1 为什么有时拿不到思维链

OpenAI 官方接口标准不暴露思维链。常见绕法有四种：

- 自定义 Provider；
- 改用 Anthropic 这类会返回推理内容的接口；
- 换 OpenRouter 等第三方集成；
- 不用 `langchain` 的 model，自己封装官方 SDK。

### 2.2 流式输出

流式返回的每个 chunk 仍然是消息对象，内容块会一段段到达：

```python
async for chunk in model.astream("你好"):
    for block in chunk.content_blocks:
        print(block)
```

## 3. 消息体系

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1793426484344_message.svg)

所有消息类型都继承自 `BaseMessage`，常用的有四种：

| 类型            | 角色      | 用途                                   |
| --------------- | --------- | -------------------------------------- |
| `SystemMessage` | system    | 规则、角色设定、环境信息               |
| `HumanMessage`  | user      | 用户输入                               |
| `AIMessage`     | assistant | 模型回复，可携带工具调用               |
| `ToolMessage`   | tool      | 工具执行结果，需与 `tool_call_id` 对应 |

```python
from langchain.messages import HumanMessage, SystemMessage, AIMessage, ToolMessage

messages = [
    SystemMessage("你是一个天气助手。"),
    HumanMessage("成都今天天气怎么样？"),
    AIMessage(
        content="",
        content_blocks=[{"type": "reasoning", "reasoning": "需要查询天气工具"}],
        tool_calls=[{"id": "call_1", "name": "get_weather", "args": {"city": "成都"}}],
    ),
    ToolMessage(content="成都晴，25°C", tool_call_id="call_1"),
]
await model.ainvoke(messages)
```

### 3.1 内容块：一条消息可以装多种模态

纯文本可以直接传字符串，但图文、音频要用内容块列表：

```python
HumanMessage([
    {"type": "text", "text": "比较这两张图片的风格"},
    {"type": "image", "url": "https://example.com/a.jpg"},
    {"type": "image", "url": "https://example.com/b.jpg"},
])
```

音频同理，用 base64 data URL 传入：

```python
HumanMessage([
    {"type": "text", "text": "这段音频说了什么？"},
    {"type": "audio", "base64": data_url, "mime_type": "audio/mpeg"},
])
```

注意：图片、音频是否支持，取决于模型、服务商和 Provider 三方能力，缺一不可。多模态消息在会话中如何保存与回放，见 [[【基础】会话管理]]。

### 3.2 消息模板

简单变量替换可以用 Mustache：

```python
from langchain_core.utils.mustache import render

render(template="Hello {{name}}, you have {{count}} messages",
       data={"name": "世界", "count": 3})
```

复杂模板（循环、条件、工具列表）通常封装成"按文件名加载模板"的工具函数，系统提示词的编写要点见 [[【基础】系统提示词]]。

消息在状态里如何累积、如何按 id 更新，则要依赖 [[【基础】状态与 Reducer]] 中的 `add_messages`。
