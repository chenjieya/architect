真实模型有三个麻烦：慢、贵、不确定。测试 Agent 的异常分支时尤其明显——想让模型报错、想复现死循环、想构造一个"调用工具但参数非法"，靠真实模型几乎不可控。**模拟模型（Mock Model）**就是为这些场景准备的。

## 1. langchain_core 自带的模拟模型

| 模拟模型                    | 适用场景                                                  |
| --------------------------- | --------------------------------------------------------- |
| `FakeChatModel`             | 最简单，固定返回 `fake response`，用于最基础的单元测试    |
| `FakeListChatModel`         | 内部维护字符串列表，每次调用依次（循环）返回一条          |
| `FakeMessagesListChatModel` | 维护 `BaseMessage` 列表，可返回带工具调用的结构化消息     |
| `GenericFakeChatModel`      | 接收消息迭代器，每次取出一条 `AIMessage` 或字符串         |
| `ParrotFakeChatModel`       | 鹦鹉学舌，把输入消息里的最后一条原样返回                  |
| `FakeListLLM`               | 模拟文本补全模型，而非聊天模型                            |
| `FakeStreamingListLLM`      | 在 `FakeListLLM` 基础上支持流式，并可模拟在指定块位置抛错 |

选型口诀：**只要固定回复就选 `FakeChatModel`；要按顺序走多条回复选 `FakeListChatModel`；要模拟工具调用或推理块选 `FakeMessagesListChatModel`；要测流式异常选 `FakeStreamingListLLM`。**

## 2. 封装好的 mock_model

工程里通常把常用配置封装成一个工厂函数，按需返回不同行为的模拟模型：

```python
from langgraph_python.core.mock_model import mock_model
from langchain.messages import HumanMessage, ToolMessage

model = mock_model()

await model.ainvoke([
    HumanMessage("你好！"),
    ToolMessage(content="当前时间: 12:00", tool_call_id="ab"),
])
```

它支持与真实模型一致的接口，因此可以在不改业务代码的前提下替换模型：

```python
chunks = model.astream([HumanMessage("你好!")])
async for chunk in chunks:
    for block in chunk.content_blocks:
        print(block)
```

## 3. 在 LangGraph 里切换到模拟模型

配置体系允许运行时把模型名改成 `fake`，图内的模型工厂就会返回模拟模型：

```python
await graph.ainvoke(
    input={"messages": [HumanMessage("你好")]},
    config={"configurable": {"model": "fake"}},
)
```

这样同一张图既能跑真实模型，也能跑稳定的测试模型。动态切换的实现见 [[【实战】配置体系：RunnableConfig 与 Runtime]]。

## 4. 适合用模拟模型验证的场景

- **异常与重试**：让模型节点抛错，验证 `RetryPolicy`、超时和兜底函数，见 [[【基础】容错与错误重试]]。
- **死循环**：让模型反复要求调用工具，验证 `recursion_limit`。
- **工具调用**：构造缺参数、错参数、未知工具名，验证工具节点的报错路径。
- **流式渲染**：模拟分块返回，验证前端逐字输出的拼接逻辑。
