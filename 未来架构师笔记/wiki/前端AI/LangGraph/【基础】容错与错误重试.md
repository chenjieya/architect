Agent 会调用网络、模型、数据库，失败是必然的。LangGraph 把容错分成三层：**自动重试、超时控制、错误兜底**，再往外还有"停下来之后人工处理"。

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1793426557592_invoke机制.svg)

## 1. 第一层：重试策略

```python
from langgraph.types import RetryPolicy

# 给所有节点设置默认重试
workflow.set_node_defaults(retry_policy=RetryPolicy(max_attempts=3))

# 给单个节点设置，覆盖默认值
workflow.add_node("call_api", call_api, retry_policy=RetryPolicy(max_attempts=3))
```

默认只重试"可能是临时故障"的错误。下面这些被认为是程序 bug，**不会重试**：

`ValueError`、`TypeError`、`ArithmeticError`、`ImportError`、`LookupError`、`NameError`、`SyntaxError`、`RuntimeError`、`ReferenceError`、`StopIteration`、`StopAsyncIteration`、`OSError`。

这很合理：参数写错、语法错误重试一万次也没用，直接暴露比隐藏更好。

## 2. 第二层：超时策略

```python
from langgraph.types import TimeoutPolicy

workflow.set_node_defaults(
    timeout=TimeoutPolicy(run_timeout=60, idle_timeout=10),
)
```

| 参数           | 含义                               |
| -------------- | ---------------------------------- |
| `run_timeout`  | 从节点开始算，最多等多久必须完成   |
| `idle_timeout` | 最多等多久必须收到下一个"进度信号" |

进度信号包括：LLM 新 token 到达、子图发出信号、其他可观测事件。`idle_timeout` 适合流式模型：整体可能跑很久，但不能长时间一个 token 都没有。

注意：**超时策略只对异步节点生效**。同步节点在事件循环里是阻塞的，框架拿不到机会打断它。

## 3. 第三层：错误兜底

重试耗尽或遇到不可重试错误时，可以让一个错误处理函数代替节点执行：

```python
from langgraph.errors import NodeError

def my_error_handler(state: State, error: NodeError):
    return {"messages": [AIMessage("服务暂时不可用，请稍后再试")]}

workflow.set_node_defaults(error_handler=my_error_handler)
workflow.add_node("call_api", call_api, error_handler=my_error_handler)
```

兜底函数的返回值同样会按 Reducer 合并进状态，所以它可以写入一条友好的提示消息，让流程继续而不是整张图崩掉。

## 4. 错误发生后：检查点停在哪

图运行期间出错时会立刻停止，**最新检查点停在错误发生之前**。因此恢复很简单：

```python
try:
    result = await client.runs.wait(
        thread_id=thread_id,
        assistant_id=assistant_id,
        input={"messages": [{"role": "user", "content": "你好！"}]},
    )
except Exception as e:
    print(e)

# 不传 input，直接从最后一个检查点继续
result = await client.runs.wait(
    thread_id=thread_id,
    assistant_id=assistant_id,
    input=None,
)
```

传入 `input=None` 表示"接着上次跑"，而不是"新开一轮"。这也是 [[【实战】时间旅行]] 里 Replay 的同一个机制。

## 5. 线上环境的完整链路

```text
超时 / 其他错误
  → 自动重试
  → 错误函数兜底
  → 终止运行
  → 用户手动刷新（Replay）/ 修改（Fork）/ 追加消息（invoke + input）
```

三层容错解决"能自动恢复的部分"，最后一步留给人：刷新结果、改条件重跑、或者补一句话继续。这正好对应时间旅行的三种操作。

想稳定复现这些分支，用模拟模型构造错误与死循环，见 [[【基础】模拟模型与测试]]。
