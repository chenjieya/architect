中间件是这套生态最核心的扩展方式。通俗说，它就是**插在 Agent 运行路线上的关卡**：消息经过关卡时可以被检查、改写、拦截或补充。

## 1. 中间件的本质

一个中间件就是一个继承自 `AgentMiddleware` 的类：

```python
class TestMiddleware(AgentMiddleware):
    pass
```

创建 Agent 时把实例注入进去：

```python
create_agent(
    model="...",
    middleware=[TestMiddleware()],  # 注入中间件
)
```

类里的特定方法会在图运行时被调用，这些方法叫**钩子函数**。

## 2. 两类钩子

| 类型     | 方法                                                         | 运行方式                         |
| -------- | ------------------------------------------------------------ | -------------------------------- |
| 节点钩子 | `before_agent`、`before_model`、`after_model`、`after_agent` | 作为图节点运行，有明确的执行位置 |
| 包裹钩子 | `wrap_model_call`、`wrap_tool_call`                          | 以洋葱模型在节点内部运行         |

**节点钩子**好理解：图走到某个位置，就停下来执行你的函数。比如 `before_model` 就是"每次调模型之前"，`after_model` 就是"每次模型回完话之后"。

**包裹钩子**的"洋葱模型"需要打个比方：把原来的模型调用当成洋葱的芯，你的钩子是一层层包在外面的皮。请求从最外层往里走，先经过 A 的"进去"逻辑，再经过 B 的"进去"逻辑，到达模型；回来时反过来，先经过 B 的"出来"逻辑，再经过 A 的"出来"逻辑。

```text
进入：A_before → B_before → 模型 → B_after → A_after：返回
```

这种结构特别适合做"临时替换输入/输出"的事：改完调用原函数，拿到结果再改回去，外面的 Agent 几乎察觉不到。[[【基础】文件系统、权限与多模态]] 里的多模态消息重排就是靠 `wrap_model_call` 做的。

## 3. 预置中间件清单

官方已经内置了大量中间件，按用途分组更容易记：

### 3.1 可靠性：出错别直接崩

| 中间件                    | 作用                                   | 适用场景                    |
| ------------------------- | -------------------------------------- | --------------------------- |
| `ToolErrorMiddleware`     | 捕获工具异常，转成模型能看懂的错误消息 | 希望 Agent 自己改参数或恢复 |
| `ToolRetryMiddleware`     | 工具调用失败自动重试，支持指数退避     | 网络请求、外部 API          |
| `ModelRetryMiddleware`    | 模型调用失败自动重试，支持指数退避     | 限流、超时、短暂不可用      |
| `ModelFallbackMiddleware` | 主模型失败时按顺序切到备用模型         | 跨厂商容灾、提高可用性      |

"指数退避"就是重试间隔一次比一次长（1 秒、2 秒、4 秒），避免把对方服务打崩。

### 3.2 成本与循环：别跑飞

| 中间件                     | 作用                                 | 适用场景                   |
| -------------------------- | ------------------------------------ | -------------------------- |
| `ModelCallLimitMiddleware` | 限制单次运行或整个线程的模型调用次数 | 防止死循环、成本失控       |
| `ToolCallLimitMiddleware`  | 限制全部或指定工具的调用次数         | 控制高成本、高风险工具频率 |

### 3.3 安全与隐私：护栏

| 中间件                     | 作用                                       | 适用场景                         |
| -------------------------- | ------------------------------------------ | -------------------------------- |
| `HumanInTheLoopMiddleware` | 工具执行前暂停，等人批准、修改或拒绝       | 发邮件、改数据、资金交易         |
| `PIIMiddleware`            | 检测并按规则拦截、隐去、哈希或遮罩个人信息 | 邮箱、信用卡号等隐私数据         |
| `ShellToolMiddleware`      | 提供持久 Shell 会话执行系统命令            | 开发、部署、脚本自动化（需隔离） |

这三个分别对应 [[【中间件】HITL 人工审批]]、[[【中间件】PII 个人信息脱敏]] 和 [[【沙箱】技术选型与 E2B 实战]]。

### 3.4 任务规划与能力扩展

| 中间件                           | 作用                                     | 适用场景                       |
| -------------------------------- | ---------------------------------------- | ------------------------------ |
| `TodoListMiddleware`             | 提供任务拆分、计划和进度跟踪             | 多步骤复杂任务                 |
| `LLMToolSelectorMiddleware`      | 先用小模型筛相关工具，再调主模型         | 工具很多，想省上下文、提准确率 |
| `ProviderToolSearchMiddleware`   | 部分工具延迟加载，由厂商服务端按需返回   | 支持工具搜索的大工具集         |
| `FilesystemMiddleware`           | 列出、读取、写入、编辑文件，可配持久存储 | 用文件保存上下文、产物或记忆   |
| `SubAgentMiddleware`             | 把任务交给子 Agent，隔离各自上下文       | 分工、专业化、避免主上下文膨胀 |
| `RubricMiddleware`（Beta）       | 按预设标准自评并反复改进直到达标         | 有明确质量标准的内容/代码生成  |
| `FilesystemFileSearchMiddleware` | 提供 Glob 匹配与 Grep 搜索工具           | 大型代码库定位文件与内容       |

### 3.5 上下文管理：只把该看的塞进上下文

| 中间件                     | 作用                               | 适用场景                 |
| -------------------------- | ---------------------------------- | ------------------------ |
| `SummarizationMiddleware`  | 上下文接近上限时把较早对话压成摘要 | 长对话、历史消息多       |
| `ContextEditingMiddleware` | 清理较早的工具调用结果，保留最近的 | 工具调用频繁的长时间对话 |

两者对应 [[【基础】上下文压缩]]。

### 3.6 测试辅助

| 中间件            | 作用                                       | 适用场景                          |
| ----------------- | ------------------------------------------ | --------------------------------- |
| `LLMToolEmulator` | 用模型生成模拟的工具返回，代替真实工具执行 | 外部工具未实现/不可用时做原型验证 |

这么多中间件不用一次背完。记住一条主线即可：**可靠性中间件管"别崩"，限制类管"别乱花钱"，安全类管"别乱来"，能力类管"能干更多事"，上下文类管"别塞太满"**。这也正是 [[【概念】驾驭工程]] 所说的护栏与情境管理。
