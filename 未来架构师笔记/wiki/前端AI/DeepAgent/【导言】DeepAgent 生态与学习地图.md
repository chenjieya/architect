如果说 [[【导言】LangGraph 学习地图]] 解决的是"怎么把一次任务画成可执行流程图"，那么这一组内容解决的是下一个问题：**怎么把一堆现成能力拼成一个真正能干活的 Agent，并把它放到服务器上给人用**。

Deep Agent 就是 LangChain 生态给出的"整车方案"：你不用从零装发动机，选好模型、装上工具、配几个中间件，就能得到一个会规划、会用文件、会调子代理的 Coding Agent。

## 1. 五层生态分工

这一组内容涉及五个名字，很容易混。先用一张表把它们的位置钉住：

| 名字           | 它负责什么                                                              | 生活化类比       |
| -------------- | ----------------------------------------------------------------------- | ---------------- |
| `LangGraph`    | 工作流运行必需的功能：节点、边、中断、时间旅行                          | 发动机与底盘     |
| `LangChain`    | 统一模型、消息、工具的格式，预置 Agent 工作流，提供中间件机制           | 统一规格的零件箱 |
| `DeepAgent`    | 预置大量中间件，让 Agent 直接具备文件、技能、子代理等能力（部分要后端） | 装配好的整车     |
| `Agent Server` | 实现 Agent Server Protocol 协议，让图变成可远程调用的服务               | 前台与门店       |
| `LangSmith`    | Agent 跟踪、图调试、部署等基础设施                                      | 监控、质检与售后 |

![LangChain 生态全景](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1795850347739_202608052258029.png)

一句话记忆：**LangGraph 管流程，LangChain 管格式，DeepAgent 管能力组合，Agent Server 管对外服务，LangSmith 管看得见**。它们不是五选一，而是从下往上叠起来的。

## 2. Agent 的三个核心能力来源

`LangChain` 基于 `LangGraph` 构建，主要做了三件事：

1. **统一模型与消息的外观**：不同厂商的模型接口不一样，统一之后换模型只改一个字符串。
2. **便捷的工具封装**：用装饰器把普通函数变成模型能调用的工具。
3. **在图上搭出 Agent 工作流**：提供 `response_format` 做结构化输出，提供灵活且内置的中间件机制。

这三件事分别对应后面的 [[【基础】Agent 创建与结构化输出]] 和 [[【基础】中间件机制与预置中间件]]。

## 3. Agent 的技术选型

做 Agent 不只有一条路。按"写代码的比例"大致分三档：

| 档位   | 代表                                                           | 特点                                     |
| ------ | -------------------------------------------------------------- | ---------------------------------------- |
| 高代码 | `LangChain 生态`、`OpenAI Agents SDK`、`AutoGen`、`AgentScope` | 灵活、可精细控制，适合复杂业务与深度定制 |
| 低代码 | `LangFlow`、`Dify`、`n8n`、`Coze`                              | 拖拽编排，上手快，适合流程相对固定的场景 |
| 无代码 | `扣子 Bot`、`Copilot Studio`、`Agentforce`                     | 配置即用，适合轻量需求与验证想法         |

本系列走的是高代码路线：能看清每一步发生了什么，也更容易迁移到生产环境。
