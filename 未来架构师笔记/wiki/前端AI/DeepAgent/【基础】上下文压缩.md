模型的上下文窗口是有限的，而 Agent 跑得越久，攒下的消息越多。上下文压缩要做的就是在**不破坏语义连贯**的前提下把内容精简掉。难点在于：有的消息正在被模型使用，不能乱动；有的早已过时，压缩了也没关系。所以要先分清楚压缩的介入点。

## 1. 两个介入点

| 介入点     | 处理对象     | 特点                         |
| ---------- | ------------ | ---------------------------- |
| 新消息防爆 | 刚产生的消息 | 立即处理，绝不能打破因果关系 |
| 上下文摘要 | 较早的旧消息 | 会让旧因果变模糊，但影响较小 |

这是整篇最关键的判断：**消息是"新"还是"旧"**。新的代表模型此刻正在做的事，动它等于打断思路；旧的是历史记录，模糊一点无伤大雅。[[【概念】上下文工程]] 里说的"治理：上下文膨胀管理"，靠的就是这两手。

## 2. 新消息防爆

特点有三条：针对新产生的消息、立即发生、非常谨慎。

### 2.1 工具返回防爆

主要手段八个字：**窗口控量，卸载兜底**。

**窗口控量**是让工具别一次性返回全部内容。比如 `read_file` 提供 `offset` 和 `limit` 参数，并给了默认值，模型一次只读一段，想要更多再翻页。这相当于从源头限流。

**卸载兜底**是万一返回还是超了阈值，就把完整结果挪走，只把摘要和引用留在上下文里：

```text
[卸载后的结果] + [完整结果引用] → 模型
```

模型看到的是"内容太长已存到文件 X，这是摘要，需要时按引用读取"。完整信息没丢，只是从随身书包搬到了仓库。这个功能已由 `FilesystemMiddleware` 实现，可以配置阈值：

```python
FilesystemMiddleware(
    tool_token_limit_before_evict=20000
)
```

产物存哪也能配置：

```python
backend=CompositeBackend(
    default=...,
    routes={},
    # Deep Agent 内部产物的保存根目录
    artifacts_root="/home/user/workspace/.deepagents",
)
```

### 2.2 用户消息防爆

用户消息超过阈值也直接卸载，同样由 `FilesystemMiddleware` 实现：

```python
FilesystemMiddleware(
    human_message_token_limit_before_evict=50000
)
```

### 2.3 想一想：哪些消息要不要立即处理

| 消息类型        | 要不要立即处理 | 原因                                                                    |
| --------------- | -------------- | ----------------------------------------------------------------------- |
| 系统提示词过大  | 不要靠防爆     | 它常驻且不变，该用 [[【中间件】Skills 技能系统]] 的渐进式披露减少常驻量 |
| 工具参数过大    | 要             | 属于正在发生的动作，需截断或卸载，见下节 `truncate_args_settings`       |
| AI 普通回复过大 | 不必           | 属于旧消息，交给上下文摘要更合适                                        |

## 3. 上下文摘要

摘要只处理旧消息。它确实会让旧的因果关系变模糊，但因为事情已经过去，这种模糊对整个会话影响较小。

### 3.1 处理旧的特殊工具参数

有两个工具的参数特别容易过大：

- `write_file`：传入的新内容可能很大。
- `edit_file`：旧内容和新内容都可能很大。

它们适合被截断，原因有三条：

1. 工具执行后，有价值的结果已经落到文件里了。
2. 模型关心的是文件**当下是什么样**，不是"曾经改过几次"的调用历史。
3. 工具调用和返回结果本身的因果关系本来就很淡。

```python
summarization_middleware = SummarizationMiddleware(
    model=model,
    backend=backend,

    # 旧工具调用参数卸载配置
    truncate_args_settings={
        # 对话达到模型上下文窗口的 85% 时，开始检查旧工具调用参数
        "trigger": ("fraction", 0.85),

        # 最近 10% 的上下文中的工具参数保持完整
        "keep": ("fraction", 0.10),

        # 单个参数字符串超过 2000 个字符才卸载
        "max_length": 2_000,

        # 卸载后的提示文字
        "truncation_text": "...(argument truncated)",
    },
)
```

`("fraction", 0.85)` 的意思是"按窗口容量的比例算，到 85% 就触发"。`keep=("fraction", 0.10)` 表示最后那 10% 别动——因为那是最新的上下文，还在被模型使用。两个比例一个管"什么时候开始压"，一个管"压到哪里停"。

### 3.2 处理整个上下文中的旧消息

```python
summarization_middleware = SummarizationMiddleware(
    model=model,
    backend=backend,

    # 整个对话达到模型上下文窗口的 85% 时触发摘要
    trigger=("fraction", 0.85),

    # 摘要时保留最近 10% 的上下文不参与摘要
    keep=("fraction", 0.10),
)
```

配置逻辑和上面一样，只是这次摘要的对象从"工具参数"变成"整段旧消息"。可以把它想成读书笔记：读到第 85 页时，把前面 90% 的内容压成一页摘要，最后 10% 的原文先留着别动。
