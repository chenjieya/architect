模型没法直接"读字"，它只能吃数字。上一讲 [[【基础】训练模式与框架]] 讲完了"AI 的本质"，从这一讲开始进入"语言模型怎么理解文字"——第一步就是把文字变成数字，这一步的关键叫**词元（Token）**。本系列第 7～12 讲会一路走到 Transformer，这里先打好第一块地基。

## 1. 一句话理解

**词元 = 把文字切成的"最小数字单元"。切的过程叫分词（Tokenize），负责切的工具叫分词器（Tokenizer）。**

大白话：模型是"数字瞎子"，你给它一段话，它要先把它拆成一个个有意义的数字，才能开始理解。在线体验：https://tiktokenizer.vercel.app/

## 2. 从文字到数字：为什么不直接用 UTF-8

最省事的做法，是把文字直接转成 **UTF-8 编码的数字**。比如 `"你好Hello!123"` 转成字节序列：

```python
list("你好Hello!123".encode("utf-8"))
# [228, 189, 160, 229, 165, 189, 72, 101, 108, 108, 111, 33, 49, 50, 51]
```

但这套数字序列**不能直接当分词结果**，有三个致命问题：

1. **长度膨胀**：一个汉字 = 3 个 UTF-8 字节数字，导致计算量、显存占用、训练速度全部恶化。
2. **信息浪费**：模型每一层都要重复学习 `228,189,160 = 你` 这种固定组合，大量重复冗余学习。
3. **语义不明**：模型很难学到"词语、字的边界"规律。

> 大白话：UTF-8 是把每个字符都掰成 3~4 块，又长又碎，模型学起来又慢又累。**不如直接把"有意义的字/词"映射成一个数字。**

## 3. 目标：一个字/词 = 一个数字

理想状态是这样：

| 文字  | 对应数字 |
| ----- | -------- |
| 你好  | 10000    |
| Hello | 10001    |
| !     | 10002    |
| 123   | 10003    |

这样 `"你好Hello!123"` 只需要 **4 个数字** 就能表达，而且每个数字都对应一个**可以被学习的语义**。

要实现这个目标，必须建立一张"词典"——**分词表（Token Vocabulary，Vocab）**。词表怎么来？答案在下一节：**从大量文字里统计出来**。

## 4. 词表是怎么建出来的：BPE 算法

词表不能靠人一个个列，而是**通过统计大量文字内容自动建立**，并**合并那些高频出现的组合**。这个算法叫 **BPE（Byte Pair Encoding，字节对编码）**，是现代分词器（GPT 的 tiktoken 等）的核心思路。

### 4.1 BPE 的三步核心思想

1. **初始**：先把文本转成 UTF-8 字节序列，初始词表就是 **0~255 的单字节**（共 256 个）。
2. **统计**：找出当前序列中**出现次数最多的相邻字节对**。
3. **合并**：把它俩合并成一个新的词表编号，替换掉序列里所有这个组合。重复 2、3 步，直到词表达到目标大小（如 400）。

### 4.2 用一个例子走一遍

假设语料是 `"ababab"`，目标词表 258（初始 256 + 合并 2 次）：

1. 初始序列：`[a][b][a][b][a][b]`
2. **统计**：相邻对 `(a,b)` 出现 3 次最多 → 合并成新编号 256。
3. **替换**：序列变成 `[256][256][256]`。
4. **再统计**：相邻对 `(256,256)` 出现 2 次最多 → 合并成 257。
5. **再替换**：序列变成 `[257][256]`。词表达到目标，结束。

> 大白话：BPE 就像玩"消消乐"——反复找"最常挨在一起的两个小块"，把它们焊成一个新块。高频出现的词（如"的"、"the"、"ing"）会先被合并成独立编号，所以词表里总是高频组合占便宜。

### 4.3 亲手跑一遍：BPE 训练代码

光看原理不够，把代码跑起来才能真正理解"词表是怎么长出来的"。下面是课件里的完整 BPE 训练代码（语料文件 `corpus.txt`、生成的词表 `bpe_vocab.json` 都在 `raw/agent-core/07. 词元/` 目录里）：

```python
import json
from collections import Counter


def bpe_train(text, target_vocab_size=400):
    """简易 BPE 算法：把文本转 UTF-8 字节序列，不断合并高频相邻对，
    直到词表大小达到 target_vocab_size。"""
    byte_seq = list(text.encode("utf-8"))
    # 初始词表：0~255 单字节
    vocab = {i: bytes([i]) for i in range(256)}
    seq = byte_seq.copy()

    print(f"文本: {len(text)} 字符")
    print(f"UTF-8 字节序列: {len(byte_seq)}（>> 初始词表 256）")
    print(f"目标词表大小: {target_vocab_size}")
    print()

    step = 0
    while len(vocab) < target_vocab_size:
        # 1. 统计相邻对出现次数
        pair_counts = Counter()
        for i in range(len(seq) - 1):
            pair_counts[(seq[i], seq[i + 1])] += 1
        if not pair_counts:
            break

        # 2. 找出现最多的相邻对，合并成新编号
        best_pair, _ = pair_counts.most_common(1)[0]
        new_id = len(vocab)
        vocab[new_id] = vocab[best_pair[0]] + vocab[best_pair[1]]
        step += 1

        # 3. 把序列里所有这个组合替换成新编号
        new_seq = []
        i = 0
        while i < len(seq):
            if i + 1 < len(seq) and seq[i] == best_pair[0] and seq[i + 1] == best_pair[1]:
                new_seq.append(new_id)
                i += 2
            else:
                new_seq.append(seq[i])
                i += 1
        seq = new_seq

    print(f"\n--- 合并结束 ---")
    print(f"合并次数: {step}")
    print(f"序列压缩: {len(byte_seq)} → {len(seq)}（{len(seq) / len(byte_seq) * 100:.1f}%）")
    print(f"词表: 256 → {len(vocab)}")

    # 保存词表（能解码成 utf-8 的存原文，否则存十六进制）
    id_to_token = {}
    for tid in sorted(vocab.keys()):
        raw = vocab[tid]
        try:
            id_to_token[tid] = raw.decode("utf-8")
        except UnicodeDecodeError:
            id_to_token[tid] = raw.hex()

    with open("bpe_vocab.json", "w", encoding="utf-8") as f:
        json.dump(id_to_token, f, ensure_ascii=False, indent=2)


# ============ 跑一遍 ============
with open("corpus.txt", "r", encoding="utf-8") as f:
    corpus = f.read()

bpe_train(corpus, target_vocab_size=400)
```

**代码拆解（看懂关键三行）**：

| 代码                                          | 在干什么                                             |
| --------------------------------------------- | ---------------------------------------------------- |
| `vocab = {i: bytes([i]) for i in range(256)}` | 初始词表：0~255 每个单字节一个编号                   |
| `pair_counts.most_common(1)[0]`               | 找出**出现最多的相邻对**                             |
| `vocab[new_id] = vocab[a] + vocab[b]`         | 把相邻对**合并**成一个新编号，并记下它俩拼起来的内容 |

运行后你会看到：`序列压缩: N → M（xx.x%）`——**文本的 token 数大幅变少**，这就是 BPE 的价值。词表也从 256 长到了 400。

### 4.4 词表建好后怎么用：分词代码

词表固定后**不再改动**，之后的分词就是"查表匹配"。下面这段代码读取刚生成的 `bpe_vocab.json`，把新文本切成一串 token：

```python
import json
import re


with open("bpe_vocab.json", "r", encoding="utf-8") as f:
    id_to_token = {int(k): v for k, v in json.load(f).items()}


def to_bytes(tid, s):
    """把词表里的字符串表示还原成字节，用于匹配。"""
    if tid < 256:
        return bytes([tid])
    if re.fullmatch(r"(?:[0-9a-f]{2})+", s):  # 十六进制片段
        raw = bytes.fromhex(s)
        try:
            raw.decode("utf-8")
        except UnicodeDecodeError:
            return raw
    return s.encode("utf-8")


vocab_bytes = {tid: to_bytes(tid, s) for tid, s in id_to_token.items()}
bytes_to_id = {}
for tid in sorted(vocab_bytes):
    b = vocab_bytes[tid]
    if b not in bytes_to_id:
        bytes_to_id[b] = tid
max_len = max(len(b) for b in bytes_to_id)


def tokenize(text):
    """贪心最长匹配：从当前位置起，尽量匹配词表里最长的片段。"""
    data = text.encode("utf-8")
    ids = []
    i = 0
    while i < len(data):
        for length in range(min(max_len, len(data) - i), 0, -1):
            piece = data[i : i + length]
            if piece in bytes_to_id:
                ids.append(bytes_to_id[piece])
                i += length
                break
    return ids


# ============ 跑一遍 ============
test_text = "人工智能模型通过深度学习来理解自然语言。"
ids = tokenize(test_text)

print(f"测试文本: {test_text}")
print(f"UTF-8 字节数: {len(test_text.encode('utf-8'))}")
print(f"分词数量: {len(ids)}")
print()
decoded = []
for tid in ids:
    raw = vocab_bytes[tid]
    try:
        decoded.append(raw.decode("utf-8"))
    except UnicodeDecodeError:
        decoded.append(f"<字节 {raw.hex()}>")

print(ids)
print(decoded)
```

**怎么跑**：先跑"BPE 训练"生成 `bpe_vocab.json`，再跑本段分词代码。运行时会看到输出：

- `分词数量` 明显小于 `UTF-8 字节数`——说明文本被压缩成了更少的 token。
- `decoded` 列表会显示每个 token 对应的文字片段——你会直观看到"哪些字被合并成了一个 token"。

> 提示：`decoded` 输出里如果看到某些 token 显示成 `<字节 xx>`，那是 BPE 合并出的"半个汉字"的字节片段（无法单独解码成完整文字），这是正常现象——正是第 6 节讲的"单个汉字被拆成多个 token"的根源。

## 5. 中英文的 token 消耗差异

一个很实用的问题：同样长度的文字，中文和英文要消耗多少 token？（直接影响计费和上下文长度）

| 文本单元     | 海外模型              | 国产模型         |
| ------------ | --------------------- | ---------------- |
| 1 个汉字     | 1.3～1.5 token        | 0.8～1 token     |
| 1 个英文字母 | 平均 0.25～0.33 token | 0.25～0.33 token |
| 1 个英文单词 | 平均 1.3 token        | 平均 1.3 token   |

**关键结论**：

- 英文单词平均 1.3 token（因为英文常用词都被合并成独立词元了）。
- **中文汉字消耗更多 token**（1 汉字 1.3~1.5），因为单个汉字语义密度高，且词表对中文的合并不如英文彻底。
- 国产模型对中文的 token 效率更优（0.8~1 个/字），因为语料以中文为主。

> 大白话：同样一段话，中文比英文"更费 token"，所以长中文文本更占上下文、更贵。这就是为什么中文场景下，国产模型（中文语料训练）更划算。

## 6. 常见现象：单个汉字被拆成多个 token

有时你会看到"一个字"被拆成好几个 token，原因有两个：

1. **词表太小**：有些词还没被收录，词表就已经达到上限了。
2. **语料里没见过**：训练语料库中没出现过这个词，词表里没有它，只能拆成更小的片段。

> 大白话：词表不是万能的，遇到"生词"就只能把它拆成认识的零件。这也是为什么中文生僻字、专业术语容易"吃 token"。

## 7. 总结

- **词元 = 文字的最小数字单元**，分词器负责把文字切成 token。
- **为什么不直接用 UTF-8**：太长、太碎、语义不明。
- **词表靠 BPE 算法自动建**：反复合并高频相邻字节对，直到词表达标。
- **词表固定后**，分词就是查表匹配。
- **中英 token 差异**：中文比英文费 token，国产模型对中文更友好。
