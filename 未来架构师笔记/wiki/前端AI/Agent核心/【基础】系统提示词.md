上一篇 [[【基础】Ollama 本地模型部署]] 解决了"模型怎么跑起来"。这一篇解决"怎么跟模型说话"——尤其是最容易被忽视、却影响最大的一条消息：**系统提示词**。

## 1. 系统提示词是什么

一次对话由多条消息组成，每条消息带一个 `role`：`system`、`user`、`assistant`。其中 **`system` 角色的消息就是系统提示词**，它永远排在所有消息的最前面。

```python
messages = [
    {"role": "system", "content": "你是代码顾问。精准解答编程问题，不懂直接说明，禁止编造信息。"},
    {"role": "user", "content": "帮我看看这段代码有什么问题"},
]
```

为什么它这么重要？因为**大模型在训练过程中被特意强化过对系统提示词的关注**——它相当于给整场对话定规矩：你是谁、要遵守什么、输出长什么样。后面每一轮用户消息都会在这个规矩下被回答。

## 2. 编写系统提示词的五条核心原则

### 2.1 精简：能不说就不说

系统提示词不是越长越好。啰嗦的描述会稀释关键指令，还可能引入歧义。

> **反面案例**：你现在要充当一名专业代码顾问，接下来我会向你提出各种各样和编程相关的问题。希望你认真仔细地阅读我每一次发送过来的内容，充分理解我的诉求之后，再进行回答。回答的时候尽量清晰易懂，方便我进行理解。如果遇到不清楚的内容，千万不要随意编造答案。
>
> **正面案例**：你是代码顾问。精准解答编程问题，不懂直接说明，禁止编造信息。

同样的意思，前者几十字，后者二十来字，后者反而更清楚。

### 2.2 自洽：提示词不能自我矛盾

规则之间打架，模型会无所适从。

> **反面案例**：你是数据分析助手。回答务必详尽，多角度展开说明；同时所有回复控制在 30 字以内。
>
> **正面案例**：你是数据分析助手。回答简洁，整体控制在 30 字以内。

"详尽展开"和"30 字以内"直接冲突，删掉冲突的一方即可。

### 2.3 全局约束：规则作用于每一轮

系统提示词里的规则对整条对话的每一轮都生效，所以不要写"只在某种情况下才适用"的局部规则——那种规则应该放到对应的用户消息里。

> **反面案例**：当用户要求你写数据分析类代码的时候，你应该使用 Python 来编写。
>
> **正面案例**：（留空，把这类条件规则放到具体那轮用户消息中）

### 2.4 保持静态：内容尽量固定不变

系统提示词应尽量**固定不变**。如果每次请求都往里塞动态内容（当前用户、当前时间等），会带来两个问题：一是难以命中模型服务商的 prompt cache（缓存前缀），二是每轮都变的内容会干扰模型对稳定规则的理解。

> **反面案例**：当前用户是：<动态内容>，时间是：<动态内容>
>
> **正面案例**：（留空，动态信息改用其他方式传递）

### 2.5 结构化：用 Markdown / XML 分层

把核心指令、硬性约束、输出规范用标题、列表、标签隔离，方便模型区分层级、识别关键规则，避免一大段扁平文本造成理解偏差。

> **反面案例**：你是技术助手。回答必须精简，不能编造信息。输出答案尽量条理清晰。如果信息不足直接说明。禁止额外多余话术。
>
> **正面案例**：

```markdown
# 角色

技术助手

## 硬性规则

1. 回答精简，严禁编造信息
2. 信息不足直接说明，不强行作答

## 输出要求

条理清晰，无多余开场白与结束语
```

## 3. 二次封装：让提示词工程化

写提示词的过程中会反复做三件事：组装消息、调用模型、打印结果。把它们各封装一层，代码会干净很多。

### 3.1 消息类

用 `dataclass` 把三种角色的消息固定下来，调用时就不用每次手写 `{"role": ..., "content": ...}`：

```python
from abc import ABC
from dataclasses import dataclass
from typing import Literal

Role = Literal["system", "user", "assistant"]


@dataclass
class Message(ABC):
    content: str
    role: Role


@dataclass
class SystemMessage(Message):
    role: Role = "system"


@dataclass
class UserMessage(Message):
    role: Role = "user"


@dataclass
class AssistantMessage(Message):
    role: Role = "assistant"
```

### 3.2 模型类

把 OpenAI 客户端包一层 `Model`，提供同步 `invoke` 和流式 `invoke_stream` 两个入口，内部自动把消息对象转成 API 需要的字典：

```python
from collections.abc import Iterator
from dataclasses import dataclass
from typing import cast
from agent.message import Message
from agent.config import openai_settings
from openai import OpenAI


@dataclass
class Chunk:
    type: str = ""
    content: str = ""


@dataclass
class Model:
    model_name: str = openai_settings.model
    _client: OpenAI = OpenAI()

    def invoke(self, messages: list[Message]):
        response = self._client.chat.completions.create(
            model=self.model_name,
            messages=cast(
                list, [{"role": m.role, "content": m.content} for m in messages]
            ),
        )
        return response

    def invoke_stream(self, messages: list[Message]) -> Iterator[Chunk]:
        stream = self._client.chat.completions.create(
            model=self.model_name,
            messages=cast(
                list, [{"role": m.role, "content": m.content} for m in messages]
            ),
            stream=True,
        )
        is_on_reasoning = False
        full_reasoning_content = ""
        full_content = ""
        for chunk in stream:
            if not chunk.choices:
                continue
            delta = chunk.choices[0].delta
            content = delta.content
            reasoning_content = getattr(delta, "reasoning_content", None)
            if not reasoning_content:
                reasoning_content = getattr(delta, "reasoning", None)

            if reasoning_content:
                full_reasoning_content += reasoning_content
                if not is_on_reasoning:
                    is_on_reasoning = True
                    yield Chunk(type="reasoning_start")
                yield Chunk(type="reasoning", content=reasoning_content)
            if content:
                full_content += content
                if is_on_reasoning:
                    is_on_reasoning = False
                    yield Chunk(type="reasoning_end", content=full_reasoning_content)
                    yield Chunk(type="content_start")
                yield Chunk(type="content", content=content)

        yield Chunk(type="content_end", content=full_content)
```

`invoke_stream` 里那段逻辑值得拆开看：模型流式返回时，"思考"（reasoning）和"正文"（content）是交错出现的。代码用 `is_on_reasoning` 这个开关跟踪当前处于哪个阶段，并在切换时补发 `reasoning_start` / `reasoning_end` / `content_start` / `content_end` 这些边界事件，方便上层打印或渲染时区分"这是思考"还是"这是答案"。

### 3.3 打印器

把流式 chunk 按类型上色输出，`PrinterConfig` 控制是否显示思考、用什么颜色：

```python
from dataclasses import dataclass
import sys


@dataclass
class PrinterConfig:
    show_reasoning: bool = True
    reasoning_color: str = "36"
    content_color: str = "31"


def print_stream(chunk_iterator, config: PrinterConfig | None = None):
    if config is None:
        config = PrinterConfig()
    for chunk in chunk_iterator:
        if chunk.type == "reasoning_start":
            if config.show_reasoning:
                print("思考：")
        elif chunk.type == "reasoning_end":
            if config.show_reasoning:
                print()
        elif chunk.type == "content_start":
            print()
            print("内容：")
        elif chunk.type == "content_end":
            print()
            print("====输出完毕====")
        elif chunk.type == "reasoning":
            if config.show_reasoning:
                print(f"\033[{config.reasoning_color}m{chunk.content}\033[0m", end="")
        elif chunk.type == "content":
            print(f"\033[{config.content_color}m{chunk.content}\033[0m", end="")
        sys.stdout.flush()
```

封完之后，使用起来就非常直观：

```python
from agent.model import Model
from agent.printer import print_stream
from agent.message import SystemMessage, UserMessage

model = Model()
resp = model.invoke_stream([
    SystemMessage("当用户向你打招呼时，你仅需回答你好即可"),
    UserMessage("你好")
])
print_stream(resp)
```

## 4. 用模板动态生成系统提示词

系统提示词本身要"保持静态"，但有一类信息天然是动态的——**当前运行环境**。比如"当前工作目录是什么""是不是 Git 仓库""用户使用什么语言"。这些信息如果不告诉模型，它就没法准确回答"目前在哪个目录"这类问题。

解决办法不是把动态内容直接拼进提示词字符串，而是用**模板**：模板固定不变，渲染时才把变量填进去。这里用 Jinja2。

### 4.1 收集环境信息

```python
import os
import platform
import subprocess


def get_cwd() -> str:
    return os.getcwd()


def get_is_git() -> bool:
    result = subprocess.run(
        ["git", "rev-parse", "--is-inside-work-tree"],
        capture_output=True,
        text=True,
        timeout=5,
    )
    return result.returncode == 0 and result.stdout.strip() == "true"


def get_language() -> str:
    system = platform.system()
    if system == "Darwin":
        result = subprocess.run(
            ["defaults", "read", "-g", "AppleLocale"],
            capture_output=True,
            text=True,
            timeout=5,
        )
        return result.stdout.strip()
    elif system == "Windows":
        import ctypes

        lcid = ctypes.windll.kernel32.GetUserDefaultLCID()
        buf = ctypes.create_unicode_buffer(256)
        ctypes.windll.kernel32.GetLocaleInfoW(lcid, 0x5C, buf, 256)
        return buf.value
    return ""
```

### 4.2 模板渲染

模板文件放在 `agent/prompt/system.j2`，里面用 `{{ 变量名 }}` 占位，例如：

```markdown
# Environment

You have been invoked in the following environment:

- Primary working directory: {{ cwd }}
- Is a git repository: {{ is_git }}
```

渲染函数负责加载模板并传入变量：

```python
import os
from jinja2 import Environment, FileSystemLoader


def render_prompt(prompt_name: str) -> str:
    template_dir = os.path.join(os.path.dirname(__file__), "prompt")
    env = Environment(loader=FileSystemLoader(template_dir))
    template = env.get_template(f"{prompt_name}.j2")
    return template.render(
        language=get_language(),
        cwd=get_cwd(),
        is_git=get_is_git(),
    )
```

### 4.3 实际使用

把渲染出来的字符串作为系统消息传进去，模型就能回答环境相关问题：

```python
from agent.prompt import render_prompt

resp = model.invoke_stream([
    SystemMessage(render_prompt("system")),
    UserMessage("目前在哪个目录？")
])
print_stream(resp)
```

## 5. 总结

- **定位**：系统提示词是 `role="system"` 的消息，排在所有消息最前，训练时被重点强化。
- **五原则**：精简、自洽、全局约束、保持静态、结构化。
- **工程化**：用 `Message` 类管角色、`Model` 类管调用、打印器管输出。
- **模板化**：动态的环境信息（cwd、是否 Git、语言）用 Jinja2 模板注入，模板本身保持静态。

提示词准备好了，但模型本身是**无状态**的——它不记得上一轮说了什么。要让对话连贯起来，就需要**会话管理**，见 [[【基础】会话管理]]。
