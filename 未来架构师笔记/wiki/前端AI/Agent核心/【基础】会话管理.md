上一篇 [[【基础】系统提示词]] 让模型知道了"规矩"，但还有一个更基础的问题没解决：**模型不记得上一轮说了什么**。这一篇讲会话管理，把对话真正串起来。

## 1. 问题：模型是无状态的

大模型的每次调用都是独立的——它只会根据你这次传进去的 `messages` 做计算，算完就"忘"了。也就是说，**模型没有记忆，记忆全靠你在每次请求时把历史重新带上**。

先看一个"失忆"的例子。第 1 次问"uv 是什么"：

```python
resp = model.invoke_stream([
    {"role": "system", "content": render_prompt("system")},
    {"role": "user", "content": "uv是什么？"}
])
print_stream(resp)
```

第 2 次问"如何安装"：

```python
resp = model.invoke_stream([
    {"role": "system", "content": render_prompt("system")},
    {"role": "user", "content": "如何安装？"}
])
print_stream(resp)
```

第 2 次调用只发了一条"如何安装？"，模型不知道"安装什么"，自然答非所问。**要让对话连贯，就必须把前面的消息一起发过去。**

## 2. Session：把历史消息攒起来

最直接的做法是维护一个消息列表，每次新增一条用户消息，就带着整份历史再调用一次模型。把这个列表和它的操作封装成 `Session` 类：

```python
import json
import uuid
from pathlib import Path


class Session:
    def __init__(self):
        self.id = str(uuid.uuid4())
        self.messages: list[dict] = []

    def add_message(self, message: dict):
        self.messages.append(message)

    def save(self):
        sessions_dir = Path(__file__).parent / "sessions"
        sessions_dir.mkdir(parents=True, exist_ok=True)

        data = {
            "id": self.id,
            "messages": self.messages,
        }

        path = sessions_dir / f"{self.id}.json"
        with open(path, "w", encoding="utf-8") as f:
            json.dump(data, f, ensure_ascii=False, indent=2)

    @classmethod
    def load(cls, session_id: str):
        path = Path(__file__).parent / "sessions" / f"{session_id}.json"
        with open(path, encoding="utf-8") as f:
            data = json.load(f)

        session = cls()
        session.id = data["id"]
        session.messages = data["messages"]
        return session
```

三个要点：

- `id`：每个会话一个 UUID，用来区分和持久化。
- `messages`：完整的历史消息列表，就是模型的"记忆"。
- `save` / `load`：把会话落盘成 JSON，下次可以接着聊。

## 3. 让 Model 自动维护会话

上面 `Session` 只管数据，还需要 `Model` 在调用后把模型的回复自动追加进去，否则下一轮历史里就少了 assistant 那一半。改造后的 `invoke` / `invoke_stream` 支持直接传 `Session`：

```python
def invoke(self, messages: list[dict] | Session):
    session = None
    if isinstance(messages, Session):
        session = messages
        messages = session.messages

    response = self._client.chat.completions.create(
        model=self.model_name,
        messages=cast(list, messages),
    )

    if session:
        content = response.choices[0].message.content or ""
        session.add_message(response.choices[0].message.to_dict())

    return response
```

流式版本稍复杂：流式响应没有现成的完整消息对象，需要一边收 chunk 一边把内容拼起来，收完后自己组装成 assistant 消息写回会话：

```python
def invoke_stream(self, messages: list[dict] | Session) -> Iterator[Chunk]:
    session = None
    if isinstance(messages, Session):
        session = messages
        messages = session.messages

    stream = self._client.chat.completions.create(
        model=self.model_name,
        messages=cast(list, messages),
        stream=True,
    )
    is_on_reasoning = False
    full_reasoning_content = ""
    full_content = ""
    reasoning_field = ""
    for chunk in stream:
        if not chunk.choices:
            continue
        delta = chunk.choices[0].delta
        content = delta.content
        reasoning_field_temp = "reasoning_content"
        reasoning_content = getattr(delta, reasoning_field_temp, None)
        if not reasoning_content:
            reasoning_field_temp = "reasoning"
            reasoning_content = getattr(delta, reasoning_field_temp, None)
        if reasoning_content:
            reasoning_field = reasoning_field_temp

        if reasoning_content:
            full_reasoning_content += reasoning_content
            if not is_on_reasoning:
                is_on_reasoning = True
                yield Chunk(type="reasoning_start")
            yield Chunk(type="reasoning", content=reasoning_content)
        if content:
            full_content += content
            if is_on_reasoning:
                is_on_reasoning = False
                yield Chunk(type="reasoning_end", content=full_reasoning_content)
                yield Chunk(type="content_start")
            yield Chunk(type="content", content=content)

    yield Chunk(type="content_end", content=full_content)

    if session:
        msg = {"role": "assistant", "content": full_content}
        if reasoning_field:
            msg[reasoning_field] = full_reasoning_content
        session.add_message(msg)
```

## 4. 使用会话

用法非常直观：把历史消息交给 `Session`，之后每轮只 `add_message` 一条用户消息，`Model` 会自动补齐 assistant 回复。

```python
from agent.session import Session
from agent.model import Model
from agent.prompt import render_prompt

model = Model()
session = Session()
session.add_message({"role": "system", "content": render_prompt("system")})
session.add_message({"role": "user", "content": "uv是什么？"})

# 第一次调用
resp = model.invoke_stream(session)
print_stream(resp)
```

第一轮结束后，`session.messages` 已经变成三条：system、user、assistant。接着追加第二条用户消息，再调用一次：

```python
session.add_message({"role": "user", "content": "如何安装？"})
resp = model.invoke_stream(session)
print_stream(resp)
```

这次模型能看到完整历史，就能正确理解"安装"指的是安装 uv。

想确认会话里到底存了什么，直接打印：

```python
import json

print(session.id)
print(json.dumps(session.messages, ensure_ascii=False, indent=2))
```

需要留档时保存：

```python
session.save()
```

## 5. 最佳实践

不管用什么方式实现会话，都应当遵守下面两条法则：

### 5.1 历史上下文不可修改

已经发出去的历史消息，**不要再回头去改**。原因是模型服务商普遍会做 **prompt cache**（提示词缓存）：把请求开头的公共部分缓存起来，下次命中就能省算力、省钱、提速。如果每次都修改历史，前缀就变了，缓存全部失效。

> 换句话说：追加新消息（append）是安全的，改写旧消息（modify）是昂贵的。

### 5.2 上下文中应保留思维链

带推理能力的模型会先产出"思考"再产出"答案"。把这部分思考**一起留在上下文里**，后续轮次模型能"看到自己当时怎么想的"，推理连贯性更好、回答质量更高。如果只保留最终答案、丢掉思考，相当于把模型的推理链路掐断了。

这与 [[【基础】推理机制]] 里讲的"模型靠前面的上下文预测下一个词"是一回事——上下文越完整、越接近真实的推理过程，模型表现越稳。

## 6. 总结

- **无状态**：模型不记忆，历史必须每次整包发回。
- **Session**：用 `id` + `messages` 管理一次会话，支持 `save` / `load` 持久化。
- **自动维护**：`Model` 在调用后自动把 assistant 回复写回会话。
- **两条法则**：历史不可修改（保 prompt cache），保留思维链（保推理质量）。

现在模型能对话了，但它**只会输出文本**——不能读文件、不能执行命令、不能联网。要让 Agent 真正干活，就需要 **Tool Calling**，见 [[【实战】Tool Calling]]。
