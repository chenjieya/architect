## 1. 什么是提示词工程

大模型是"输入文字、输出文字"的机器。同一件事，换个说法，结果可能天差地别。**提示词工程（Prompt Engineering）就是研究"怎么把指令写好"，让模型稳定给出期望结果的一套方法。**

它回答的核心问题是：

- 用什么**身份/角色**让模型进入正确的状态？
- 任务要**怎么描述**才不产生歧义？
- 需要给**示例**吗？给几个？
- 想要**推理过程**还是只要答案？
- 输出要**什么格式**才方便程序消费？

## 2. 为什么值得认真对待

提示词是**成本最低、见效最快**的优化手段：

- **不改模型**：不需要训练、微调，改几行文字就能提升效果。
- **即时可迭代**：改完立刻能测，反馈闭环很短。
- **可复用**：一套写好的提示词能沉淀为模板，服务大量请求。

对 Agent 而言更是如此：[[【基础】系统提示词]] 处在所有消息最前面，模型训练时会重点"关注"这一段，它写得好不好，直接决定 Agent 的行为边界。

## 3. 常用技巧

### 3.1 角色与身份

给模型一个明确身份，能收窄它的表达风格与知识调用范围，例如"你是一个严谨的代码审查助手"。

### 3.2 指令明确、结构化

把要求拆成清晰的条目，避免含糊表述；用 Markdown 标题、列表组织提示词，让模型更容易抓住重点。

### 3.3 少样本示例

需要固定格式或特定风格时，直接给一两个输入输出示例，比长篇描述更有效。

### 3.4 思维链（Chain of Thought）

对需要推理的任务，让模型"一步步想"再给答案，通常比直接要答案更准。

### 3.5 结构化输出

明确要求输出 JSON、表格等结构，方便后续程序解析，减少自然语言带来的不确定性。

### 3.6 迭代优化

提示词很少一次写对。要基于实际输出反推问题，反复改写——可参考 [[【LLM】提示词：基于反馈迭代优化]]、[[【LLM】提示词常见技巧]] 与 [[【LLM】提示词：RCT构词法]]。

## 4. 与上下文工程的关系

提示词工程关注"**指令怎么写**"；而模型最终看到的其实是**一整段上下文**——除了提示词，还包含用户问题、历史对话、工具定义、检索资料等。随着 Agent 越来越复杂，只优化"提示词那一段"已经不够，必须从整体上编排上下文。

这就是 [[【概念】上下文工程]] 要解决的问题：**提示词工程是上下文工程的一个子集**。

## 5. 总结

- **定义**：研究如何组织文字指令，让模型稳定产出期望结果。
- **价值**：不改模型、即时迭代、可沉淀复用，是性价比最高的优化手段。
- **技巧**：角色设定、指令结构化、少样本、思维链、结构化输出、迭代优化。
- **边界**：当上下文里不再只有提示词时，就需要升级到上下文工程。
