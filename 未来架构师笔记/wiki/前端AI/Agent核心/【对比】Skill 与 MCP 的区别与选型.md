[[【实战】Skill 技能系统]] 和 [[【基础】MCP 协议]] 看起来都在"给 Agent 加能力"，很容易被混为一谈。但它们**完全是两个东西**——之所以放在一起讨论，是因为在**使用感官上**有一些共同点。

## 1. 共同点

### 1.1 都有事实标准

Skill 和 MCP 各自都有事实标准。正因为有标准，才容易形成社区和聚合站：我们能直接使用大量现成的 Skill 与 MCP 工具，而不用自己从头造。

### 1.2 功能体验重叠

以"获取某个城市的天气"为例，它既可以写成一个 Skill，也可以做成一个 MCP 服务器——对用户来说结果差不多。

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1791013352385_获取天气.svg)

## 2. 差异点

关键区别在**定位**：

> MCP 告诉模型"谁来做"，Skill 告诉模型"怎么做"。

MCP 是**可执行的外部工具**，模型调用它，由服务端真正执行并返回确定结果；Skill 是**提示词模块**，模型加载它，得到的是"这类任务该怎么处理的指导"，具体动作仍由模型自己决定。

| 维度                 | Skill | MCP                        |
| -------------------- | ----- | -------------------------- |
| 上下文消耗（未命中） | 低    | 高（可通过渐进式披露解决） |
| 上下文消耗（命中）   | 高    | 低                         |
| 接入成本             | 低    | 高                         |
| 可扩展性             | 高    | 低                         |
| 贡献人群             | 广    | 窄                         |
| 确定性               | 低    | 高                         |
| 通用工具依赖         | 高    | 低                         |
| 越权风险             | 高    | 低                         |

逐行理解：

- **上下文消耗（未命中）**：没用到时，Skill 只在系统提示词里占一行名字+描述；MCP 却要把工具清单和 schema 全量注入，占得多。MCP 后续可以用渐进式披露优化（先给工具名，需要时再取 schema）。
- **上下文消耗（命中）**：一旦命中，Skill 要把整篇正文注入，成本高；MCP 调用只回一个工具结果，成本低。
- **接入成本**：写 Skill 就是写一个 Markdown 文件；写 MCP 要起服务、配传输、调协议。
- **可扩展性**：Skill 靠社区贡献提示词，增长快；MCP 需要写代码，门槛高。
- **贡献人群**：会写 Markdown 的人远多于会写服务的人，所以 Skill 贡献者更广。
- **确定性**：MCP 是代码执行，结果可复现；Skill 引导模型自由发挥，结果有波动。
- **通用工具依赖**：Skill 本身没有执行能力，必须依赖 Agent 已有的通用工具（读写文件、执行命令）去落地；MCP 自带执行能力。
- **越权风险**：Skill 只给建议，模型可能借通用工具做出危险操作；MCP 的权限边界由服务端把控，风险更低。

## 3. 最佳实践

既然两者互补，最佳实践就是**各司其职**：

> MCP 定义底层工具，Skill 定义业务流程。

**MCP 负责实现底层工具**，适合对确定性、安全性要求高的操作：

- 文件读写
- 命令执行
- 网络搜索
- 接口搜索、调用
- 代码执行
- 其他需要稳定、可审计、可限权的操作

**Skill 负责定义业务流程**，适合对灵活性、专业性要求高的流程：

- 机票怎么订、行程怎么规划
- 退货能不能退、怎么退
- 怎么介绍产品
- 怎么促成成交
- 其他依赖经验与话术的流程

一句话：**底层的"手"用 MCP，业务上的"脑子"用 Skill**。

## 4. 总结

- **共同点**：都有事实标准、都易形成社区、功能体验可能重叠。
- **定位差异**：MCP 管"谁来做"（工具执行），Skill 管"怎么做"（流程指导）。
- **权衡维度**：上下文消耗、接入成本、扩展性、确定性、风险各有优劣。
- **选型原则**：底层工具与高确定性操作交给 MCP，灵活业务与专业流程交给 Skill。
