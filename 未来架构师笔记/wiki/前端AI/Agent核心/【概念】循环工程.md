## 1. 什么是循环工程

[[【实战】ReAct 循环]] 解决的是"一次任务内的思考—行动—观察"；[[【实战】子代理 Sub Agent]] 解决的是"把大任务拆给多个 Agent"。**循环工程（Loop Engineering）则把尺度再放大一层**：

> 关注的是如何让 Agent **自我推动**，最终完成一个**可交付的产品**。

也就是说，人只给出目标与验收标准，剩下的"发现还差什么、怎么安排、怎么并行、怎么沉淀经验"都由 Agent 在一个大循环里自主完成。

## 2. 循环中包含什么

循环工程的实现方式就是**循环**，在每一轮循环中，Agent 要做五件事：

### 2.1 自主发现还未完成的任务

Agent 不能只被动等指令，而要主动对照目标检查当前进度，找出"还差什么"。这正是 [[【概念】驾驭工程]] 里"可观测"的延伸——只有能判断"完成到哪一步了"，才能发现缺口。

### 2.2 驱动多个子代理并行，并用工作树隔离

把发现的任务分派给多个子代理同时推进。关键在于**隔离**：每个子代理在自己的工作树（独立分支 / 独立目录）里干活，互不覆盖、互不污染，最后再合并。

> 隔离不力，多个 Agent 同时改同一个文件，结果会互相踩踏——这比单 Agent 更危险。

### 2.3 自主沉淀知识

每一轮产生的经验（踩过的坑、有效的做法、项目约定）要被写下来，供后续轮次或子代理复用。这是 Agent 版的"记忆"与"文档化"，直接对应 [[【概念】上下文工程]] 中的治理：不让知识随上下文膨胀而丢失。

### 2.4 自主接入工具

遇到现有工具搞不定的环节，Agent 要能发现并接入新工具（写一个、装一个、连一个 MCP）。否则循环到一半就会卡住。

### 2.5 子代理之间的分工

不同子代理承担不同角色：有的负责实现、有的负责测试、有的负责审查。分工让复杂流程可以并行，也让每种角色聚焦自己擅长的事。

## 3. 与相邻概念的关系

- **ReAct 循环**：任务内的循环，是循环工程的最小单元。
- **子代理**：循环工程并行化的执行者。
- **驾驭工程**：提供状态管理、护栏与可观测，是循环能长时间安全推进的前提。
- **上下文工程**：控制每轮循环看到的上下文，防止无限膨胀。

一句话：**循环工程 = 把 ReAct 循环、子代理、状态管理、知识沉淀组合成一个能长期自我驱动的大回路。**

## 4. 风险与约束

- **终止条件**：循环必须能停下来。需要明确的"完成标准"，否则会无限空转。
- **合并冲突**：并行子代理的产出需要可靠的合并策略，工作树隔离只是第一步。
- **成本失控**：长时间、多子代理并行会迅速放大 token 与 API 成本，必须设预算上限。
- **越权**：自主接入工具、自主执行命令意味着更大权限，护栏必须同步收紧。

## 6. 总结

- **目标**：让 Agent 自我推动，交付可用产品，而非只完成单次问答。
- **五个循环动作**：自主发现任务、并行子代理 + 工作树隔离、自主沉淀知识、自主接入工具、子代理分工。
- **前提**：依赖驾驭工程的状态管理与可观测，以及上下文工程的膨胀治理。
- **约束**：终止条件、合并冲突、成本与权限，一个都不能少。

循环描述的是"不断重复"，但如果任务本身存在清晰的依赖与分支，用**图**来编排会更精确——见 [[【概念】图工程]]。
