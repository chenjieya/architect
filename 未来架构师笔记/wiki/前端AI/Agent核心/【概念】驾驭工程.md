## 1. Harness 是什么

Harness 一词意为**马具**。

> 马具对骑乘的影响非常大。

一匹好马，配上烂马具照样难骑；一匹普通的马，配上好马具反而能跑得又稳又远。原作者的意思是：**在任务落地时，我们应该把更多注意力从"选什么马（模型）"转移到"选什么样的马具（如何驾驭模型）"身上。**

因此，这个词也被翻译为 **"驾驭工程" / "缰绳工程"**。

对 AI 应用而言，"马"是底层大模型，"马具"则是围绕模型搭建的一整套运行机制：怎么给它上下文、怎么限制它能做什么、怎么判断它做得好不好。

## 2. 三大核心关注点

### 2.1 情境与状态管理

确保 AI 在复杂、长周期任务中，能获得正确的上下文信息，并**记住任务状态**，避免"失忆"和"跑偏"。

它强调一个循环：**召回 → 规划 → 行动**。

- **召回**：从历史、记忆、外部资料里取回当前需要的信息；
- **规划**：基于现状决定下一步做什么；
- **行动**：执行并更新状态。

这正好衔接 [[【概念】上下文工程]]：上下文编排解决"这一轮给模型看什么"，情境与状态管理解决"跨轮次、跨任务如何保持一致性"。

### 2.2 护栏

像给系统设置权限一样，严格管理 AI 能调用哪些工具、访问哪些数据。核心理念是 **最小权限原则**——只给 AI 完成当前任务所必须的权限，以防误操作或恶意利用。

护栏的落地方式包括：

- 工具白名单 / 命令沙箱；
- 敏感操作需人工审批；
- 资源范围限制（只能读写指定目录、只能访问指定接口）。

这与 [[【实战】Tool Calling]] 里"工具是模型的手"直接相关——手能伸多远，必须由护栏划定。

### 2.3 可观测

需要做详细设计，保证：

- 模型知晓**是否完成了任务**？
- **判断的依据**是什么？
- 从哪里**获取判断所需的信息**？

一个 Agent 如果无法判断自己是否达标，就会陷入"自我感觉良好"或"无限打转"。可观测要求把任务的成功标准显式化，并让模型能读到验证结果（测试输出、错误日志、指标数据等）。

## 3. 与相邻概念的关系

- **上下文工程**：关注单轮上下文的质量；驾驭工程进一步关注跨轮次的状态与记忆。
- **工具系统**：工具决定 Agent 能做什么；护栏决定它被允许做什么。
- **循环工程**：驾驭工程提供"安全、可判断"的地基，[[【概念】循环工程]] 才敢让 Agent 长时间自我驱动。

## 5. 总结

- **隐喻**：从"选马"转向"配马具"，强调驾驭模型比挑选模型更关键。
- **情境与状态管理**：召回 → 规划 → 行动，跨轮次不失忆、不跑偏。
- **护栏**：最小权限原则，明确 Agent 能碰什么。
- **可观测**：让"任务是否完成"有明确依据和可获取的信息。
- **定位**：驾驭工程是 Agent 从"能跑"走向"跑得稳、可托付"的工程地基。

地基打好后，就可以让 Agent 长时间自我推动了——见 [[【概念】循环工程]]。
