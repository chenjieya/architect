> 所属：继承、多态与抽象设计 · Java 面向对象与核心类库

## 1. 概述

本节说明 **组合（Composition）**：通过 **has-a（有一个）** 持有其他对象完成功能，对比 **is-a（是一个）** 的继承；在不少场景下 **组合优于继承**，降低耦合。

## 2. 核心概念

| 术语                | 说明                                                        |
| ------------------- | ----------------------------------------------------------- |
| 组合（Composition） | 类内部**持有**其他类的对象作为成员，通过委托其方法完成行为  |
| has-a 关系          | 「汽车**有一个**发动机」，用成员变量 `Engine engine` 表达   |
| is-a 关系           | 「狗**是一种**动物」，用 `extends Animal` 表达              |
| 委托（Delegation）  | 不自己实现全部逻辑，而是调用成员对象的方法                  |
| 耦合                | 类之间依赖程度；继承过深或乱用会导致子类与父类强绑定        |
| 组合优于继承        | 优先用 has-a 复用行为；仅在真正的 is-a 且需多态时用 extends |

## 3. 操作步骤

1. **新建** `Engine.java`：字段 `power`、方法 `start()`、`getPower()`
2. **新建** `Car.java`：成员 `private Engine engine;`，构造器传入或内部 `new Engine(150)`
3. **在 `Car` 中委托**：`public void start() { engine.start(); }`
4. **新建** `CarDemo.java`：创建 `Car`，调用 `start()`、`getEnginePower()`
5. **对比思考**：若写 `class SportsCar extends Engine` 是否合理？（应否，引擎不是车的一种）
6. **运行** 验证输出

## 4. 语法与写法

### 4.1 组合示例：Car 与 Engine

```java
// 文件：Engine.java
public class Engine {
    private int power;

    public Engine(int power) {
        this.power = power;
    }

    public void start() {
        System.out.println("发动机启动，功率 " + power + " 马力");
    }

    public int getPower() {
        return power;
    }
}
```

```java
// 文件：Car.java
public class Car {
    private String model;
    private Engine engine;   // has-a：汽车有一个发动机

    public Car(String model, int enginePower) {
        this.model = model;
        this.engine = new Engine(enginePower);
    }

    public void start() {
        System.out.println(model + " 准备出发");
        engine.start();      // 委托给 Engine
    }

    public int getEnginePower() {
        return engine.getPower();
    }
}
```

```java
// 文件：CarDemo.java
public class CarDemo {
    public static void main(String[] args) {
        Car car = new Car("Model-Y", 200);
        car.start();
        System.out.println("当前引擎功率：" + car.getEnginePower());
    }
}
```

### 4.2 组合 + 接口（灵活替换部件）

```java
// 文件：Car.java（扩展：构造器注入不同 Engine）
public class Car {
    private String model;
    private Engine engine;

    public Car(String model, Engine engine) {
        this.model = model;
        this.engine = engine;   // 外部传入 Engine，便于换配置
    }

    public void start() {
        System.out.println(model + " 准备出发");
        engine.start();
    }
}
```

```java
// 使用
Car eco = new Car("Eco", new Engine(100));
Car sport = new Car("Sport", new Engine(300));
```

### 4.3 继承 vs 组合（决策简表）

| 场景                   | 更合适     | 示例                           |
| ---------------------- | ---------- | ------------------------------ |
| 明确的 is-a + 需要多态 | 继承       | `Dog extends Animal`           |
| 复用代码但非 is-a      | 组合       | `Car` 持有 `Engine`            |
| 多种能力、需多实现     | 接口       | `implements Payable, Loggable` |
| 固定流程 + 可变步骤    | 抽象类模板 | `AbstractReport.generate()`    |

### 4.4 错误示范：滥用继承

```java
// ❌ 不合理：SportsCar 不是一种 Engine
// public class SportsCar extends Engine { ... }

// ✅ 合理：SportsCar 有一个更强的 Engine
public class SportsCar extends Car {
    public SportsCar(String model) {
        super(model, new Engine(400));
    }
}
```

上例中 `SportsCar extends Car` 仍是 is-a（跑车是一种车），**引擎能力**通过组合 `Engine` 实现，而非 `extends Engine`。

## 5. 常见用法

1. **部件可替换**：同一 `Car` 类，构造时传入不同 `Engine` 功率
2. **避免继承层次爆炸**：`FlyingCar` 不必 `extends Car` 又 `extends Plane`，可 `Car` + `FlyingModule` 组合
3. **与接口配合**：`Car` 实现 `Payable`（停车缴费），`Engine` 只管动力——职责分离

## 6. 易错点

- **把 has-a 写成 extends**：`class Car extends Engine` 语义错误，且 Engine 只能单继承给 Car，无法再给 `Truck` 复用同一引擎类
- **组合后仍暴露内部对象**：直接 `return engine` 可能被外部乱改；可提供只读方法或副本
- **继承只为复用代码**：父类改一点，所有子类受影响；组合改 `Engine` 不影响 `Car` 其他逻辑
- **过深继承链**：`A → B → C → D`，排查困难；优先浅继承 + 组合/接口
- **忽略 Liskov 直觉**：子类应能替代父类使用；若子类行为与父类假设冲突，应重新考虑继承

## 7. 本节小结

- **组合** = 成员对象 + **委托**；表达 **has-a**
- **继承**适合真正的 **is-a** 与多态；仅为抄代码时用组合或工具方法
- 设计时问：**「X 是一种 Y 吗？」** 是 → 考虑继承；**「X 有一个 Y 吗？」** → 用组合
