> 所属：继承、多态与抽象设计 · Java 面向对象与核心类库

## 1. 概述

本节说明  **`abstract`  抽象类**：不能  `new`，用于抽取子类共性；含  **抽象方法**  强制子类实现，以及  **模板方法**  在父类固定流程、子类填细节。

## 2. 核心概念

| 术语                        | 说明                                                               |
| --------------------------- | ------------------------------------------------------------------ |
| 抽象类（Abstract Class）    | 用  `abstract class`  声明，**不能实例化**，可含抽象方法与具体方法 |
| 抽象方法（Abstract Method） | 只有声明、无方法体，子类**必须**实现（除非子类也是抽象类）         |
| `abstract`  关键字          | 修饰类或方法；含抽象方法的类必须是抽象类                           |
| 模板方法（Template Method） | 父类定义算法骨架（具体方法），把可变步骤留给子类重写               |
| 职责拆分                    | 公共流程放父类，差异化步骤放子类，减少重复                         |

## 3. 操作步骤

1. **新建抽象类** `AbstractReport.java`，声明  `abstract void exportBody();`
2. **写模板方法** `public final void generate()`：固定「标题 → 正文 → 页脚」顺序，中间调用  `exportBody()`
3. **新建子类** `PdfReport.java`、`TextReport.java`，分别实现  `exportBody()`
4. **新建** `ReportDemo.java`：`AbstractReport r = new PdfReport(); r.generate();`
5. **运行**：切换  `PdfReport` / `TextReport`  观察输出差异
6. **验证**：尝试  `new AbstractReport()`，IDE 应报红

## 4. 语法与写法

### 4.1 抽象类与抽象方法

```java
// 文件：AbstractReport.java
public abstract class AbstractReport {
    protected String title;

    public AbstractReport(String title) {
        this.title = title;
    }

    // 模板方法：固定流程，不允许子类改顺序（可用 final）
    public final void generate() {
        printHeader();
        exportBody();      // 抽象步骤，子类实现
        printFooter();
    }

    private void printHeader() {
        System.out.println("===== " + title + " =====");
    }

    private void printFooter() {
        System.out.println("===== END =====");
    }

    // 抽象方法：无方法体
    protected abstract void exportBody();
}
```

### 4.2 具体子类实现

```java
// 文件：PdfReport.java
public class PdfReport extends AbstractReport {
    public PdfReport(String title) {
        super(title);
    }

    @Override
    protected void exportBody() {
        System.out.println("[PDF] 导出正文内容...");
    }
}
```

```java
// 文件：TextReport.java
public class TextReport extends AbstractReport {
    public TextReport(String title) {
        super(title);
    }

    @Override
    protected void exportBody() {
        System.out.println("[TXT] 写入纯文本正文...");
    }
}
```

### 4.3 多态使用抽象父类

```java
// 文件：ReportDemo.java
public class ReportDemo {
    public static void main(String[] args) {
        AbstractReport pdf = new PdfReport("销售月报");
        AbstractReport txt = new TextReport("销售月报");

        pdf.generate();
        System.out.println("---");
        txt.generate();

        // AbstractReport r = new AbstractReport("x");  // 编译错误：不能 new 抽象类
    }
}
```

### 4.4 抽象类 vs 普通类（对比）

| 对比项         | 普通类         | 抽象类                                    |
| -------------- | -------------- | ----------------------------------------- |
| 能否  `new`    | 能             | **不能**                                  |
| 能否有抽象方法 | 不能           | 能                                        |
| 子类要求       | 可直接 extends | 必须实现全部抽象方法（或子类也 abstract） |

## 5. 常见用法

1. **报表/日志导出**：头尾相同，中间格式不同 → `generate()` + `exportBody()`
2. **游戏角色回合**：`playTurn()`  固定流程，攻击/防御步骤子类不同
3. **与多态结合**：业务代码只依赖  `AbstractReport`，具体用  `PdfReport`  或  `TextReport`

## 6. 易错点

- **抽象类忘记实现抽象方法**：具体子类漏写  `exportBody()` → 编译错误，或子类须声明为  `abstract`
- **把抽象类当接口用**：抽象类可有构造器、字段、具体方法；仍占**单继承**位
- **模板方法步骤过多抽象化**：每一步都 abstract 会难读；只把**真正变化**的步骤抽象
- **误写抽象方法体**：`abstract void m() { }`  非法，抽象方法不能有  `{}`  实现
- **`final`  模板方法被重写**：若希望流程固定，模板方法应  `final`，子类只改抽象钩子

## 7. 本节小结

- **抽象类**不能实例化，用于抽取共性 + 定义抽象步骤
- **抽象方法**强制子类实现；**模板方法**在父类固定算法骨架
- 与多态配合：`AbstractReport r = new PdfReport(); r.generate();`
