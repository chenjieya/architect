## 1. 概述

本节说明如何**自定义异常类**表达业务错误（如余额不足、订单不存在），如何编写**有意义的异常名与消息**，以及受检与非受检自定义异常的**选型入门**。

## 2. 核心概念

| 术语                | 说明                                                                        |
| ------------------- | --------------------------------------------------------------------------- |
| 自定义异常          | 继承 `Exception` 或 `RuntimeException`（或其子类）的自有异常类              |
| 业务异常            | 表示业务规则违反，如 `InsufficientFundsException`、`OrderNotFoundException` |
| 异常消息（message） | 构造时传入的说明文字，通过 `getMessage()` 获取，应**可读、可定位**          |
| 受检自定义异常      | `extends Exception`，调用方必须处理或 `throws`                              |
| 非受检自定义异常    | `extends RuntimeException`，适合「调用方难以预先处理」的编程/业务错误       |
| `super(message)`    | 子类构造器中把消息交给父类，保证 `getMessage()` 一致                        |

## 3. 操作步骤

在 IDEA 中完成「自定义 + 抛出 + 捕获」：

1. **新建** `InsufficientFundsException.java`，继承 `RuntimeException`，提供带 `message` 的构造器
2. **修改** `BankAccount.withdraw`：余额不足时 `throw new InsufficientFundsException(...)`
3. **新建** `OrderNotFoundException.java`（继承 `Exception` 作受检示例），在 `OrderService.findById` 中找不到时抛出
4. **新建** `OrderService.java` 与 `OrderDemo.java`：`findById` 声明 `throws OrderNotFoundException`，调用方 `try-catch`
5. **运行** 两个 Demo，对比受检与非受检在调用处的写法差异

## 4. 语法与写法

### 4.1 非受检业务异常（常用）

```java
// 文件：InsufficientFundsException.java
public class InsufficientFundsException extends RuntimeException {
    public InsufficientFundsException(String message) {
        super(message);
    }
}
```

```java
// 文件：BankAccount.java（节选：withdraw 改用自定义异常）
public void withdraw(double amount) {
    if (amount <= 0) {
        throw new IllegalArgumentException("取款金额必须大于 0");
    }
    if (amount > balance) {
        throw new InsufficientFundsException(
            "账户 " + owner + " 余额不足，需要 " + amount + "，当前 " + balance);
    }
    balance -= amount;
}
```

### 4.2 受检业务异常（调用方必须处理）

```java
// 文件：OrderNotFoundException.java
public class OrderNotFoundException extends Exception {
    public OrderNotFoundException(String message) {
        super(message);
    }
}
```

```java
// 文件：OrderService.java
public class OrderService {
    public String findById(String orderId) throws OrderNotFoundException {
        if (orderId == null || orderId.isEmpty()) {
            throw new OrderNotFoundException("订单号不能为空");
        }
        if (!"10001".equals(orderId)) {
            throw new OrderNotFoundException("未找到订单: " + orderId);
        }
        return "订单详情-" + orderId;
    }
}
```

```java
// 文件：OrderDemo.java
public class OrderDemo {
    public static void main(String[] args) {
        OrderService service = new OrderService();
        try {
            System.out.println(service.findById("10001"));
            System.out.println(service.findById("99999"));
        } catch (OrderNotFoundException e) {
            System.out.println("查询失败: " + e.getMessage());
        }
    }
}
```

### 4.3 命名与消息建议

| 建议                    | 示例                                           |
| ----------------------- | ---------------------------------------------- |
| 类名以 `Exception` 结尾 | `InsufficientFundsException`                   |
| 消息含关键业务数据      | `"余额不足，需要 200，当前 100"`               |
| 一种错误一种类          | 不要把「找不到」和「无权限」混在一个泛化异常里 |

## 5. 常见用法

1. **可预期的业务失败**：用自定义异常 + 清晰消息，UI 层 catch 后提示用户
2. **API 层**：受检异常表示「调用方必须考虑」的失败；团队规范统一即可
3. **与 `IllegalArgumentException` 分工**：参数格式错用 `IllegalArgumentException`；余额不足用业务异常类
4. **保留原因**：包装底层异常时 `super("加载订单失败", cause)`（需带 `Throwable cause` 的构造器）

## 6. 易错点

- **类名不像异常**：`BalanceError` 不如 `InsufficientFundsException` 一眼可知类型
- **空消息**：`throw new InsufficientFundsException();` 排查时只有类名没有上下文
- **滥用受检异常**：层层 `throws` 导致代码臃肿；很多团队业务异常倾向 `RuntimeException` 子类（本课两种都练）
- **继承错父类**：想受检却 `extends RuntimeException`，调用方编译期无感知
- **在异常里写复杂业务逻辑**：异常类应轻量，逻辑放在服务类，异常只负责**携带信息**

## 7. 本节小结

- 自定义异常通过 **`extends Exception` 或 `RuntimeException`** 表达业务语义
- **类名、消息** 要让人和日志都能读懂；构造器用 **`super(message)`**
- **受检** 强制调用方处理；**非受检** 灵活但须在边界 `catch` 或统一处理
- 示例：`InsufficientFundsException` + `OrderNotFoundException` 配合 `BankAccount`、`OrderService`
