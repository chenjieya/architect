## 1. 概述

本节聚焦 **`NullPointerException`**、**数组越界**、**数字格式错误** 等高频运行时异常，说明典型成因、如何用 **IDE 栈信息** 与 **防御式校验** 排查，并介绍 **`Objects.requireNonNull`** 等入门写法。

## 2. 核心概念

| 术语                             | 说明                                                  |
| -------------------------------- | ----------------------------------------------------- |
| `NullPointerException`（NPE）    | 对值为 `null` 的引用调用方法或访问字段时抛出          |
| `ArrayIndexOutOfBoundsException` | 数组下标 `< 0` 或 `>= length`                         |
| `NumberFormatException`          | 字符串无法解析为请求的数字类型                        |
| 防御式编程                       | 在使用前**校验**参数与状态，失败时早返回或抛明确异常  |
| `Objects.requireNonNull`         | JDK 工具方法，参数为 `null` 时立即抛 NPE 并带指定消息 |
| 空安全习惯                       | 赋值、返回值、集合元素使用前考虑是否可能为 `null`     |

## 3. 操作步骤

在 IDEA 中练习「制造 → 读栈 → 修复」：

1. **新建** `NpeDemo.java`：未初始化对象就调用方法，Run 后记录 **栈顶业务行号**
2. **用断点**：在可疑行左侧打断点，Debug 查看变量是否为 `null`
3. **修复**：增加 `if (obj == null)` 判断或保证构造/`new` 赋值
4. **新建** `BoundaryDemo.java`：演示数组越界与 `Integer.parseInt("12a")`
5. **将** `NpeDemo` 中一处改为 `Objects.requireNonNull(name, "姓名不能为 null");`，对比异常消息

## 4. 语法与写法

### 4.1 NPE 典型场景与修复

```java
// 文件：NpeDemo.java
public class NpeDemo {
    public static void printLength(String name) {
        // 修复前：name 为 null 时 name.length() 抛 NPE
        if (name == null) {
            System.out.println("姓名为空，跳过长度计算");
            return;
        }
        System.out.println("长度: " + name.length());
    }

    public static void main(String[] args) {
        printLength(null);
        printLength("李四");
    }
}
```

```java
import java.util.Objects;

public class UserService {
    public void register(String username) {
        Objects.requireNonNull(username, "用户名不能为 null");
        if (username.isEmpty()) {
            throw new IllegalArgumentException("用户名不能为空字符串");
        }
        System.out.println("注册: " + username);
    }
}
```

### 4.2 边界与格式

```java
// 文件：BoundaryDemo.java
public class BoundaryDemo {
    public static int parseIndex(String text, int length) {
        int index = Integer.parseInt(text);   // 可能 NumberFormatException
        if (index < 0 || index >= length) {
            throw new IllegalArgumentException("下标非法: " + index + ", 长度: " + length);
        }
        return index;
    }

    public static void main(String[] args) {
        int[] data = {10, 20, 30};
        try {
            int i = parseIndex("1", data.length);
            System.out.println(data[i]);
            System.out.println(data[10]);   // ArrayIndexOutOfBoundsException
        } catch (NumberFormatException e) {
            System.out.println("不是数字");
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("数组越界: " + e.getMessage());
        }
    }
}
```

### 4.3 读栈定位（IDEA）

1. 控制台点击异常行 **`at NpeDemo.printLength(NpeDemo.java:5)`**
2. IDEA 跳转到 **第 5 行**，查看哪个引用为 `null`
3. 沿调用栈向上看 **谁传入了 null**（`main` → `printLength`）

### 4.4 与封装、构造器衔接

```java
// 文件：AccountValidator.java
public class AccountValidator {
    public static void checkOwner(String owner) {
        Objects.requireNonNull(owner, "户主不能为 null");
        if (owner.trim().isEmpty()) {
            throw new IllegalArgumentException("户主姓名不能为空");
        }
    }
}
```

在 `BankAccount` 构造器中先调用 `checkOwner(owner)`，避免对象处于非法状态。

## 5. 常见用法

1. **方法入口校验**引用参数，失败抛 `IllegalArgumentException` 或 `Objects.requireNonNull`
2. **集合/数组访问前**检查 `length` 与下标范围
3. **解析用户输入**用 `try-catch NumberFormatException` 或先校验格式
4. **返回值为对象时**文档或命名标明是否可能 `null`（进阶用 `Optional`，后续章节）

## 6. 易错点

- **只 catch 不防**：反复 NPE 却不修根因（未赋值、未校验）
- **自动拆箱 NPE**：`Integer n = null; int x = n;` 会 NPE
- **链式调用 NPE**：`a.getB().getC()` 中间任一环节 `null` 都会炸
- **混淆 NPE 与「找不到」**：业务「无数据」宜用明确异常或返回值约定，不要靠 NPE
- **requireNonNull 后仍要业务校验**：`requireNonNull` 只防 `null`，不防空字符串

## 7. 本节小结

- **NPE、越界、格式错误** 是最常见的三类运行时异常，靠 **栈行号** 定位
- **防御式校验**：入口检查、`Objects.requireNonNull`、合法范围判断
- 业务「不存在」应用 **自定义异常或明确返回值**，不要用 NPE 表达业务语义
- 与 **`BankAccount` / `AccountValidator`** 结合，在构造与方法入口建立健壮习惯
