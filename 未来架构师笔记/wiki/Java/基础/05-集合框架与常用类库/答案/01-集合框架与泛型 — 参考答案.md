## 2. L2 原理与应用

### 2.1

**答**：改用 **`Set`** 接口及 **`HashSet`**（或 `Set` + `HashSet`）。`Set` 按 `equals`/`hashCode` 保证元素不重复，无需手写双重循环，语义更清晰。

### 2.2

**答**：`Set` 不允许重复元素，第二次 `add("A")` 无效；`List` 允许重复，故 size 为 2。唯一用户名应选 **`Set`**（如 `HashSet<String>`）。

### 2.3

**答**：**现象**：ArrayList 的 `get` 远快于 LinkedList。**结构**：ArrayList 数组下标直接访问 O(1)；LinkedList 需从链头遍历到索引 O(n)。**结论**：大量随机读应选 ArrayList。

### 2.4

**答**：① 键 `"英语"` 不存在；② 键存在且值为 `null`。用 `containsKey("英语")`：false 为不存在，true 且 get 为 null 表示值为 null。

### 2.5

**答**：`hashCode` 决定进哪个桶；桶内用 `equals` 判断是否同一键。只重写 `equals` 时，两对象 `equals` 为 true 但 `hashCode` 可能不同，会进不同桶，`HashMap` 视为两个键，故 `size` 可能为 2。

### 2.6

**答**：`? extends Number` 表示只读上界，编译器无法保证 `add` 的元素类型安全，故禁止 add；`get` 取出至少是 Number 子类，可赋给 Number。体现 **泛型不变性**，上界通配符偏读。

### 2.7

**答**：for-each 内部用 Iterator，结构修改（直接 `list.remove`）与迭代器预期不一致，触发 `ConcurrentModificationException`。改法：用 **`Iterator` 的 `remove()`**，或先收集要删元素再统一删（本章推荐 Iterator）。

### 2.8

**答**：`compare` 返回 0 表示相等；在稳定排序下，相等元素（同姓名）可能 **保持原先相对顺序**（相对学号排序后的顺序）。

### 2.9

**答**：`HashSet` 不允许重复元素，重复整数只保留一份。要保持首次出现顺序用 **`LinkedHashSet`**：`new ArrayList<>(new LinkedHashSet<>(raw))`。

### 2.10

**答**：① 先 `containsKey(userId)` 或判 `getToken` 是否为 null 再调用 `length`；② 未登录返回明确约定（如空字符串）或文档说明，避免对 null 链式调用。与第 3 章 **防御式编程** 一致。

## 3. L3 场景实战

### 3.1 [面试]

**答**：**List**：有序、可重复，如 `ProductCatalog` 商品列表。**Set**：不重复，如用户标签去重。**Map**：键唯一、键值查找，如 `UserSessionMap` 的 userId→token。

### 3.2 [面试]

**答**：ArrayList 动态数组，随机访问快；LinkedList 双向链表，按索引慢、头尾操作灵活。业务读多、按下标访问多，数组更省时间且缓存友好，故默认 ArrayList。

### 3.3 [面试]

**答**：`put` 用 `hashCode` 定位桶，桶内用 `equals` 判断同键则覆盖、不同键则冲突。冲突：不同键同一桶，用链表存放（JDK8+ 过长转红黑树）。扩容降低冲突。

### 3.4 [面试]

**答**：编译期类型检查，减少强转与 `ClassCastException`。类型擦除：编译后泛型信息大多擦除，运行期主要按 Object 或边界处理，检查主要在编译期完成。

### 3.5 [面试·扩展]

**答**：`extends` 偏 **Producer（往外取）**；`super` 偏 **Consumer（往里放）**。PECS：Producer Extends, Consumer Super。

### 3.6 [面试]

**答**：`Comparable` 元素自身 `compareTo`，自然排序；`Comparator` 外部比较器。无参 `sort(list)` 依赖 **Comparable**；双参 `sort(list, comparator)` 依赖 **Comparator**。

### 3.7 [工作]

**答**：用 **`LinkedHashSet`** 去重保序：`new ArrayList<>(new LinkedHashSet<>(orderList))`；或遍历订单列表，用 **`LinkedHashSet`** 按订单号去重（键为订单号时需 `Map` 或 Set 存订单号，简单列表可对订单号 `LinkedHashSet` 再重建列表）。要点：**LinkedHashSet** 保留首次出现顺序。

### 3.8 [面试]

**答**：增强 for 使用迭代器，直接 `list.remove` 导致并发修改异常。应使用 **`Iterator.remove()`**。

### 3.9 [面试]

**答**：先 **`containsKey(key)`**：false 则键不存在；true 且 `get` 为 null 则值为 null。

### 3.10 [工作]

**答**：**Map**：`get(userId)` 可能 null（无缓存），链式 `.getName()` 前判空或 `containsKey`。**防御**：`get` 后判空再调方法；或放入 Map 前保证非 null；结合第 3 章 **入口校验** 与明确「无用户」语义，避免用 NPE 表达业务不存在。
