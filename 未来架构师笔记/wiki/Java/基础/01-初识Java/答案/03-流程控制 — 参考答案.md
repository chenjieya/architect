## 2. L2 原理应用

### 2.1

**现象**：95 分输出「及格」而非「优秀」。  
**推理**：`else if`  链从上到下匹配；`95 >= 60`  为真，进入第一个分支后**不再判断** `>= 90`。  
**结论**：互斥区间应  **先严后宽**。  
**修改**：先  `else if (score >= 90)`  再  `else if (score >= 60)`（其余分支顺序相应调整）。

### 2.2

**现象**：打印  `Tue`  后继续打印  `Wed`（若 default 无 break 还可能更多）。  
**推理**：case 2 末尾**无 break**，执行流  **fall-through（贯穿）**  进入 case 3。  
**结论**：传统 switch 默认不自动停止。  
**修复**：① case 2 末尾加  `break;`；② 或改为  `case 2 -> System.out.println("Tue");`（箭头写法默认不贯穿）。

### 2.3

**现象**：`i`  恒为 0，条件  `i < 5`  一直为真，死循环。  
**推理**：循环体内**未更新** `i`。  
**结论**：`while`  须在体中使条件 eventually 为假。  
**补全**：在  `println`  后加  `i++;`（或  `i = i + 1`）。

### 2.4

**推断**：仅打印  **1**（一行）。  
**分步**：

- i=0：`i==3`  否；`i % 2 == 0`  为真 → `continue`，不打印
- i=1：`i==3`  否；奇数 → 打印 1
- i=2：`i==3`  否；偶数 → `continue`，不打印
- i=3：`i==3`  为真 → `break`，不再执行第二个  `if`，循环结束

**最终打印**：只有  **1**。

### 2.5

**过程**：外层 4 次，每次内层完整 3 次 → `count`  增加 4×3=12 次。  
**最终**：`count = 12`。  
**内层 j==1 时 break**：每轮内层只执行 j=0,1 两次 → 总次数  **变少**（为 4×2=8）。

## 3. L3 场景实战

### 3.1 [面试]

**要点**：

- Java **强类型**，条件位置要求  `boolean`，避免 C/JS 中  `if (x=1)`  误写为真的经典错误
- 与第 2 章一致：类型在编译期检查，减少隐式 truthy/falsy 带来的歧义

### 3.2 [面试]

**要点**：

- **switch**：**单个表达式**对**多个离散常量**（星期 1 ～ 7），结构清晰
- **if-else**：**区间**、**复合布尔条件**（分数段、BMI），switch 无法直接表达连续区间

### 3.3 [面试]

**要点**：

- **break**：**结束整个循环**（或跳出 switch case 贯穿）
- **continue**：**跳过本轮剩余代码**，进入下一轮迭代
- **continue 场景**：打印 1 ～ 10 中的奇数（偶数时  `continue`  跳过）

### 3.4 [面试·扩展]

**要点**：

- **do-while**  先执行体再判条件，**至少 1 次**菜单展示
- 纯  **while**  若初始条件为假（如尚未读入用户输入就判「是否继续」），可能  **0 次**展示菜单

### 3.5 [面试]

**要点**：

- **fall-through**：未  `break`  时执行流进入**下一 case**
- **故意特性**：多个 case 标签共用一段逻辑（case 1/2/3 连写后一个 break）
- **bug**：忘记 break 导致多输出、逻辑错乱

### 3.6 [工作]

**要点**：

- 选用  **do-while**：保证菜单**至少显示一次**
- 菜单打印放在  **循环体开头**（先展示再读选项、再判是否继续）
- 理由：若条件在末尾且初值为假，while 可能一次都不进入
