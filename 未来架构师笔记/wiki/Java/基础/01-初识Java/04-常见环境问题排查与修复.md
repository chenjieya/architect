## 1. 概述

本节汇总初学者高频环境问题：**多版本 JDK、Path 顺序、IDE 与终端不一致** 等，给出排查命令与修复步骤。分层排查的**思维迁移**见教案。

## 2. 核心概念

| 术语                | 说明                                                                                                                    |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Path 搜索顺序       | 系统从 Path **第一项起**查找可执行文件，**先匹配到的先生效**                                                            |
| 版本分裂            | `java -version` 与 `javac -version` **主版本不一致**，通常说明两者来自不同安装路径                                      |
| Project SDK（IDEA） | **项目结构 → 项目 → SDK**（界面常只标 SDK）；IDE 编译/提示用的 JDK，**独立于** Path；**不是** Maven「运行程序」里的 JRE |
| 四层排查            | ① JDK 本体 → ② 环境变量 → ③ IDE 配置 → ④ 源码/命令/目录                                                                 |

## 3. 操作步骤

### 3.1 排查命令（Windows）

```powershell
java -version
javac -version
echo $env:JAVA_HOME
where java
where javac
```

Linux / macOS 将 `where` 换为 `which`，`echo $env:JAVA_HOME` 换为 `echo $JAVA_HOME`。

### 3.2 分层排查流程

```text
第 1 层：java / javac -version 是否正常、版本是否一致
第 2 层：JAVA_HOME、Path 顺序、where 实际路径
第 3 层：**项目结构 → 项目 → SDK**（Project SDK）是否为 JDK 17；改 Path 后是否重启 IDE
第 4 层：类名/文件名、是否 javac、当前目录、main 签名（含 static）
```

### 3.3 典型问题修复

#### 3.3.1 `'java' 不是内部或外部命令`

1. 确认已安装 JDK
2. 设置 `JAVA_HOME` 为 JDK 根目录
3. Path 添加 `%JAVA_HOME%\bin`，且尽量靠前
4. **新开**终端

#### 3.3.2 `java` 可用但 `javac` 不可用

- Path 可能指向 **JRE** 或旧版残留 → 改为 **JDK** 的 `bin`；用 `where javac` 确认

#### 3.3.3 `java` 1.8 与 `javac` 17 不一致

1. `where java` 与 `where javac` 对比路径
2. 常见原因：Path 中 **`Oracle javapath`** 或旧 JRE **排在** `%JAVA_HOME%\bin` **前面**
3. 处理：删除或后移冲突项，保证 JDK 17 的 `bin` 优先；统一 `JAVA_HOME`
4. 新开终端，再测

#### 3.3.4 `错误: 找不到或无法加载主类 X`

| 检查项    | 处理                                    |
| --------- | --------------------------------------- |
| 类名拼写  | `java` 后的名字与 public 类名一致       |
| 是否编译  | 目录下是否有 `X.class`                  |
| 当前目录  | 无 package 时，在 `.class` 所在目录执行 |
| main 签名 | 必须含 **`static`** 等标准签名          |

#### 3.3.5 IDEA 正常、终端 `javac` 失败

- 终端依赖 **Path / JAVA_HOME**；IDEA 绿色三角依赖 **项目结构 → 项目 → SDK**
- 两处分别检查；**第 1 章不涉及 Maven**，勿只改 Maven 里的 JRE 就当环境修好

#### 3.3.6 `Main method not found` 但 javac 成功

- 检查 `main` 是否为 **`public static void main(String[] args)`**
- 缺 **`static`** 时典型：编译过、运行失败（见第 3 节文档）

## 4. 常见用法

- 改 Path 后：**新终端** + 必要时 **重启 IDEA**
- 同事能跑你不能：先对比 `java -version`、`javac -version`、`where java`，再对比 IDEA Project SDK

## 5. 易错点

- **只查 `java` 不查 `javac`** → 无法发现 JRE-only 或版本分裂
- **忽略 Path 顺序** → 多条 Java 路径时旧版可能“抢答”
- **以为 IDEA 能 Run 等于环境正确** → 必须在**系统终端**独立验证

## 6. 本节小结

- Path **顺序优先**；用 **`where java` / `where javac`** 定位版本分裂
- 终端看 **Path/JAVA_HOME**；IDEA 看 **项目结构 → 项目 → SDK**
- **`Main method not found`** 且已编译：优先查 **main 是否 static、签名是否标准**
