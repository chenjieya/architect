## 1. Linux 用户分类

### 1.1 系统用户

- **UID 范围**：0 和 1~999
- **root 用户**：UID 为 0，拥有最高权限
- **系统进程用户**：UID 1~999，用于系统服务进程，不能用于登录系统。

`id root` 查看用户 ID、 初始组、 附加组
![image.png](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/20251118171147642.png)

### 1.2 普通用户

- **UID 范围**：1000~65536
- 用于日常操作和普通应用程序

> 创建用户会默认也创建一个和用户同名的组。

## 2. 用户配置文件

### 2.1 /etc/passwd 文件

存储用户基本信息，但不包含密码。

**文件格式示例：**

```
root:x:0:0:root:/root:/bin/bash
```

**各字段含义：**

- **用户名**：用户登录名
- **密码占位符**：x 表示密码存储在/etc/shadow 文件中
- **UID**：用户 ID
- **GID**：主组 ID
- **描述信息**：用户全名或描述（通常无意义）
- **家目录**：用户的主工作目录
- **Shell 环境**：用户登录后使用的 shell
  - `/bin/bash`：可登录的 bash shell
  - `/sbin/nologin`：禁止登录
  - `/bin/false`：禁止登录

![image.png](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/20251118171352863.png)

### 2.2 /etc/shadow 文件

存储用户的实际密码和密码策略信息。

![image.png](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/20251118171412818.png)

**每行格式**（`:` 分隔，共 9 个字段）：

```
用户名:密码:最近修改日:最小修改间隔:密码有效期:警告期:宽限期:账号失效日:保留
```

**各字段含义：**

| 字段         | 含义                                                         |
| ------------ | ------------------------------------------------------------ |
| 用户名       | 账号名称，与 /etc/passwd 对应                                |
| 密码         | 加密后的密码（`!` 或 `!!` 表示未设置密码/锁定）              |
| 最近修改日   | 距 1970-01-01 的天数，最后一次修改密码的日期                 |
| 最小修改间隔 | 距上次修改密码后，**多少天内禁止再改**；0 表示随时可改       |
| 密码有效期   | 密码最多使用多少天；**99999 表示永不过期**，无需重设         |
| 警告期       | 密码即将到期前，提前多少天向用户发出警告                     |
| 宽限期       | 密码过期后，**多少天内仍可登录**（宽限期内还能用旧密码登录） |
| 账号失效日   | 账号在什么日期失效（距 1970-01-01 的天数），到时无法登录     |
| 保留字段     | 目前无用，保留                                               |

> **提示**：`chage -l 用户名` 可以把你账号的密码策略以可读形式列出来，非常方便查看，不必手算天数。

## 3. 用户管理命令

### 3.1 创建用户

```bash
# 基本创建用户
useradd username

# 创建用户时指定详细信息
useradd -g groupname -d /home/username -s /bin/bash -e 2015-07-01 username
```

**参数说明：**

- `-g`：指定主组
- `-d`：指定家目录
- `-s`：指定 shell 环境
- `-e`：设置账号过期时间

```bash
# 创建系统账号（UID 自动落在系统区间）
useradd -r sysuser

# 系统账号创建时会参考的配置文件
#  /etc/login.defs          # 用户默认属性（UID范围、密码策略等）
#  /etc/default/useradd     # useradd 默认值（默认shell、家目录基址等）
#  /etc/skel/               # 骨架目录，用户家目录的"模板"，里面的文件会自动复制给新用户
ls /etc/skel
.bash_logout  .bash_profile  .bashrc
```

> **区分**：`useradd username` 创建**普通用户**（UID ≥ 1000）；`useradd -r username` 创建**系统账号**（UID 落在系统区间，无家目录或非登录 shell），常用于运行系统服务（如 nginx、mysql 用的账号），不用于登录。

### 3.2 设置用户密码

```bash
# 交互式设置密码
passwd username

# 非交互式设置密码
echo "password" | passwd --stdin username
```

### 3.3 修改用户信息

```bash
# 修改账号过期时间
usermod -e 2024-12-31 username

# 查看用户密码信息
chage -l username
```

### 3.4 删除用户

```bash
# 删除用户及其家目录
userdel -r username
```

> **注意：** `-r`参数会同时删除用户的家目录。家目录很重要，`history`等历史记录都存在家目录下面

## 4. 用户组管理

### 4.1 创建和删除用户组

```bash
# 创建用户组
groupadd groupname

# 创建时指定 GID
groupadd -g 10000 train    # 新建组 train，GID 强制指定为 10000

# 删除用户组
groupdel groupname
```

> **注意：** 当组中有关联用户时，无法删除该组

### 4.2 修改用户组关系

```bash
# 修改用户的主组（会移除原来的附加组）
usermod -g groupname username

# 修改用户的附加组（会覆盖原来的附加组）
usermod -G groupname username

# 同时指定多个附加组
usermod -G testalvis,testgroup testuser
```

### 4.3 初始用户组 vs 有效用户组（newgrp）

一个用户可以有多个组：**初始用户组**（主组，写入 /etc/passwd 第 4 字段）和**附加组**（写入 /etc/group 第 4 字段）。

**问题：当用户属于多个组时，他新建的文件"组所有者"到底是哪个组？** —— 答案是**有效用户组**。

- **初始用户组（主组）**：创建用户时指定的组，`id` 命令显示的第一个组
- **有效用户组**：用户**当前生效**的组，创建文件时文件继承这个组
- 登录时，有效用户组 = 初始用户组；可用 `newgrp` 临时切换

```bash
# 查看当前用户身份（第一个组是初始组）
$ id
uid=500(testuser) gid=502(testuser) groups=502(testuser),503(pgroup)

# 用 newgrp 切换到附加组 pgroup，使其成为"有效用户组"
$ newgrp pgroup

# 此时再创建文件，文件的组所有者就是 pgroup
$ touch /tmp/testfile
$ ls -l /tmp/testfile
-rw-r--r-- 1 testuser pgroup 0 8月  2 19:00 /tmp/testfile

# 用 groups 命令确认当前生效的组
$ groups
testuser pgroup
```

> **记忆技巧**：文件"跟谁姓"取决于你**当时**用哪个有效组去创建；`newgrp 组名` 就是临时换"姓氏"。退出该组用 `exit` 回到初始组。

## 5. 权限管理

### 5.1 权限表示方法

**权限位说明：**

```
l r w x r w x r w x
│ │ │ │ │ │ │ │ │ │
│ │ │ │ │ │ │ │ └── 其他用户执行权限 (others execute)
│ │ │ │ │ │ │ └─── 其他用户写权限 (others write)
│ │ │ │ │ │ └───── 其他用户读权限 (others read)
│ │ │ │ │ │
│ │ │ │ │ └─────── 所属组执行权限 (group execute)
│ │ │ │ └───────── 所属组写权限 (group write)
│ │ │ └─────────── 所属组读权限 (group read)
│ │ │
│ │ └───────────── 所属用户执行权限 (user execute)
│ └─────────────── 所属用户写权限 (user write)
└───────────────── 所属用户读权限 (user read)
│
└───────────────── 文件类型标识
```

**文件类型标识：**

- `-`：普通文件
- `d`：目录
- `l`：符号链接
- `s`：socket 文件
- `p`：pipe 文件
- `b`：块设备文件
- `c`：字符设备文件

### 5.2 权限修改方法

#### 5.2.1 字符表示法

```bash
# 添加执行权限
chmod u+x filename

# 移除写权限
chmod g-w filename

# 设置特定权限
chmod u=rwx,g=rx,o=r filename

# 清空所有权限
chmod u=- filename
```

**权限标识符：**

- `u`：用户（user）
- `g`：用户组（group）
- `o`：其他用户（others）
- `a`：所有用户（all）

**权限操作符：**

- `+`：添加权限
- `-`：移除权限
- =: 设置权限（覆盖原有权限）

#### 5.2.2 数字表示法

```bash
# 设置完全权限 (rwxrwxrwx)
chmod 777 filename

# 设置用户可读写执行，组可读执行，其他无权限 (rwxr-x---)
chmod 750 filename
```

**权限数值：**

- `r`（读）= 4
- `w`（写）= 2
- `x`（执行）= 1

## 6. 所有权管理

### 6.1 修改文件所有者

```bash
# 修改文件所有者
chown username filename

# 递归修改目录及其内容的所有者
chown -R username directory

# 同时修改所有者和所属组
chown username:groupname filename
```

### 6.2 修改文件所属组

```bash
# 修改文件所属组
chgrp groupname filename

# 递归修改目录及其内容的所属组
chgrp -R groupname directory
```

## 9. 权限匹配规则

**重要权限匹配顺序：**

1. **用户权限**：如果文件属于当前用户，直接应用用户权限
2. **组权限**：如果文件不属于当前用户但当前用户属于文件所属组，应用组权限
3. **其他用户权限**：以上都不满足时，应用其他用户权限

**注意：** 权限匹配具有优先级，一旦匹配成功就不会继续向后匹配。

## 10. umask 权限掩码

### 10.1 umask 作用

umask 用于设置新建文件和目录的默认权限。

### 10.2 计算方法

```bash
# 查看当前umask值
umask

# 目录默认权限 = 777 - umask
# 文件默认权限 = 666 - umask（自动去掉执行权限）
```

**示例：**
如果 umask 为 0022：

- 目录权限：777 - 022 = 755 (rwxr-xr-x)
- 文件权限：666 - 022 = 644 (rw-r--r--)

## 11. 文件隐藏属性

### 11.1 chattr 命令

```bash
# 添加不可修改属性
chattr +i filename

# 移除不可修改属性
chattr -i filename
```

**i 属性效果：**

- 不能修改文件内容
- 不能删除文件
- 不能重命名文件
- 不能创建软链接
- 不能修改文件权限

## 12. 重要提示

1. **家目录重要性**：用户的`history`等历史记录都存储在家目录中
2. **用户创建默认行为**：创建用户时会自动创建一个同名的用户组
3. **权限操作谨慎**：使用`-R`参数递归修改权限时要特别小心
4. **系统用户保护**：不要随意修改系统用户的属性和权限

## 13. 练习巩固

**用户和组管理：**

1. 创建用户账户 `practice`，密码 `practice`
2. 创建用户账户 `baduser`，密码 `baduser`
3. 创建附加组 `pgroup`，GID 指定为 30000
4. 创建附加组 `badgroup`
5. 将 `practice` 用户添加到附加组 `pgroup` 中
6. 修改 `baduser` 的密码为 `redhat`
7. 修改 `baduser` 账户，使其密码在 30 天后过期
8. 删除 `baduser` 账户
9. 删除 `badgroup` 附加组

**文件及文件夹权限：**

1. 创建名为 `ateam` 的组
2. 创建名为 `bteam` 的组
3. 在 `/home` 目录中创建名为 `ateam` 的文件夹
4. 将 `ateam` 文件夹的组所有权更改为 `ateam`
5. 确保 `ateam` 文件夹访问权限为允许组成员创建和删除文件
6. 确保 `ateam` 文件夹访问权限为禁止其他人访问其文件

> 参考提示：第 5、6 题涉及组写权限与"other"权限的控制，可结合 chmod（如 `chmod 770`）完成；若要成员删除他人文件还需考虑 SGID/Sticky Bit，可参考《特殊权限》篇。
