## 1. 链接是什么

Linux 中一个文件在磁盘上由两部分组成：

- **inode**（节点）：记录文件的属性，以及内容存在哪个块
- **block**（数据块）：存放文件内容

"链接"就是给同一个 inode 再开一个"别名"，让我们可以从不同的路径访问同一份数据。链接分两种：**软链接**（符号链接）和**硬链接**。
相关：inode/block 的存储细节与文件系统结构见 [[【磁盘】Linux文件系统与磁盘管理完全指南]]。

## 2. 软链接（符号链接）

### 2.1 创建方式

```bash
ln -s 源文件 链接名    # -s 表示 symbolic（符号链接）
```

```bash
# 给 /etc/hosts 建一个软链接
$ ln -s /etc/hosts myhosts
$ ls -l myhosts
lrwxrwxrwx 1 root root 10 8月  2 19:10 myhosts -> /etc/hosts
```

> 首字符 `l`（link）表示这是一个符号链接，后面的 `->` 指向真实文件。

### 2.2 软链接的特点

1. **无分区限制**：可以链接不同文件系统/分区的文件
2. **可作用于文件和目录**：目录也能建软链接（硬链接不行）
3. **会产生新的 inode 和 block**（一个很短的"指向信息"），磁盘消耗基本可以忽略

### 2.3 软链接的常见行为

| 操作          | 结果                                               |
| ------------- | -------------------------------------------------- |
| `rm 软链接`   | 只删除链接本身，**原始文件不受影响**               |
| `rm 原始文件` | 链接还在，但变成"红色断链"（broken），内容丢失     |
| `cp 软链接`   | 默认复制**链接指向的内容**；`cp -d` 才保留链接本身 |
| `mv 软链接`   | 移动的是链接本身                                   |
| `rsync`       | 默认**不跟随**软链接（用 `-l` 才复制链接本身）     |
| `scp`         | 默认**跟随**软链接，复制的是目标内容               |

> **实战提醒**：备份/同步时，要确认工具是"复制链接"还是"复制内容"，避免备份出错或产生大量重复。

## 3. 硬链接

### 3.1 创建方式

```bash
ln 源文件 链接名      # 注意：不加 -s 才是硬链接
```

```bash
$ echo "hello" > f1
$ ln f1 f2            # 给 f1 建硬链接 f2
$ ls -l f1 f2
-rw-r--r-- 2 root root 6 8月  2 19:12 f1
-rw-r--r-- 2 root root 6 8月  2 19:12 f2
```

> 中间的数字 `2` 是**链接数**，表示这个 inode 被两个名字引用。

### 3.2 硬链接的特点

1. **不能跨分区**：数据块必须留在同一分区内，不同分区无法建立硬链接
2. **不能链接目录**：硬链接只针对普通文件（防止目录循环引用）
3. **不产生新的 inode 和数据块**：只是给同一个 inode 在别的目录下多加一个关联名

### 3.3 查看 inode

```bash
df -i        # 查看各分区 inode 使用情况（inode 用完也无法创建文件）
ls -il       # 显示每个文件的 inode 号
```

```bash
$ ls -il f1 f2
1000001 -rw-r--r-- 2 root root 6 8月  2 19:12 f1
1000001 -rw-r--r-- 2 root root 6 8月  2 19:12 f2
```

> 两个文件的 **inode 号相同**（1000001），说明它们指向同一份数据。

## 4. 思考题（答案）

1. **新建的文件/目录，链接数是多少？** —— 普通文件默认是 **1**；新建目录默认是 **2**（自身 + 内部的 `.`）。
2. **文件建立硬链接后，链接数变化？** —— 每加一个硬链接，链接数 +1。
3. **删除一个硬链接后，原始数据还存在吗？** —— **存在**，只要还有至少一个链接指向该 inode，数据就还在。
4. **删除原始文件后，硬链接内容还在吗？** —— **还在**，硬链接与"原始文件"地位完全平等，都是同一个 inode 的名字；只有**所有链接都删光**，数据才真正被释放。

## 5. 软链接 vs 硬链接 对比

| 对比项         | 软链接                   | 硬链接                   |
| -------------- | ------------------------ | ------------------------ |
| 命令           | `ln -s`                  | `ln`                     |
| 显示           | `lrwxrwxrwx ... -> 目标` | 普通权限位，链接数 +1    |
| inode          | 新 inode（指向目标路径） | 与源文件**同一个 inode** |
| 跨分区         | 可以                     | **不可以**               |
| 目录           | 可以                     | **不可以**               |
| 原始文件删除后 | 链接**失效**（断链）     | 数据**仍然可用**         |
| 空间占用       | 极小（存路径字符串）     | 不占（共享原数据块）     |
