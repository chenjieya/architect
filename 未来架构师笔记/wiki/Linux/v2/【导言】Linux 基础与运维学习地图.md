## 1. 概述

这篇是整个 v2 系列的入口。它回答四个问题：**为什么先学 Linux、这一版要学什么、实验环境怎么搭、命令记不住怎么办。** 读完再进入具体章节，能少走很多弯路。

## 2. 从本机到服务器

写好的前后端项目，在**自己的电脑上**跑起来只是第一步。真正要解决的是：**怎么把它放到服务器上，让别人也能访问，并且长期稳定地运行。**

一条常见的学习路线是这样的：

```text
Linux 基础 → Docker → Nginx 与并发数据服务 → K8S → CI/CD → 监控观测 → 云上部署
（你现在在这里）
```

后面每一步都在 Linux 服务器上完成。这一阶段没打好基础，后面会处处卡住。

## 3. 为什么先学 Linux

- **绝大多数服务器跑的都是 Linux。** 最终部署的目标环境基本就是它。
- **后面学的工具都长在 Linux 上。** Docker、Nginx、K8S、CI/CD、监控，打开就是命令行。
- **服务器没有图形界面。** 它不是靠鼠标点，而是靠命令行远程操作；命令行就是你跟服务器沟通的语言。

一句话：**Linux 是后面所有内容的地基。**

## 4. 这一版学什么

| 章节               | 学什么                                                                                               | 学完能做什么                         |
| ------------------ | ---------------------------------------------------------------------------------------------------- | ------------------------------------ |
| 环境               | Linux 是什么；安装一台虚拟机；远程连接                                                               | 自己装好一台 Linux，并远程登录       |
| 常用命令           | **基础**：看、找、改文件、打包<br>**核心**：进程与服务、权限、装软件<br>**网络**：排查、登录、防火墙 | 在服务器上完成日常操作、定位常见问题 |
| 系统资源与性能排查 | 服务器“慢”，是 CPU、内存、磁盘还是文件句柄的问题                                                     | 判断“慢在哪”，并找到原因             |
| Shell 脚本         | 变量、`if`、`while`、`for`、函数、重定向、`awk`                                                      | 写基础脚本，看懂别人写的脚本         |
| 网络基础           | IP、子网、网关、DNS、TCP/UDP、虚拟网络、静态 IP                                                      | 能一层一层解释“为什么连不上”         |

其中**常用命令是主干**，也是以后用得最多的内容。

## 5. 实验环境

统一环境能避免大量“我这边怎么不一样”的问题：

| 项目     | 配置                                    |
| -------- | --------------------------------------- |
| 系统     | Rocky Linux 9（最小安装，没有图形界面） |
| 虚拟机   | 4 核 CPU，8 GB 内存，40 GB 磁盘         |
| 用户     | 普通用户 `ops`（可以使用 `sudo`）       |
| 练习目录 | `~/lab`（练坏了，重新生成一遍就好）     |

- 自己电脑内存只有 8 GB 时，虚拟机先给 4 GB，具体安装步骤见 [[【环境】Linux 历史、发行版与安装]]。
- 阶段一、阶段二可以共用同一台虚拟机，后面按需要再调整。
- 苹果 M 系列芯片要用 **ARM 版**镜像。

## 6. 命令很多，不用怕

没有人能把命令和参数全背下来，也不需要。真正要做的是：

| 忘了怎么办              | 怎么做                                                        |
| ----------------------- | ------------------------------------------------------------- |
| 忘了某条命令怎么写      | 翻对应章节末尾的**命令速查**，或查 `命令 --help` / `man 命令` |
| 忘了某个参数什么意思    | `命令 --help`，或者 `man 命令`                                |
| 遇到没见过的报错        | 把报错**原样复制**去搜索，或者问 AI                           |
| 想让 AI 帮你写命令/脚本 | 可以问，但**要看得懂它给的命令**，再执行                      |

需要掌握的是三件事，而不是“记住”：

1. **知道有这个命令**：遇到问题，脑子里知道该用哪一类命令；
2. **看得懂输出**：执行完能判断结果正常还是有问题；
3. **知道危险在哪**：哪些命令会删东西、改配置、影响别人。

> 真正要练的是排查思路：**先看状态，再看日志，再看环境。** 命令只是工具。

## 7. 实验习惯

- **一定要自己动手敲。** 只看不敲，一周后就忘了。
- **动手之前先“拍快照”。** 虚拟机快照相当于游戏存档；做危险操作之前拍一个，改坏了可以回到原来的样子。
- **出错不可怕。** 练习用的是一台随时可以重装的虚拟机，大胆试；看报错、查日志本身就是学习。
- **危险操作只在虚拟机里做**：`rm`、改系统配置、关防火墙……真正的生产服务器上，先想清楚：**会改什么？能回滚吗？影响多大？**
- **配置改动先备份**：改配置文件前先 `cp` 一份，改完用 `diff` 对比，不对就回滚。具体流程见 [[【命令】Linux 基础核心与网络命令]]。

## 8. 学完后的自查清单

- [ ] 自己装好一台 Rocky Linux 虚拟机，并用 `ssh` 远程登录
- [ ] 在命令行里查看文件和日志、搜索内容、修改配置，并且知道先备份
- [ ] 管理服务（`systemctl`），查看服务日志（`journalctl`）
- [ ] 看懂文件权限，遇到 `Permission denied` 知道怎么查
- [ ] 用 `dnf` 安装软件
- [ ] 服务访问不了时，能按“服务 → 端口 → 防火墙”逐层排查
- [ ] 服务器变慢时，能判断是 CPU、内存、磁盘还是句柄的问题
- [ ] 写简单的 Shell 脚本，看懂别人的脚本
- [ ] 能说清一次网页访问经过 IP、端口、网关、DNS、TCP 的哪些环节
