## 1. 概述

这一篇回答一个核心问题：**从浏览器里敲下网址，到页面出来，中间发生了什么；出问题时又该在哪一层排查。** 主线是“四站”：域名解析 → 建立连接 → 发请求 → 服务处理。后面每一章分别拆开其中一段。

## 2. 一次访问的四个站

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663569_1.2-four-stops.png)

_一次访问经过的四个站_

每一站各管一件事，出了问题就能一站一站排除。

> 记住这句话，它是整套内容的主线：
>
> **网络能到达服务器，不代表网页一定能打开。** 服务器上还得有程序在运行，监听正确的地址和端口，并且允许请求进来。

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663570_1.1-local-ok-remote-fail.png)

_本机能访问、别的机器访问不了：问题常在监听地址或防火墙_

## 3. 四个基本词

先看两个和地址有关的：

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663571_1.3-ip-and-port.png)

_IP 找主机，端口找服务_

再看两个和“角色”有关的：

| 名词   | 意思                                             |
| ------ | ------------------------------------------------ |
| 客户端 | 主动发起请求的一方，比如浏览器、SSH 客户端       |
| 服务器 | 提供服务的一方，一台服务器上可以同时跑好几个程序 |

> **把 IP 想成小区地址，端口就是门牌号。** 只知道小区不行，还得知道敲哪一扇门。

## 4. 常见网络设备

数据在网络里走，会经过三类设备：

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663573_1.4-network-devices.png)

_常见网络设备与它们的位置_

| 设备   | 作用                                      |
| ------ | ----------------------------------------- |
| 网卡   | 计算机连接网络的接口，虚拟机里有虚拟网卡  |
| 交换机 | 主要在局域网内，根据 MAC 地址转发以太网帧 |
| 路由器 | 连接不同的 IP 网络，根据路由表转发数据包  |

## 5. 网络协议分层

协议就是通信双方共同遵守的规则。一份数据发出去，会被一层一层“包起来”：

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663575_1.5-protocol-layers.png)

_协议分层，一层包一层_

先记住四个，其他用到再学：

| 协议    | 主要负责什么                        |
| ------- | ----------------------------------- |
| IP      | 地址，以及在不同网络之间转发        |
| TCP/UDP | 应用程序之间的数据传输              |
| DNS     | 域名解析                            |
| HTTP    | 浏览器和 Web 服务之间交换请求和响应 |

## 6. IP 地址

IPv4 地址由 **32 个二进制位**组成。32 位太长，所以每 8 位分一组，每组写成一个十进制数，中间用点隔开：

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663577_2.2-ip-32-bits.png)

_32 位二进制拆成四组十进制_

8 位最多表示 256 个值，所以每一组范围是 `0～255`。

### 6.1 私有地址

私有地址不能直接在互联网上使用，但可以在不同的内网里重复使用：

| 地址范围                       | 前缀写法         | 常见场景                  |
| ------------------------------ | ---------------- | ------------------------- |
| 10.0.0.0 ～ 10.255.255.255     | `10.0.0.0/8`     | 大型企业内网、云上网络    |
| 172.16.0.0 ～ 172.31.255.255   | `172.16.0.0/12`  | Docker 默认网段所在范围   |
| 192.168.0.0 ～ 192.168.255.255 | `192.168.0.0/16` | 家庭网络、VMware 虚拟网络 |

### 6.2 特殊地址

| 地址          | 含义                                                 |
| ------------- | ---------------------------------------------------- |
| `127.0.0.1`   | 回环地址，只代表本机自己                             |
| `0.0.0.0`     | 服务端监听时表示本机所有 IPv4 地址，**不是**访问目标 |
| `169.254.x.x` | 链路本地地址，Windows 上 DHCP 获取失败时常见         |

> 这里以 IPv4 为主。IPv6 地址更长、写法不同，但思路一致，用到再学。

## 7. 子网掩码

一个 IP 地址包含两部分：

- **网络部分**：我在哪个网络里，可以理解为“小区”；
- **主机部分**：我是这个网络里的哪一台，可以理解为“小区里的某一户”。

从第几位开始算主机部分？这就是**子网掩码**的作用。

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663578_2.3-prefix-split.png)

_子网掩码把 IP 切成网络部分和主机部分_

```text
IP 地址：     192.168.10.20
子网掩码：    255.255.255.0
简写（CIDR）：192.168.10.20/24
所属子网：    192.168.10.0/24
```

`/24` 表示**前 24 位是网络部分**，剩下 `32 - 24 = 8` 位是主机部分。

```text
11000000.10101000.00001010 .00010100    ← 192.168.10.20
|------ 网络部分（24 位）---| |主机部分|
11111111.11111111.11111111 .00000000    ← 255.255.255.0 （/24）
```

掩码里的 `1` 对应网络部分，`0` 对应主机部分。把 IP 和掩码对齐，网络部分保留、主机部分清零，就得到**网络地址** `192.168.10.0`。

### 7.1 常见前缀速查

| 前缀  | 子网掩码        | 地址总数 | 可用主机数 |
| ----- | --------------- | -------- | ---------- |
| `/16` | 255.255.0.0     | 65536    | 65534      |
| `/24` | 255.255.255.0   | 256      | 254        |
| `/25` | 255.255.255.128 | 128      | 126        |
| `/26` | 255.255.255.192 | 64       | 62         |
| `/27` | 255.255.255.224 | 32       | 30         |
| `/28` | 255.255.255.240 | 16       | 14         |
| `/29` | 255.255.255.248 | 8        | 6          |
| `/30` | 255.255.255.252 | 4        | 2          |

> **前缀越大，网络越小。** 每加 1 位，地址数减半。
>
> 可用主机数比地址总数少 2：每个子网的第一个地址是**网络地址**，最后一个是**广播地址**，都不分配给普通主机。

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663579_2.5-block-26.png)

_以 /26 为例：64 个地址被切成 4 段，每段的首尾不能用_

## 8. 子网判断

方法只有一条：

> **各自用自己的掩码，算出自己所在的网络地址。网络地址相同，就是同一个子网。**

**例 1：都是 /24**

```text
A：192.168.10.10/24   → 网络地址 192.168.10.0/24
B：192.168.10.200/24  → 网络地址 192.168.10.0/24
```

网络地址相同，属于同一子网。

**例 2：只把掩码改成 /25**

```text
A：192.168.10.10/25   → 网络地址 192.168.10.0/25
B：192.168.10.200/25  → 网络地址 192.168.10.128/25
```

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663580_2.4-subnet-judge.png)

_同样的 IP，掩码一变，子网就变_

`/25` 把一个 256 的地址段切成两半：`0～127` 和 `128～255`。A 的最后一段是 `10`，落在前一半；B 是 `200`，落在后一半。**它们不在同一个子网。**

A 判断 B 不在自己的网络里，就不会直接去找 B，而是把数据交给**网关**；如果没配网关，系统会报 `Network is unreachable`。

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663581_2.1-same-prefix-different-subnet.png)

_前三段相同不代表同一子网，必须看掩码_

> **不能只看前三段数字是否相同。** 要看掩码、算网络地址。
>
> 同一子网只说明“配置上属于同一个网络”。能不能真正通信，还要看链路、虚拟网络、防火墙。

## 9. MAC 地址与 ARP

每块网卡出厂时都有一个 **MAC 地址**，长度 48 位，写成 6 组十六进制数：

```text
00:0c:29:11:22:33
```

虚拟机里的虚拟网卡也有 MAC 地址，由虚拟化软件生成。查看：

```bash
ip -br link
```

```text
lo      UNKNOWN   00:00:00:00:00:00 <LOOPBACK,UP,LOWER_UP>
ens160  UP        00:0c:29:11:22:33 <BROADCAST,MULTICAST,UP,LOWER_UP>
```

IP 和 MAC 各管一段：

|              | IP 地址                  | MAC 地址                             |
| ------------ | ------------------------ | ------------------------------------ |
| 作用         | 决定数据最终去哪里       | 决定数据在**当前这一段链路**上交给谁 |
| 谁来分配     | 管理员配置，或 DHCP 分配 | 网卡自带                             |
| 管辖范围     | 整个网络，可以跨网段     | 只在同一个局域网内有效               |
| 经过路由器时 | 不变                     | 重新封装，会变                       |

> “信封套信封”里最外层的以太网帧，用的就是 MAC 地址。交换机转发看的是 MAC。

### 9.1 ARP：用 IP 问出 MAC

要给同一子网里的 `192.168.10.2` 发数据，IP 有了，但以太网帧要填**对方的 MAC**，你不知道。办法是问，这就是 **ARP**（地址解析协议）：

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663581_3.3-arp.png)

_ARP：先广播提问，再单播回答_

1. **广播提问**：“谁是 `192.168.10.2`？请告诉 `192.168.10.20`。”发给整个局域网；
2. **单播回答**：只有 `192.168.10.2` 回应：“我是，我的 MAC 是 `00:50:56:aa:bb:cc`。”
3. **记进缓存**：结果暂时记在 **ARP 缓存**，下次直接用。

> 广播只能在同一个局域网传播，**过不了路由器**，所以 ARP 只用在同一子网内部。

查看 ARP 缓存：

```bash
ip neigh
```

```text
192.168.10.2 dev ens160 lladdr 00:50:56:aa:bb:cc REACHABLE
```

| 状态                    | 意思                                               |
| ----------------------- | -------------------------------------------------- |
| `REACHABLE`             | 刚刚确认过，可以直接用                             |
| `STALE`                 | 有记录，但一阵子没确认，下次用到时会重新确认       |
| `FAILED` / `INCOMPLETE` | 问了没人回答，说明对方不在线、不在同一网络或被隔离 |

## 10. 网关与路由表

目标**不在同一个子网**时，主机不会去 ARP 它，因为广播到不了对方。主机会把数据**交给网关**。

> **网关**就是本子网里负责把数据转发到其他网络的那台设备的 IP，通常是一台路由器。

关键：数据交给网关时，

- **目标 IP** 仍然是最终要访问的服务器；
- **目标 MAC** 换成了网关的 MAC。

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663582_3.4-ip-same-mac-changes.png)

_一路上 IP 不变，MAC 每一段链路换一次_

路由器收到后，拆掉旧的以太网帧，看目标 IP，查自己的路由表，决定下一站，再套上新的以太网帧送出去。

### 10.1 路由表

主机的“下一站交给谁”，写在**路由表**里：

```bash
ip route
```

```text
default via 192.168.10.2 dev ens160 proto dhcp metric 100
192.168.10.0/24 dev ens160 proto kernel scope link src 192.168.10.20 metric 100
```

| 这一行                                | 意思                                                                   |
| ------------------------------------- | ---------------------------------------------------------------------- |
| `192.168.10.0/24 dev ens160 ...`      | 目标在这个网段里，直接从 `ens160` 送出去；由系统根据 IP 和前缀自动生成 |
| `default via 192.168.10.2 dev ens160` | **默认路由**：其他所有目标都交给 `192.168.10.2`                        |

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663583_3.5-route-match.png)

_路由匹配：先看更具体的网段，最后才走默认路由_

## 11. DNS 与域名解析

平时在浏览器、`ping`、`curl` 里用的是**域名**，网络上真正通信用的是 **IP**。把名字换成 IP 的系统就是 **DNS**（Domain Name System，域名系统）。

### 11.1 域名的结构

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663592_4.2-domain-structure.png)

_域名从右往左读，范围越来越小_

| 部分          | 例子               | 说明                                          |
| ------------- | ------------------ | --------------------------------------------- |
| 根            | 最后那个 `.`       | 整个 DNS 的最顶层，日常书写通常省略           |
| 顶级域        | `com`、`cn`、`org` | 最大的分类                                    |
| 二级域名      | `example`          | 公司或个人注册的名字                          |
| 子域 / 主机名 | `www`              | 域名所有者自己划分，例如 `www`、`mail`、`api` |

完整写法 `www.example.com.`（末尾带点）叫 **FQDN**（完全限定域名）。平时末尾的点可以省略。

### 11.2 解析过程

虚拟机自己并不知道所有域名的 IP，它是去**问**的：

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663595_4.3-resolve-flow.png)

_一次域名解析的过程_

1. 虚拟机先问**本地 DNS 服务器**：`example.com` 的 IP 是多少？这台服务器的地址写在 `/etc/resolv.conf`。
2. 本地 DNS 服务器不一定知道，它替你去**一级一级地问**：先问根服务器，根说去问 `.com`；再问 `.com` 服务器，它说去问 `example.com` 的权威服务器；最后拿到答案。
3. 本地 DNS 服务器把答案返回，并**缓存**。缓存时间由记录里的 **TTL**（秒）决定。

> 你的机器只需要知道“本地 DNS 服务器在哪”，剩下的一级一级问是它的事。**DNS 服务器地址配错，整个解析就瘫了。**

TTL 的影响：解析记录改了，但各处缓存还没到期，有人看到新 IP，有人还看到旧 IP。这就是“改了 DNS 但还没生效”的原因之一。

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663596_4.1-ip-ok-name-fail.png)

_能 ping 通 IP、却打不开域名：问题在 DNS_

### 11.3 本机自查

去问 DNS 服务器之前，系统会先看本机有没有答案：

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663596_4.4-lookup-order.png)

_系统解析名字的顺序，以及两类工具的覆盖范围_

| 文件                 | 作用                                                                 |
| -------------------- | -------------------------------------------------------------------- |
| `/etc/hosts`         | 本机的静态“通讯录”，格式 `IP 主机名`，优先于 DNS                     |
| `/etc/resolv.conf`   | 告诉系统去问哪台 DNS 服务器，也就是 `nameserver`                     |
| `/etc/nsswitch.conf` | 规定查找顺序；`hosts:` 那一行通常写着先查 `files`（hosts）再查 `dns` |

```bash
cat /etc/hosts
cat /etc/resolv.conf
grep '^hosts' /etc/nsswitch.conf
```

```text
# /etc/hosts 示例
127.0.0.1   localhost localhost.localdomain
::1         localhost localhost.localdomain

# /etc/resolv.conf 示例
search localdomain
nameserver 192.168.10.2

# /etc/nsswitch.conf 示例
hosts:      files dns myhostname
```

### 11.4 DNS 记录类型

既然 hosts 文件也能做域名和 IP 的映射，为什么 DNS 还要设计 A、AAAA、CNAME 等类型？

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663598_image-20261110105745986.png)

_hosts 只有静态映射，DNS 记录类型承担更多用途_

`/etc/hosts` 只做静态映射：

```text
127.0.0.1       localhost
192.168.1.100   www.test.com
192.168.1.101   www.demo.com
```

这里没有记录类型，因为通过地址格式就能判断是 IPv4 还是 IPv6。

但 DNS 不只是“域名换 IP”。一个域名可能同时需要：网站 IP、邮件服务器、子域名别名、所有权验证、指定权威 DNS 服务器。于是引入记录类型：

```text
example.com     A       192.168.1.100          # IPv4 地址
example.com     AAAA    2001:db8::1            # IPv6 地址
example.com     MX      mail.example.com       # 邮件服务器
example.com     TXT     "verification=abc123"  # 文本验证
www.example.com CNAME   example.com            # 别名
example.com     NS      ns1.example.com        # 权威 DNS 服务器
```

### 11.5 dig

`ping` 只告诉你通不通，`dig` 才能看清解析细节。没有命令先安装：

```bash
sudo dnf install -y bind-utils
dig example.com
```

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663600_4.6-dig-output.png)

_`dig` 输出里的四个关键位置_

`status` 是最先看的一项：

| 状态       | 意思                                                           |
| ---------- | -------------------------------------------------------------- |
| `NOERROR`  | 解析成功；如果 ANSWER 为空，说明名字存在，但没有你查的这种记录 |
| `NXDOMAIN` | 域名不存在，多半拼错、没注册或没配置                           |
| `SERVFAIL` | DNS 服务器自己解析失败，问题通常在服务器那一侧                 |

如果压根没有返回、提示超时，说明**连 DNS 服务器都没联系上**，要回头查网络和防火墙。DNS 默认用 UDP 53，数据较大时改用 TCP 53，防火墙两个都要放行。

## 12. TCP 与 UDP

### 12.1 端口

IP 只能找到是哪台机器。一台机器同时跑 SSH、Web、数据库，要靠**端口**区分。端口是 **16 位整数**，范围 `0～65535`：

| 范围           | 说明                                                       |
| -------------- | ---------------------------------------------------------- |
| `0～1023`      | 知名端口，留给常见服务；Linux 上监听这个范围需要 root 权限 |
| `1024～49151`  | 注册端口，各类软件常用，比如 MySQL 的 `3306`               |
| `32768～60999` | Linux 默认的**临时端口**范围，客户端发起连接时从这里随机挑 |

| 端口         | 服务                |
| ------------ | ------------------- |
| `22`         | SSH                 |
| `53`         | DNS                 |
| `80` / `443` | HTTP / HTTPS        |
| `3306`       | MySQL               |
| `5432`       | PostgreSQL          |
| `6379`       | Redis               |
| `8080`       | 常见的备用 Web 端口 |

一条连接由**四个值**确定：

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663601_5.2-connection-tuple.png)

_源 IP、源端口、目标 IP、目标端口_

客户端的源端口是系统随机分配的临时端口，服务器的目标端口是服务监听的端口。因为每条连接的源端口不同，**同一个服务端口可以同时接受成千上万条连接**。

```bash
cat /proc/sys/net/ipv4/ip_local_port_range
```

### 12.2 TCP 与 UDP 的区别

端口属于传输层，最主要的两个协议是 **TCP** 和 **UDP**：

|                | TCP                            | UDP                            |
| -------------- | ------------------------------ | ------------------------------ |
| 是否先建立连接 | 是，要先握手                   | 否，直接发                     |
| 数据是否可靠   | 可靠，丢了重传，保证按顺序到达 | 不保证，丢了就丢了             |
| 速度和开销     | 相对慢，开销大                 | 快，开销小                     |
| 典型用途       | HTTP、SSH、MySQL               | DNS 查询、音视频、部分实时游戏 |

> DNS 默认用 **UDP 53**，数据较大时才改用 TCP 53。端口号相同，TCP 和 UDP 是两套互不干扰的端口。

### 12.3 三次握手

TCP 传数据前，双方要先“打个招呼”，确认彼此都在、都准备好了，这叫**三次握手**：

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663601_5.4-three-way-handshake.png)

_三次握手，以及建立失败时的两种结局_

1. **SYN**：客户端说，我想连你；
2. **SYN-ACK**：服务器说，好的，我也准备好了；
3. **ACK**：客户端说，收到，开始通信吧。

握手完成，连接进入 `ESTABLISHED`，才开始传 HTTP 请求。

失败有两种典型结局，**表现完全不同**：

| 现象                                    | 发生了什么                                                                |
| --------------------------------------- | ------------------------------------------------------------------------- |
| **立刻**报 `Connection refused`         | SYN 到达服务器，但那个地址和端口上**没有程序监听**，服务器回了拒绝（RST） |
| **卡住很久**后报 `Connection timed out` | SYN 发出去**石沉大海**，没有任何回应，常见于防火墙直接丢弃                |

> 立刻拒绝，说明对方在线，只是那扇门没开。
>
> 一直没动静，说明包半路被拦了，或者对方根本不在线。

### 12.4 监听地址

服务启动后，会在某个**地址和端口**上等待连接，这叫**监听**（`LISTEN`）。关键是：程序要指定**绑定在哪个地址**。

| 监听写法                | 含义                                 |
| ----------------------- | ------------------------------------ |
| `127.0.0.1:8080`        | 只接受本机自己发来的连接             |
| `192.168.10.20:8080`    | 只接受发往这个 IP 的连接             |
| `0.0.0.0:8080`          | 接受发往本机**所有 IPv4 地址**的连接 |
| `*:8080` 或 `[::]:8080` | 所有地址，包括 IPv6                  |

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663602_5.5-bind-address-matrix.png)

_监听在哪个地址，决定了谁能访问_

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663603_5.1-local-ok-remote-refused.png)

_本机能访问、远程被拒绝：服务只监听了 127.0.0.1_

> 解决办法：让服务监听 `0.0.0.0`，或者监听正确的网卡 IP。
>
> `0.0.0.0` 是服务**监听**时的写法，表示“所有地址”。它不是让客户端访问的目标地址；客户端要访问的是机器真实的 IP。

### 12.5 ss 查看监听与连接

```bash
sudo ss -tlnp
```

| 参数 | 含义                                   |
| ---- | -------------------------------------- |
| `-t` | 只看 TCP（UDP 用 `-u`）                |
| `-l` | 只看**正在监听**的                     |
| `-n` | 不把端口和 IP 翻译成名字，直接显示数字 |
| `-p` | 显示进程，需要 `sudo` 才能看全         |

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663603_5.6-ss-output.png)

_`ss -tlnp` 输出里的三个关键位置_

**找出谁占用了端口：**

```bash
sudo ss -tlnp | grep ':8080'
```

**看已建立的连接：**

```bash
ss -tn
```

| 状态         | 意思                                                         |
| ------------ | ------------------------------------------------------------ |
| `LISTEN`     | 在监听，等待别人来连                                         |
| `ESTAB`      | 连接已建立，正在通信                                         |
| `TIME-WAIT`  | 连接刚关闭，正在收尾；大量出现通常正常                       |
| `CLOSE-WAIT` | 对方已关闭，本机程序还没关；大量堆积往往是程序没及时关闭连接 |
| `SYN-SENT`   | 本机发了 SYN，还在等回应；大量出现说明对方没响应             |

## 13. 虚拟网络与三种模式

### 13.1 VMware 造出的网络设备

安装 VMware 时，它会在宿主机上“造”出一套网络设备：

| 虚拟设备           | 作用                                                                           |
| ------------------ | ------------------------------------------------------------------------------ |
| 虚拟网卡           | 虚拟机里的网卡（如 `ens160`），对虚拟机来说和真网卡没区别                      |
| 虚拟交换机         | 把虚拟机连在一起，编号 `VMnet0`、`VMnet1`、`VMnet8`                            |
| 宿主机上的虚拟网卡 | Windows 网络连接里的 `VMware Network Adapter VMnet1/8`，让宿主机接入虚拟交换机 |
| 虚拟 NAT 设备      | 让虚拟机借宿主机的网络上网                                                     |
| 虚拟 DHCP 服务     | 自动给虚拟机分配 IP                                                            |

| 虚拟交换机 | 网络模式   |
| ---------- | ---------- |
| `VMnet0`   | 桥接模式   |
| `VMnet1`   | 仅主机模式 |
| `VMnet8`   | NAT 模式   |

### 13.2 三种模式

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663604_6.3-three-modes.png)

_三种网络模式，连接方式不同_

- **桥接**：虚拟机像局域网里多出来的一台真实机器，和宿主机平等；
- **NAT**：虚拟机躲在宿主机后面，借宿主机的网络上网；
- **仅主机**：虚拟机只能和宿主机通信，不能上网。

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663605_6.4-mode-matrix.png)

_三种模式的访问能力对比_

| 模式   | 适合什么时候用                                 | 需要注意                                                          |
| ------ | ---------------------------------------------- | ----------------------------------------------------------------- |
| 桥接   | 想让虚拟机像真机一样，被局域网其他机器直接访问 | 要占用局域网 IP；有的公司、学校网络不允许；部分无线网卡桥接不稳定 |
| NAT    | 个人学习，最省心                               | 局域网里的其他机器访问不了，需要端口转发                          |
| 仅主机 | 隔离实验，不想让虚拟机上网                     | 上不了外网                                                        |

### 13.3 NAT 怎么工作

虚拟机的 IP 是**私有地址**，不能直接在互联网使用。它靠 **NAT**（网络地址转换）上网：

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663605_6.5-nat-translation.png)

_NAT：出去时改写源地址，回来时再改回去_

1. 虚拟机发出的包，源地址是私有 IP；
2. NAT 设备把**源地址改成宿主机的 IP**，换一个端口，同时**记下对应关系**；
3. 服务器回应发给 NAT 设备，NAT 按记录把目标改回虚拟机，再送回去。

这样，外面的服务器只看到宿主机的 IP，看不到虚拟机。

## 14. 动态 IP 与静态 IP

### 14.1 动态 IP 与 DHCP

大多数时候，虚拟机 IP 是**自动获得**的，这就是**动态 IP**，分配它的服务叫 **DHCP**。机器刚启动还没有 IP，是这样“要”到的：

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663606_7.2-dhcp-four-steps.png)

_DHCP 的四步_

1. **Discover**：虚拟机还没有 IP，只能**广播**喊：有 DHCP 服务器吗？我需要一个 IP；
2. **Offer**：DHCP 服务器回应：我可以给你 `192.168.10.128`；
3. **Request**：虚拟机再广播：好，我就要这个；
4. **Ack**：服务器确认，这个 IP 借给你了。

注意，借来的 IP 有**租期**，到期前要续租。DHCP 给的不只是 IP，而是**一整套**：IP、子网掩码、网关、DNS、租期。

```bash
ip -br addr
nmcli connection show "ens160" | grep ipv4.method
```

`ipv4.method: auto` 就是动态获取。连接名以 `nmcli connection show` 的结果为准，通常和网卡名一样。

|          | 动态 IP（DHCP）        | 静态 IP                        |
| -------- | ---------------------- | ------------------------------ |
| 谁决定   | DHCP 服务器分配        | 管理员手动指定                 |
| 重启之后 | 可能会变               | 不变                           |
| 配置工作 | 不用配                 | 要自己配齐                     |
| 适合     | 个人电脑、临时用的机器 | 服务器，别人要用固定地址访问它 |
| 风险     | 地址变了，别人连不上   | 配错了，或者和别人冲突         |

### 14.2 静态 IP 的三条规则

| 规则                   | 原因                                   |
| ---------------------- | -------------------------------------- |
| 必须在**同一个子网**里 | 和网关不在同一个子网，就出不了网       |
| 不能和别的机器**冲突** | 两台机器用同一个 IP，会时通时不通      |
| 要**避开 DHCP 池**     | 否则 DHCP 可能把同一个 IP 分给别的机器 |

结合 VMware NAT 网段规划：

- `.2` 是网关，不能占用；
- `.128 ～ .254` 是 DHCP 池，要避开；
- `.3 ～ .127` 空闲，可以选。

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663606_6.6-address-plan.png)

_NAT 网段的地址规划：网关、DHCP 池、可用静态地址_

这里用 `192.168.10.50` 作为例子，你的网段以自己的为准。

### 14.3 静态 IP 要配三样

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663607_7.4-three-pieces.png)

_静态 IP 要配齐三样，缺一样就是一种故障_

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663607_3.1-gateway-ok-internet-fail.png)

_能 ping 通网关、却上不了公网：网关之后的配置或 NAT 还有问题_

DNS 的作用是把域名换成 IP。常用公共 DNS 有 `223.5.5.5`、`8.8.8.8`；在 VMware 的 NAT 网络里，网关 `.2` 通常也能充当 DNS。动态 IP 时这三样都是 DHCP 配好的，改成静态就要**自己配齐**。

> 配好后用 `ping` 逐步检查：网关、公网 IP、域名，哪一步不通就缺了哪一样。

### 14.4 在 Rocky Linux 上配置

Rocky Linux 用 **NetworkManager** 管理网络，推荐用 `nmcli`：

```bash
nmcli connection show                     # 连接名
ip -br addr                               # 当前 IP
ip route show default                     # 网关
cat /etc/resolv.conf                      # DNS
```

改成静态 IP：

```bash
sudo nmcli connection modify "ens160" \
  ipv4.method manual \
  ipv4.addresses 192.168.10.50/24 \
  ipv4.gateway 192.168.10.2 \
  ipv4.dns "223.5.5.5 8.8.8.8"

sudo nmcli connection up "ens160"
```

| 参数                 | 含义                        |
| -------------------- | --------------------------- |
| `ipv4.method manual` | 改成手动配置，不再用 DHCP   |
| `ipv4.addresses`     | IP 和前缀，对应前面的 `/24` |
| `ipv4.gateway`       | 网关                        |
| `ipv4.dns`           | DNS 服务器                  |

改回动态 IP：

```bash
sudo nmcli connection modify "ens160" \
  ipv4.method auto \
  ipv4.addresses "" ipv4.gateway "" ipv4.dns ""

sudo nmcli connection up "ens160"
```

![](https://picgo-1300696809.cos.ap-beijing.myqcloud.com/obsidian/1794631663608_7.1-ip-changed-ssh-fail.png)

_改了 IP 之后原 SSH 连接会断，必须用新 IP 重连_

> **请在 VMware 的虚拟机控制台里操作，不要用 SSH。** 改了 IP 之后原来的 SSH 连接一定会断。

配置保存在文件里，不同版本位置不同：

| 系统版本      | 位置                                                         |
| ------------- | ------------------------------------------------------------ |
| Rocky Linux 8 | `/etc/sysconfig/network-scripts/ifcfg-ens160`                |
| Rocky Linux 9 | `/etc/NetworkManager/system-connections/ens160.nmconnection` |

了解位置即可，不建议手改，用 `nmcli` 更稳；习惯文本界面也可以用 `nmtui`。

### 14.5 配置并验证

**第一步：记下现状**

```bash
nmcli connection show
ip -br addr
ip route show default
cat /etc/resolv.conf
```

**第二步：配置静态 IP**（用上面的 `nmcli connection modify`）

**第三步：验证**

```bash
ip -br addr                    # IP 是不是你设置的
ip route show default          # 网关是不是对的
cat /etc/resolv.conf           # DNS 是不是对的

ping -c 2 192.168.10.2         # 网关
ping -c 2 223.5.5.5            # 公网 IP
ping -c 2 example.com          # 域名
```

三个 `ping` 都通，说明三样都配对了。重启虚拟机后再看 `ip -br addr`，IP 不会变。

**选做：故意缺一样，看现象**

```bash
# 清掉网关
sudo nmcli connection modify "ens160" ipv4.gateway ""
sudo nmcli connection up "ens160"
ping -c 2 192.168.10.2         # 通
ping -c 2 223.5.5.5            # Network is unreachable

# 补回网关，清掉 DNS
sudo nmcli connection modify "ens160" ipv4.gateway 192.168.10.2 ipv4.dns ""
sudo nmcli connection up "ens160"
ping -c 2 223.5.5.5            # 通
ping -c 2 example.com          # 域名解析失败
```

对照“三样”图，正好一一对应。最后记得把 DNS 补回去，再恢复动态 IP。

**动手清单：**

- [ ] 确认虚拟机当前是动态 IP 还是静态 IP
- [ ] 在 `.3 ～ .127` 范围内选一个 IP，配置成静态 IP
- [ ] 用三个 `ping` 验证网关、公网、域名
- [ ] 重启虚拟机，确认 IP 没有变
- [ ] （选做）故意去掉网关、DNS，对比现象
