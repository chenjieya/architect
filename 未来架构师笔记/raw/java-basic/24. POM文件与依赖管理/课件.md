# POM文件与依赖管理

## 课程目标

- 深入理解 `pom.xml` 文件的各个核心元素
- 掌握 Maven 依赖的声明方式、范围和作用域
- 理解传递性依赖机制及其带来的版本冲突问题
- 掌握版本管理的最佳实践（属性管理、SNAPSHOT 版本）
- 学会使用 `dependency:tree` 分析依赖关系



## POM 文件结构详解

`pom.xml`（Project Object Model）是 Maven 项目的核心配置文件，它定义了项目的基本信息、构建配置、依赖关系等。以下是一个完整的 POM 文件结构示例：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
         http://maven.apache.org/xsd/maven-4.0.0.xsd">
  
    <modelVersion>4.0.0</modelVersion>

    <!-- ========== 项目坐标 ========== -->
    <groupId>com.example</groupId>
    <artifactId>my-app</artifactId>
    <version>1.0-SNAPSHOT</version>
  
    <packaging>jar</packaging>

    <!-- ========== 项目元信息 ========== -->
    <name>My Application</name>
    <description>A simple Maven project</description>
    <url>https://example.com</url>

    <!-- ========== 父 POM（继承） ========== -->
    <parent>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-parent</artifactId>
        <version>2.7.0</version>
        <relativePath/> <!-- 从本地/远程仓库查找父 POM -->
    </parent>

    <!-- ========== 属性定义 ========== -->
    <properties>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
        <maven.compiler.source>11</maven.compiler.source>
        <maven.compiler.target>11</maven.compiler.target>
      
        <jackson.version>2.13.0</jackson.version>
    </properties>

    <!-- ========== 依赖管理 ========== -->
    <dependencyManagement>
        <dependencies>
            <!-- 统一管理子模块依赖版本（不实际引入） -->
        </dependencies>
    </dependencyManagement>

    <!-- ========== 实际依赖 ========== -->
    <dependencies>
        <dependency>
            <groupId>org.apache.httpcomponents</groupId>
            <artifactId>httpclient</artifactId>
            <version>4.5.13</version>
        </dependency>
        <dependency>
            <groupId>com.fasterxml.jackson.core</groupId>
            <artifactId>jackson-databind</artifactId>
            <version>${jackson.version}</version>
        </dependency>
        <dependency>
            <groupId>junit</groupId>
            <artifactId>junit</artifactId>
            <version>4.13.2</version>
            <scope>test</scope>
        </dependency>
    </dependencies>

    <!-- ========== 构建配置 ========== -->
    <build>
        <plugins>
            <!-- 插件配置 -->
        </plugins>
    </build>
</project>
```



### 项目坐标（groupId, artifactId, version）

项目坐标是 Maven 仓库中唯一标识一个构件的三元组，类似于数据库中的复合主键。

| 元素         | 说明                           | 示例                        |
| ------------ | ------------------------------ | --------------------------- |
| `groupId`    | 组织或公司的域名反写，用于分组 | `com.example`、`org.apache` |
| `artifactId` | 项目本身的唯一标识符           | `my-app`、`httpclient`      |
| `version`    | 项目的版本号                   | `1.0-SNAPSHOT`、`4.5.13`    |

### packaging 类型

`<packaging>` 定义项目的打包方式，常见值：

- `jar`：默认，打包为 Java 归档文件
- `war`：打包为 Web 应用归档文件（用于部署到 Servlet 容器）
- `pom`：仅用于父模块（不包含代码，只做依赖管理和聚合）

### parent 元素（继承）

`<parent>` 用于声明父 POM，子项目可以继承父项目的配置（如依赖版本、插件配置等），实现配置复用。

```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>2.7.0</version>
    <relativePath/> <!-- 从本地仓库查找，若省略则从远程仓库查找 -->
</parent>
```



### properties 元素（属性）

`<properties>` 用于定义可重用的变量，常用于统一版本号、指定编码等：

```xml
<properties>
    <java.version>11</java.version>
    <jackson.version>2.13.0</jackson.version>
</properties>
```

后续通过 `${...}` 引用：

```xml
<version>${jackson.version}</version>
```



## 依赖管理（Dependency Management）

### 依赖声明结构

一个完整的依赖声明由三要素组成（坐标）：

```xml
<dependency>
    <groupId>org.apache.httpcomponents</groupId>
    <artifactId>httpclient</artifactId>
    <version>4.5.13</version>
  
  
    <scope>compile</scope>   <!-- 可选，默认 compile -->
  
    <optional>false</optional>
  
    <exclusions>
        <!-- 排除传递依赖 -->
    </exclusions>
</dependency>
```



### 依赖范围（scope）

`<scope>` 控制依赖在哪些构建阶段中被包含，分为以下 5 种：

| scope             | 编译时 | 测试时 | 运行时 | 打包时 | 示例                           |
| ----------------- | ------ | ------ | ------ | ------ | ------------------------------ |
| `compile`（默认） | ✅      | ✅      | ✅      | ✅      | Apache HttpClient              |
| `provided`        | ✅      | ✅      | ❌      | ❌      | Servlet API（容器已提供）      |
| `runtime`         | ❌      | ✅      | ✅      | ✅      | JDBC 驱动                      |
| `test`            | ❌      | ✅      | ❌      | ❌      | JUnit                          |
| `system`          | ✅      | ✅      | ❌      | ❌      | 本地 JAR（不推荐，需指定路径） |

**典型场景：**

- **test**：仅测试阶段使用，不会被打入最终 JAR。
- **provided**：编译和测试时需要，但运行时由容器提供（如 Tomcat 的 `servlet-api`）。
- **runtime**：编译时不需要，运行时需要（如数据库驱动）。

### 传递性依赖（Transitive Dependency）

Maven 会自动解析并引入依赖所依赖的其他 JAR 包（传递依赖），无需手动添加。

**示例：** 我们在项目中声明了 `httpclient`，而 `httpclient` 本身依赖 `httpcore` 和 `commons-logging`。Maven 会自动下载并引入这两个传递依赖。

**传递依赖带来的好处：** 大大减少了人工工作量，避免遗漏依赖。

**传递依赖带来的问题：** 可能引入版本冲突（不同路径引入同一依赖的不同版本）。

### 依赖冲突与版本仲裁

当多个传递依赖路径引入了同一个依赖的不同版本时，Maven 会进行版本仲裁，规则如下：

1. **最短路径优先**：路径最短的依赖版本被选中。
2. **第一声明优先**：若路径长度相同，则先声明的依赖版本被选中。

**示例：**

- 项目 A 直接依赖了 `jackson-databind:2.12.0`
- 项目 A 又依赖了 B，而 B 依赖了 `jackson-databind:2.10.0`
- 那么 2.12.0 会被选中（因为直接依赖路径最短）。

### 查看依赖树

使用 `mvn dependency:tree` 可以查看完整的依赖树，便于排查冲突：

```
mvn dependency:tree
```

输出示例：

```
[INFO] com.example:my-app:jar:1.0-SNAPSHOT
[INFO] +- org.apache.httpcomponents:httpclient:jar:4.5.13:compile
[INFO] |  +- org.apache.httpcomponents:httpcore:jar:4.4.13:compile
[INFO] |  \- commons-logging:commons-logging:jar:1.2:compile
[INFO] +- com.fasterxml.jackson.core:jackson-databind:jar:2.13.0:compile
[INFO] |  +- jackson-core:jackson-core:jar:2.13.0:compile
[INFO] |  \- jackson-annotations:jackson-annotations:jar:2.13.0:compile
[INFO] \- junit:junit:jar:4.13.2:test
```



### 排除传递依赖

如果不想引入某个传递依赖，可以使用 `<exclusions>` 排除：

```xml
<dependency>
    <groupId>org.apache.httpcomponents</groupId>
    <artifactId>httpclient</artifactId>
    <version>4.5.13</version>
    <exclusions>
        <exclusion>
            <groupId>commons-logging</groupId>
            <artifactId>commons-logging</artifactId>
        </exclusion>
    </exclusions>
</dependency>
```



### dependencyManagement 统一管理版本

在父 POM 中使用 `<dependencyManagement>`，可以统一管理子模块的依赖版本，但不会实际引入依赖，子模块只需声明 `groupId` 和 `artifactId`，版本从父继承。

**父 POM：**

```xml
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>com.fasterxml.jackson.core</groupId>
            <artifactId>jackson-databind</artifactId>
            <version>2.13.0</version>
        </dependency>
    </dependencies>
</dependencyManagement>
```



**子模块：** 只需声明，无需指定版本：

```xml
<dependency>
    <groupId>com.fasterxml.jackson.core</groupId>
    <artifactId>jackson-databind</artifactId>
</dependency>
```



## 版本管理策略

### 使用属性管理版本

将所有依赖版本集中定义在 `<properties>` 中，便于统一升级：

```xml
<properties>
    <jackson.version>2.13.0</jackson.version>
    <httpclient.version>4.5.13</httpclient.version>
</properties>
...
<dependency>
    <groupId>com.fasterxml.jackson.core</groupId>
    <artifactId>jackson-databind</artifactId>
    <version>${jackson.version}</version>
</dependency>
```



### SNAPSHOT 版本

- **SNAPSHOT** 表示“开发中的版本”，Maven 不会缓存 SNAPSHOT 版本，每次都会去仓库检查更新。
- **RELEASE** 表示“正式发布版本”，会被缓存，除非强制更新。
- **版本号规范**：一般使用 `x.y.z-SNAPSHOT`（如 `1.0.0-SNAPSHOT`），正式版去 `-SNAPSHOT`。



## 实践示例：将上节课的手工项目转为 Maven 项目

让我们将第 1 课中的 `GithubApiClient` 手工项目转换为 Maven 项目，只需在 `pom.xml` 中添加以下依赖：

```
<dependencies>
    <!-- Apache HttpClient -->
    <dependency>
        <groupId>org.apache.httpcomponents</groupId>
        <artifactId>httpclient</artifactId>
        <version>4.5.13</version>
    </dependency>

    <!-- Jackson Databind（自动传递 jackson-core 和 annotations） -->
    <dependency>
        <groupId>com.fasterxml.jackson.core</groupId>
        <artifactId>jackson-databind</artifactId>
        <version>2.13.0</version>
    </dependency>
</dependencies>
```

执行 `mvn compile`，Maven 自动下载所有依赖（包括传递依赖），项目即可编译通过，无需手动下载任何 JAR 包。对比之前的手工过程，效率提升显著。
