# 包管理

## 课程目标

- 理解包（Package）的概念和作用
- 掌握包的声明和导入语法
- 了解 Java 模块化系统的基本概念



## 什么是包

**包（Package）** 是 Java 中用于**组织类和接口**的机制，类似于文件系统中的文件夹。包将功能相关的类分组在一起，形成一个**命名空间**，避免类名冲突，并提供访问控制层级。

```java
// 包的声明必须放在文件第一行
package com.example.demo;

public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}
```

> [!NOTE]
>
> 一个 Java 源文件只能有一个 `package` 语句，且必须放在文件的最前面（注释除外）。



------

## 包的作用

| 作用             | 说明                                                         |
| ---------------- | ------------------------------------------------------------ |
| **避免命名冲突** | 不同包中的类可以同名（如 `java.util.Date` 和 `java.sql.Date`） |
| **组织代码**     | 按功能模块划分，使项目结构清晰                               |
| **访问控制**     | 配合访问修饰符，控制类、方法、字段的可见性                   |
| **封装性**       | 将实现细节隐藏，只暴露必要的 API                             |
| **版本管理**     | 便于模块化开发和发布                                         |

### 命名冲突示例

```java
// 使用完整的类名来区分同名的不同类
java.util.Date utilDate = new java.util.Date();
java.sql.Date sqlDate = new java.sql.Date(System.currentTimeMillis());
```

## 包名命名规范

为了确保包名的**全局唯一性**，Java 社区遵循以下规范：

| 规范               | 说明                            | 示例                                    |
| ------------------ | ------------------------------- | --------------------------------------- |
| **全小写**         | 包名全部使用小写字母            | `com.example.util`                      |
| **域名倒序**       | 使用公司/组织的域名倒序作为前缀 | `com.example.project`                   |
| **有意义的名称**   | 反映模块的功能                  | `com.example.user`、`com.example.order` |
| **不以下划线开头** | 避免与 Java 关键字混淆          | `com.example`（而非 `_com.example`）    |

包结构示例：

```Java
com.example.project
    ├── controller    // 控制器层
    ├── service       // 业务逻辑层
    ├── dao           // 数据访问层
    ├── model         // 数据模型
    └── util          // 工具类
```

> [!CAUTION]
>
> - 不要使用 Java 保留关键字作为包名（如 `int`、`class`）。
> - 包名应使用 `.` 分隔，不允许使用连字符 `-` 或其他特殊字符。

## 包的声明

使用 `package` 关键字声明类所在的包。

```java
// 文件: com/example/demo/Calculator.java
package com.example.demo;

public class Calculator {
    public int add(int a, int b) {
        return a + b;
    }
}
```



### 无名包（默认包）

如果源文件中没有 `package` 语句，类就属于**无名包**（默认包）。**不推荐**使用无名包，因为无法被其他包中的类导入，且容易造成命名冲突。

```java
// 不建议：没有 package 声明
public class DefaultClass {
    // 该类位于默认包中
}
```



### 包描述文件 `package-info.java`

`package-info.java` 是 Java 中一个**特殊的元数据文件**，专门用于为**整个包**提供注释和声明。它并不是普通的 Java 类（没有 `public class` 定义），而是放在包的根目录下，充当该包的“介绍信”和“注解挂载点”。它主要有**两大核心使命**：

- **提供包级注解**：将注解（如 `@Deprecated`、`@NonNullApi`）应用到包下的所有类上，无需逐个类重复标注。
- **生成包级 Javadoc**：在生成 API 文档时，文件开头的 `/** ... */` 注释会作为该包的详细说明文档。

```java
/**
 * 提供 Demo 项目的公共 API 接口。
 * <p>
 * 此包包含所有对外暴露的服务契约，外部模块只需依赖此包即可调用。
 * 使用此包时，请确保传入的参数符合非空约束。
 * </p>
 *
 * @author 你的名字
 * @since 1.0.0
 */
// 1. 包级注解（放在 package 声明之前）
@Deprecated  // 示例：标记整个包为已弃用（若需要）
package com.example.demo.api;

// 2. 导入放在 package 声明之后
import java.lang.Deprecated;
```

 **格式规则**：

- Javadoc 注释（`/**`）必须在最顶部。
- 注解必须紧跟在 Javadoc 之后，且在 `package` 声明**之前**。
- `package` 声明必须存在且放在中间。
- `import` 语句必须放在 `package` 声明**之后**

## 包的导入

使用 `import` 语句导入其他包中的类，避免每次使用时都写完整类名。

### 导入单个类

```java
import java.util.ArrayList;
import java.util.List;

public class ImportDemo {
    public static void main(String[] args) {
        List<String> list = new ArrayList<>();  // 无需写完整类名
    }
}
```



### 按需导入（通配符 `*`）

使用 `*` 导入包中所有类，**不会**递归导入子包中的类。

```java
import java.util.*;      // 导入 java.util 包中的所有类
import java.io.*;        // 导入 java.io 包中的所有类

public class WildcardImport {
    public static void main(String[] args) {
        List<String> list = new ArrayList<>();
        File file = new File("test.txt");
    }
}
```

> [!NOTE]
>
> - 通配符导入不会影响性能，编译时会解析为实际需要的类。
> - 推荐导入具体的类，以提高代码可读性（IDE 可自动管理）。



### 静态导入（`import static`）

使用 `import static` 导入类的**静态成员**（静态字段和方法），可以直接使用静态成员名而无需类名前缀。

```java
import static java.lang.Math.PI;
import static java.lang.Math.pow;

public class StaticImportDemo {
    public static void main(String[] args) {
        // 直接使用 PI 和 pow，无需 Math.PI / Math.pow
        double area = PI * pow(5, 2);
        System.out.println(area);  // 78.53981633974483
    }
}
```



导入所有静态成员：

```java
import static java.lang.Math.*;   // 导入所有静态成员

public class StaticImportAll {
    public static void main(String[] args) {
        double result = sqrt(16) + pow(2, 3);  // 直接使用
    }
}
```

> [!CAUTION]
>
> - 静态导入**可能降低代码可读性**，读者需要判断某个静态成员来自哪个类。
> - 当多个类有同名静态成员时，容易产生混淆，应谨慎使用。

## 包与目录结构

Java 要求包名与文件目录结构**一一对应**：

```
项目根目录/
└── src/
    └── com/
        └── example/
            └── demo/
                └── Calculator.java   // package com.example.demo;
```



### 编译与运行

```
# 编译（在 src 目录下执行）
javac com/example/demo/Calculator.java

# 运行
java com.example.demo.Calculator
```

> [!CAUTION]
>
> - 编译和运行时的**当前工作目录**必须与包结构匹配。
> - 运行时要使用**完整类名**（包含包路径）。

## 包的可见性与访问控制

包的声明配合访问修饰符，共同控制类成员的可见性：

| 修饰符                | 同一类 | 同一包 | 子类 | 任何地方 |
| --------------------- | ------ | ------ | ---- | -------- |
| `private`             | ✓      |        |      |          |
| `default`（无修饰符） | ✓      | ✓      |      |          |
| `protected`           | ✓      | ✓      | ✓    |          |
| `public`              | ✓      | ✓      | ✓    | ✓        |

```java
package com.example.util;

public class AccessDemo {
    private int a = 1;           // 仅类内访问
    int b = 2;                   // 同一包内访问
    protected int c = 3;         // 同一包 + 子类访问
    public int d = 4;            // 任意地方访问
}
```

## Java 模块化系统（Java 9+）

Java 9 引入了**模块化系统**（Project Jigsaw），在包的基础上增加了模块（Module）的概念。

### 模块描述文件 `module-info.java`

```java
module com.example.demo {
    // 导出包，使其对外可见
    exports com.example.demo.api;
    
    // 依赖其他模块
    requires java.sql;
}
```

### 对比`module-info.java`和`package-info.java`

| 对比维度     | **`module-info.java`**                            | **`package-info.java`**                              |
| ------------ | ------------------------------------------------- | ---------------------------------------------------- |
| **作用层级** | **模块级**（整个 Jar 包）                         | **包级**（仅限当前包及其子包）                       |
| **核心职责** | 定义模块依赖（`requires`）、导出接口（`exports`） | 定义包文档、包级注解、包级可见性（如 `@Deprecated`） |
| **放置位置** | 源码根目录（如 `src/main/java` 下）               | 具体包的目录下（如 `com/example/demo/api` 内）       |
| **是否必须** | **必须**（模块化项目启动的必要条件）              | **可选**（按需添加，强烈建议用于核心导出包）         |

> [!NOTE]
>
> 本课程重点掌握包的使用，模块化系统作为补充了解即可。

## 注意事项

> [!CAUTION]
>
> - 包名必须与目录结构完全一致，否则编译会报错。
> - 避免使用 Java 标准库的包名（如 `java.*`、`javax.*`）。
> - 一个源文件最多只能有一个 `package` 语句。
> - `import` 语句必须放在 `package` 语句之后，类声明之前。
> - 静态导入要慎用，避免混淆代码可读性。
