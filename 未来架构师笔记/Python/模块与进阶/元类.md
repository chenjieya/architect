## 1. 概述

理解 Python 元类,绕不开一个底层事实:**Python 里"类"本身也是对象**。要把元类讲透,得先讲清两件根基:

- `type` 和 `object` 这对"鸡生蛋"是怎么共存的;
- 每个对象身上有**两条独立的链**(继承链 / 实例链),它们分别决定不同的查找行为。

把这两件根基立住,后面元类、`super()`、属性查找顺序就全是水到渠成的推论。

---

## 2. 根基:type 和 object 的关系

### 2.1 两个看似矛盾的事实

```python
type.__bases__      # (<class 'object'>,)   type 继承自 object
object.__class__    # <class 'type'>         object 是 type 创建的(是 type 的实例)
type.__class__      # <class 'type'>         type 是它自己的实例
object.__bases__    # ()                     object 到顶,没有父类
```

看起来死循环:要先有 `type` 才能造 `object`,要先有 `object` 才能让 `type` 继承它。

### 2.2 为什么不矛盾:C 层自举

`type` 和 `object` 都是 CPython 用 C 写死的**静态结构体**,启动时**早已在内存里**,不需要"创建"动作。解释器初始化时只是**回填指针**让它们互相引用:

1. 把 `type` 的父类指针指向 `object`(完成继承);
2. 把 `object` 的"类"指针指向 `type`(完成"object 是 type 的实例");
3. 把 `type` 的"类"指针指向它自己。

> **通俗类比**:`object` 和 `type` 是一对**同时出生的双胞胎**,出生后互相在对方档案上登记。登记是出生**之后**做的,所以不存在"谁先生出谁"。

---

## 3. 核心:每个对象身上的两条链

这是理解后面一切的总开关。任何对象都有两条**正交**的关系链:

| 链         | 含义              | 属性                    | 决定什么                         |
| :--------- | :---------------- | :---------------------- | :------------------------------- |
| **继承链** | 父类是谁(is-a)    | `__bases__` / `__mro__` | 在一个类里**怎么逐层往上找**属性 |
| **实例链** | 由谁创建(type-of) | `__class__` / `type()`  | **从哪个类的链开始**找           |

一句话记牢:**实例链决定"用谁的 MRO",继承链决定"MRO 怎么走"。**

```
        实例链(__class__,跳一级)        继承链(__mro__,走多级)
        "我的类是谁"                     "在这个类里逐层找"
 obj ──────────────────▶ type(obj) ──────────────▶ 父类 ─▶ ... ─▶ object
 (定位起点)               (查找入口)
```

## 4. 三个继承属性:`__base__` / `__bases__` / `__mro__`

很多人把它们混为一谈,**单继承时像,多继承立刻露馅**。

| 属性        | 含义                                             | 数量          |
| :---------- | :----------------------------------------------- | :------------ |
| `__base__`  | **主基类**(`__bases__` 里的第一个)               | 一个类        |
| `__bases__` | **直接父类**(只一层,写在括号里的)                | 元组          |
| `__mro__`   | **完整线性化查找链**(含自己,到 object,去重+排序) | 元组,通常更长 |

### 4.1 单继承:仍不相等

```python
class A: ...
class B(A): ...

B.__base__    # <class 'A'>
B.__bases__   # (<class 'A'>,)
B.__mro__     # (B, A, object)   ← 头是自己,尾是 object,多一层
```

### 4.2 多继承(菱形):彻底不同

```python
class A: ...
class B(A): ...
class C(A): ...
class D(B, C): ...

D.__bases__   # (B, C)               ← 只有直接写的两个
D.__mro__     # (D, B, C, object)    ← C3 算法拍平:A 去重并后置,只出现一次
D.__base__    # <class 'B'>          ← 取第一个
```

**关键区别**:`__bases__` 只往上看一层;`__mro__` 是经过 **C3 线性化算法**算出来的——每个祖先只出现一次,且保证"子类一定排在父类前"。真正决定方法查找顺序的是 `__mro__`,不是 `__bases__`。

> 记法:`__bases__` 是"我爸妈是谁";`__mro__` 是"出事按什么顺序挨个问长辈(不重复、定好先后)"。

## 5. 属性查找顺序(两条链如何协作)

### 5.1 实例访问:`obj.attr`(obj 不是类)

```
1. type(obj).__mro__   找 data descriptor(如 property)   ← 数据描述符最高优先
2. obj.__dict__        实例自己的属性
3. type(obj).__mro__   找类属性 / 普通方法(non-data)
4. type(obj).__getattr__
```

**只走 `type(obj).__mro__` 这条继承链,元类链碰都不碰。**

### 5.2 类访问:`Class.attr`(Class 是元类的实例)

```
1. type(Class).__mro__  找 data descriptor                ← 元类链
2. Class.__mro__         类自己的整条继承链               ← 注意:不是只查 Class.__dict__
3. type(Class).__mro__  找普通属性(non-data)             ← 元类链
4. type(Class).__getattr__
```

### 5.3 唯一的不对称:"自身"的含义

- **实例** `obj` 的"自身"= 一个 `obj.__dict__`(实例不参与继承);
- **类** `Class` 的"自身"= **整条 `Class.__mro__`**(类本身就是继承链的节点)。

### 5.4 特殊方法(dunder)只认类、绕过实例

`len(x)`、`x + y`、`with x` 这类隐式调用,**只在 `type(x).__mro__` 上找,跳过实例 `__dict__`**:

```python
class C: ...
c = C()
c.__len__ = lambda: 42
len(c)          # ❌ TypeError —— 解释器只查 type(c).__mro__,不看 c.__dict__
C.__len__ = lambda self: 42
len(c)          # ✅ 42
```

> 总规则:`X.__dunder__` 永远去 `type(X).__mro__` 找。想拦截"对实例的操作"写进普通类;想拦截"对类本身的操作"写进元类。

## 6. super() 按哪条链查找

### 6.1 核心规则

`super()` 走的是 **`__mro__`(完整线性化链),不是 `__bases__`**。它等价于 `super(当前类, self)`:

1. 取 **`type(self).__mro__`**(运行时真实类型的 MRO,不是定义方法那个类的);
2. 找到"当前类"在这条 MRO 里的位置;
3. 从它**后面一个**开始往后查。

### 6.2 为什么必须是 `__mro__`:协作式多继承

```python
class A:
    def hi(self): print("A")
class B(A):
    def hi(self): print("B"); super().hi()
class C(A):
    def hi(self): print("C"); super().hi()
class D(B, C):
    def hi(self): print("D"); super().hi()

D().hi()        # D → B → C → A
```

`B.hi` 里的 `super().hi()` 调到的是 **`C.hi`** 而不是 `A.hi`,因为运行时 `type(self) == D`,`D.__mro__ == (D, B, C, A, object)`,`B` 后面是 `C`。**若按 `__bases__`(B 的父类是 A)就会跳过 C。**

### 6.3 用哪条 MRO:看第二个参数

| 写法                             | 用哪条 MRO           | 从哪开始     |
| :------------------------------- | :------------------- | :----------- |
| `super()` / `super(Child, self)` | `type(self).__mro__` | `Child` 之后 |
| `super(Child, SubClass)`         | `SubClass.__mro__`   | `Child` 之后 |

### 6.4 元类里的 super()

同一规则,只是 `self` 换成 `cls`,`type(cls)` 是元类,所以走元类链:

```python
class MyMeta(type):
    def __new__(mcs, name, bases, ns):
        # super() == super(MyMeta, mcs),走 (MyMeta, type, object)
        # MyMeta 之后是 type → 落到 type.__new__ 真正造类
        return super().__new__(mcs, name, bases, ns)
```

## 7. 类的创建过程

用 `class` 定义类时,底层调用元类来创建类:

```python
class Dog:
    pass

# 等效于
class Dog(metaclass=type):
    pass

# 等效于
Dog = type("Dog", (), {})

# 等效于
Dog = type.__call__(type, "Dog", (), {})
```

`class` 关键字只是**语法糖**,底层仍是通过 `type()` 创建类。

## 8. 自定义元类

通过继承 `type`,可以控制类的创建过程。

```python
class MyMeta(type):
    def __new__(mcs, name, bases, namespace):
        print(f"正在创建类: {name}")
        print(f"父类: {bases}")
        print(f"属性: {list(namespace.keys())}")

        # 必须调用 type.__new__ 来真正创建类
        cls = super().__new__(mcs, name, bases, namespace)
        return cls


class Dog(metaclass=MyMeta):
    species = "Canis familiaris"

    def bark(self):
        print("Woof!")

# 等效于
# Dog = type.__call__(MyMeta, "Dog", (), {"species": "Canis familiaris", "bark": bark})

# 输出：
# 正在创建类: Dog
# 父类: ()
# 属性: ['__module__', '__qualname__', 'species', 'bark']
```

**参数说明:**

| 参数        | 含义                           |
| :---------- | :----------------------------- |
| `mcs`       | 元类自身(类似类方法里的 `cls`) |
| `name`      | 类名字符串                     |
| `bases`     | 父类元组                       |
| `namespace` | 类属性的字典                   |

### 8.1 重要澄清:自定义元类 ≠ 给类加一层继承

接第 3 节的两条链:**自定义元类改的是"实例链"那一侧,不是 `MyClass` 的继承链。**

```python
class Meta(type): ...
class MyClass(Base, metaclass=Meta): ...

MyClass.__mro__       # (MyClass, Base, object)   ← 没有 Meta!继承链不受影响
MyClass.__class__     # <class 'Meta'>            ← 变的是这里:它的"类"成了 Meta
```

效果:写在 `Meta` 里的成员,`MyClass` 能用(查 `type(MyClass).__mro__`),但 `MyClass()` 的实例够不到(实例的类是 `MyClass`)。

### 8.2 元类里能写什么

元类就是普通类,写进去的东西变成**类级别**成员:

- **普通方法** → 变成"类方法"效果(`MyClass.method()`,实例够不到);
- **property** → "类级别计算属性"(纯属性写法做不到);
- **控制类本身行为的 dunder** → `__repr__`(改 `repr(MyClass)`)、`__iter__`(`for x in MyClass`)、`__getitem__`(`MyClass[k]`,泛型 `List[int]` 就是这么实现)、`__getattr__`、`__instancecheck__`(自定义 `isinstance`);
- **`__prepare__`** → 定制类体命名空间(元类专属)。

## 9. 元类的查找与传播

### 9.1 子类自动沿用父类的元类

```python
class MyMeta(type):
    pass

class Base(metaclass=MyMeta):
    pass

class Child(Base):  # 自动沿用 MyMeta
    pass

print(type(Child))  # <class '__main__.MyMeta'>
```

**这不是"继承"来的,是"推导"来的**:Python 创建 `Child` 时检查所有父类的元类,规则要求"子类的元类必须是所有父类元类的(非严格)子类",于是自动选用 `MyMeta` 来造 `Child`。

### 9.2 这个例子里的两条 MRO

```python
Child.__mro__        # (Child, Base, object)    ← 继承链
type(Child).__mro__  # (MyMeta, type, object)   ← 元类链
```

为什么元类链是 `(MyMeta, type, object)` 而不是 `(type, object)`?

- `type(Child)` 返回"造 Child 的元类"= **`MyMeta`**(从父类传播来),不是 `type`;
- `type(Child).__mro__` 就是 `MyMeta` 自己的 MRO,而 `MyMeta(type)` 继承自 `type`,所以链头是 `MyMeta`,后面才是 `type`、`object`。

对比:

| 情况              | `type(X)` 是谁 | `type(X).__mro__`        |
| :---------------- | :------------- | :----------------------- |
| 普通类(默认元类)  | `type`         | `(type, object)`         |
| Child(自定义元类) | `MyMeta`       | `(MyMeta, type, object)` |

### 9.3 用这个例子验证查找顺序

```python
class MyMeta(type):
    meta_attr = "我在元类里"
class Base(metaclass=MyMeta):
    base_attr = "我在 Base 里"
class Child(Base):
    child_attr = "我在 Child 里"

c = Child()

# 实例访问:只走 (Child, Base, object)
c.child_attr     # ✅
c.base_attr      # ✅
c.meta_attr      # ❌ AttributeError —— 元类链不参与

# 类访问:两条链都走
Child.child_attr # ✅ 继承链(自己)
Child.base_attr  # ✅ 继承链(父类)
Child.meta_attr  # ✅ 元类链 (MyMeta, type, object)
```

`Child.meta_attr` 拿得到、`c.meta_attr` 拿不到——区别就在 `Child` 的类是 `MyMeta`(够得到元类链),`c` 的类是 `Child`(够不到)。

### 9.4 元类冲突

```python
class MetaA(type): pass
class MetaB(type): pass
class A(metaclass=MetaA): pass
class B(metaclass=MetaB): pass

# class C(A, B): pass        # TypeError! 元类冲突(MetaA 与 MetaB 互不为子类)

class CommonMeta(MetaA, MetaB): pass        # 造一个兼容的元类
class C(A, B, metaclass=CommonMeta): pass   # 正常
```

## 10. 总结

| 概念               | 说明                                                                 |
| :----------------- | :------------------------------------------------------------------- |
| 元类               | 创建类的类,默认是 `type`                                             |
| 继承链 `__mro__`   | 决定"在一个类里怎么逐层往上找";含自己、到 object、去重排序           |
| 实例链 `__class__` | 决定"从哪个类的 MRO 起跳";`type(X)` 是谁就用谁的链                   |
| `__new__`          | 创建类,返回类对象                                                    |
| `__init__`         | 初始化类,无返回值                                                    |
| `__call__`         | 控制类的实例化过程                                                   |
| `super()`          | 沿 `type(self).__mro__` 从当前类**之后**找,不是按 `__bases__` 找父类 |
| 应用场景           | 命名检查、自动注册、方法增强、ORM 等                                 |

**一句话贯穿全文**:看 `type(X)` 是谁,就从谁的 MRO 起跳——实例起点是它的类,类的起点是它的元类。

## 11. 作业

### 11.1 实现单例元类

编写元类 `SingletonMeta`,使任何使用它的类自动成为单例:

```python
class SingletonMeta(type):
    # 你的代码
    pass

class Database(metaclass=SingletonMeta):
    def __init__(self, host):
        self.host = host

db1 = Database("localhost")
db2 = Database("remote")
print(db1 is db2)  # 应输出 True
print(db1.host)    # 应输出 localhost
```

### 11.2 自动注册子类

编写元类 `PluginMeta`,使任何继承自 `Plugin` 的子类自动注册到 `PluginMeta.registry`(键为类名,值为类本身):

```python
class PluginMeta(type):
    # 你的代码
    pass

class Plugin(metaclass=PluginMeta):
    pass

class ImagePlugin(Plugin):
    pass

class TextPlugin(Plugin):
    pass

print(PluginMeta.registry)
# 应输出类似：{'ImagePlugin': <class '__main__.ImagePlugin'>, 'TextPlugin': <class '__main__.TextPlugin'>}
```

### 11.3 为所有方法添加日志

编写元类 `LogMeta`,自动为类中每个非私有方法(不以 `_` 开头)加执行日志,调用时先打印 `[LOG] 调用 {方法名}` 再执行原方法:

```python
class LogMeta(type):
    # 你的代码
    pass

class Calculator(metaclass=LogMeta):
    def add(self, a, b):
        return a + b

    def sub(self, a, b):
        return a - b

calc = Calculator()
print(calc.add(3, 5))
print(calc.sub(10, 4))

# 应输出：
# [LOG] 调用 add
# 8
# [LOG] 调用 sub
# 6
```
