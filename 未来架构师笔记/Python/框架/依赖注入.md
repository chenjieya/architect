## 1. 理解IoC、DI、IoC容器

`IoC`: **Inversion of Control，控制反转**

`DI`：**Dependency Injection，依赖注入**

```python
# Depends.py
from __future__ import annotations

from collections.abc import Callable
from typing import Any


class Depends:
    _overrides: dict[Callable[..., Any], Callable[..., Any]] = {}

    def __init__(self, func: Callable[..., Any]) -> None:
        self.func = func

    def __call__(self, *args: Any, **kwds: Any) -> Any:
        actual = self._overrides.get(self.func, self.func)
        return actual(*args, **kwds)

    @classmethod
    def override(
        cls,
        original: Callable[..., Any],
        replacement: Callable[..., Any],
    ) -> None:
        cls._overrides[original] = replacement

    @classmethod
    def clear_override(cls, func: Callable[..., Any] | None = None) -> None:
        if func is not None:
            cls._overrides.pop(func, None)
        else:
            cls._overrides.clear()



 # main.py
from Depends import Depends


def check_permission(user: str) -> bool:
    print(f"验证用户{user}权限")
    return True


def ali_oss_upload(user: str, file: str, has_permission=Depends(check_permission)):
    if not has_permission(user):
        raise Exception("权限不足")
    print(f"阿里云，{file} 上传中...")


def upload_file(user: str, file: str, oss_upload=Depends(ali_oss_upload)):
    print("上传准备")
    oss_upload(user, file)  # 注意这里传入的是函数本身
    print("上传成功")


# 正常情况
upload_file("张三", "1.txt")


# 特殊情况：希望切换为腾讯云怎么办？？？
def tencent_oss_upload(user: str, file: str, has_permission=Depends(check_permission)):
    if not has_permission(user):
        raise Exception("权限不足")
    print(f"腾讯云，{file} 上传中...")


Depends.override(ali_oss_upload, tencent_oss_upload)
upload_file("张三", "2.txt")


# 测试环境：希望使用假的oss上传怎么办？？？
def fake_upload(user: str, file: str, has_permission=Depends(check_permission)):
    if not has_permission(user):
        raise Exception("权限不足")

def fake_check_permission(user: str) -> bool:
    print(f"模拟：验证用户{user}权限")
    return True


Depends.clear_override()
Depends.override(ali_oss_upload, fake_upload)
Depends.override(check_permission, fake_check_permission)

```

**IoC**：一种设计思想，旨在将某种**选择权**移交出去，从而避免与其耦合

**DI**：将IoC思想落地的一种手段

**IoC容器**：优化DI的工具，它负责交付依赖项

## 2. 类型标注、元数据与注入原理

### 2.1 `Annotated` 类型标注

```python
from typing import Annotated
from fastapi import Depends
from sqlalchemy.ext.asyncio import AsyncSession

def handler(db: Annotated[AsyncSession, Depends(get_db)]):
    pass
```

`Annotated[T, X]` 是一个**类型+元数据容器**：

| 部分       | 内容              | 用途                                  |
| ---------- | ----------------- | ------------------------------------- |
| 类型 `T`   | `AsyncSession`    | 给类型检查器用（IDE 提示、mypy 校验） |
| 元数据 `X` | `Depends(get_db)` | 给 FastAPI 用（提取依赖信息）         |

**Python 解释器本身对元数据完全无视**，只把它当作 `AsyncSession` 类型。

### 2.2 元数据 (Metadata)

元数据 = **关于数据的数据**。`Annotated` 底层存储结构：

```python
from typing import Annotated, get_args, get_origin

T = Annotated[int, "hello", 42]

T.__origin__               # <class 'int'>        ← 类型
T.__metadata__             # ("hello", 42)        ← 元数据（元组）

# 等价方式
get_origin(T)              # Annotated
get_args(T)                # (int, "hello", 42)
```

### 2.3 FastAPI 如何提取元数据

FastAPI 启动时扫描路由函数签名，**它不看类型，只看元数据**：

```python
import inspect
from typing import Annotated, get_args

def handler(
    data: CategoryCreate,
    db: Annotated[AsyncSession, Depends(get_db)],
):
    pass

sig = inspect.signature(handler)

for name, param in sig.parameters.items():
    ann = param.annotation                    # 参数注解

    # 检查是否是 Annotated
    if get_origin(ann) is Annotated:
        args = get_args(ann)                  # (AsyncSession, Depends(get_db))
        typ = args[0]                         # AsyncSession      → 类型
        meta = args[1:]                       # (Depends(get_db),) → 元数据

        # FastAPI 识别出 Depends(get_db)
        # 知道这个参数需要调用 get_db() 来注入
```

**关键**：FastAPI 根本不关心 `AsyncSession` 这个类型，它只提取 `Depends(get_db)` 这个元数据，知道要调用 `get_db`。

### 2.4 `Depends` 原理

FastAPI 的 `Depends` 本质上就是一个**标记 + 依赖解析器**：

```python
# FastAPI 源码简化版
class Depends:
    def __init__(self, dependency=None, *, use_cache=True):
        self.dependency = dependency      # 存着 get_db 这个函数
        self.use_cache = use_cache
```

**它不是依赖本身，只是一个「便签」**，告诉 FastAPI：

> "这个参数需要调用 `get_db()` 来获取值"

### 2.5 完整的注入流程

```
请求到达
    │
    ├─ 1. FastAPI 用 inspect 解析 handler 的参数
    │     发现 db 参数有 Depends(get_db) 标记
    │
    ├─ 2. FastAPI 内部执行依赖解析：
    │     │
    │     ├─ 调用 get_db()
    │     │   ├─ async with AsyncSession(engine) as session:
    │     │   │       yield session              ← 生成器暂停，返回 session
    │     │   │
    │     │   └─ 拿到 session 实例
    │     │
    │     ├─ 把 session 作为 db 参数传入 handler
    │     │   await handler(data, db=session)
    │     │                       ↑↑
    │     │                 这就是「注入」
    │     │
    │     └─ handler 执行完毕，继续执行 get_db()
    │         └─ 退出 async with，关闭 session
    │
    └─ 3. 返回响应
```

### 2.6 生成器型依赖的生命周期

```python
async def get_db():
    async with AsyncSession(engine) as session:
        # ─── 进入上下文（打开连接）───
        yield session
        # ─── 退出上下文（关闭连接）───
```

FastAPI 内部大致这样处理：

```python
# FastAPI 伪代码
gen = get_db()                       # 创建生成器对象（此时还没执行）
session = await anext(gen)            # 进入 async with → yield → 拿到 session
try:
    result = await handler(data, db=session)   # 注入 session，执行 API
finally:
    try:
        await anext(gen)              # 继续生成器 → 退出 async with → 关连接
    except StopIteration:
        pass
```

**不是 API 代码「进入了 get_db 的上下文」，而是 FastAPI 主动串起来了：**

1. `next(gen)` → 进入 `async with`，打开连接，`yield` 暂停
2. FastAPI 拿到 session → 注入 handler
3. handler 用 session 操作数据库
4. handler 结束 → FastAPI 再次 `next(gen)` → 退出 `async with`，关闭连接

### 2.7 等价写法对比

```python
# 老写法：Depends 直接作为默认值
def handler(db: AsyncSession = Depends(get_db)):
    pass

# 新写法：Annotated 分离类型和元数据
def handler(db: Annotated[AsyncSession, Depends(get_db)]):
    pass
```

**两者完全等价**，FastAPI 内部统一处理。`Annotated` 的优势：

- 类型检查器能正确识别类型（老写法 ` = Depends(...)` 会让 mypy/pyright 困惑）
- 语义更清晰：类型归类型，依赖归依赖
