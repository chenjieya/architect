## 1. 系统状态监控

### 1.1 系统负载分析

#### 1.1.1 uptime 命令详解

```bash
$ uptime
 10:30:45 up 15 days,  3:25,  3 users,  load average: 0.08, 0.03, 0.05
```

- **显示内容解析**：
  - 当前系统时间：10:30:45
  - 运行时间：15天3小时25分钟
  - 登录用户数：3个
  - 系统平均负载：0.08（1分钟）、0.03（5分钟）、0.05（15分钟）

#### 1.1.2 负载均衡深度分析

```bash
# 查看CPU核心数
$ cat /proc/cpuinfo | grep "processor" | wc -l
4

# 查看详细负载信息
$ cat /proc/loadavg
0.08 0.03 0.05 1/320 4567

# 各部分含义：
# 0.08 - 1分钟平均负载
# 0.03 - 5分钟平均负载
# 0.05 - 15分钟平均负载
# 1/320 - 当前运行进程数/总进程数
# 4567 - 最近运行的进程ID
```

**负载值解读规则**：

- 负载值 < CPU核心数：系统空闲
- 负载值 ≈ CPU核心数：系统满负荷但可接受
- 负载值 > CPU核心数：系统过载

#### 1.1.3 实时监控工具

```bash
# top命令（基础版）
$ top

# htop命令（增强版，需安装）
$ sudo apt install htop  # Ubuntu/Debian
$ sudo yum install htop  # CentOS/RHEL
$ htop
```

## 2. 进程管理详解

### 2.1 进程查看命令

#### 2.1.1 ps 命令的不同用法

```bash
# 显示当前终端进程
$ ps

# 显示所有用户的所有进程（BSD风格）
$ ps aux
USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root         1  0.0  0.1 168320  6384 ?        Ss   Oct10   0:01 /sbin/init
root         2  0.0  0.0      0     0 ?        S    Oct10   0:00 [kthreadd]

# 显示进程树形结构
$ ps auxf

# 显示完整格式（标准风格）
$ ps -ef
UID        PID  PPID  C STIME TTY          TIME CMD
root         1     0  0 Oct10 ?        00:00:01 /sbin/init
root         2     0  0 Oct10 ?        00:00:00 [kthreadd]
```

#### 2.1.2 进程字段详解

- **USER**：进程所有者
- **PID**：进程ID
- **PPID**：父进程ID
- **%CPU**：CPU使用率
- **%MEM**：内存使用率
- **VSZ**：虚拟内存大小（KB）
- **RSS**：物理内存大小（KB）
- **TTY**：终端设备
- **STAT**：进程状态
- **START**：启动时间
- **TIME**：累计CPU时间
- **COMMAND**：命令名称

### 2.2 进程状态详解

#### 2.2.1 进程状态码（STAT）

```bash
# 常见状态码：
R   运行中或可运行（在运行队列中）
S   可中断的休眠状态（等待事件完成）
D   不可中断的休眠状态（通常与I/O相关）
T   已停止（通过作业控制信号或追踪）
Z   僵尸进程（已终止但未回收）
X   已死亡（仅瞬间状态）

# 附加标志：
<   高优先级（nice值负）
N   低优先级（nice值正）
L   有页面锁定在内存中
s   会话首进程
l   多线程进程
+   前台进程组
```

#### 2.2.2 父子进程关系

```bash
# 查看指定进程的子进程
$ pstree -p 1
systemd(1)─┬─ModemManager(658)
           ├─NetworkManager(703)
           └─sshd(895)───sshd(1234)───bash(1235)

# 查看进程树（带进程ID）
$ pstree -p

# 查看特定用户的进程树
$ pstree -p username
```

### 2.3 进程优先级管理

#### 2.3.1 nice 值调整

```bash
# 启动程序时指定优先级
$ nice -n -5 /usr/bin/important_job  # 较高优先级（-20到19）

# 调整运行中进程的优先级
$ renice -n -10 -p 1234  # 将PID 1234的nice值设为-10

# 查看进程nice值
$ ps -eo pid,comm,nice --sort=-nice

# 批量调整进程组优先级
$ renice -n 5 -g group_name
```

### 2.4 前台与后台作业管理

#### 2.4.1 作业控制命令

```bash
# 1. 启动后台作业
$ tar -zcvf backup.tar.gz /data &

# 2. 查看后台作业
$ jobs
[1]  + running    tar -zcvf backup.tar.gz /data
[2]  - suspended  vim config.txt

# 3. 前台转后台
$ # 按下Ctrl+Z暂停前台作业
$ bg %1  # 将作业1转到后台继续运行

# 4. 后台转前台
$ fg %2  # 将作业2转到前台

# 5. 杀死后台作业
$ kill %1  # 杀死作业1
```

#### 2.4.2 nohup 命令（断开连接后继续运行）

```bash
# 使用nohup在后台运行程序
$ nohup ./long_running_script.sh > script.log 2>&1 &

# 解释：
# > script.log      # 标准输出重定向到文件
# 2>&1             # 标准错误重定向到标准输出
# &                # 在后台运行
```

### 2.5 进程信号管理

#### 2.5.1 常用信号列表

```bash
# 查看所有信号
$ kill -l
 1) SIGHUP       2) SIGINT       3) SIGQUIT      4) SIGILL
 2) SIGTRAP      6) SIGABRT      7) SIGBUS       8) SIGFPE
 3) SIGKILL     10) SIGUSR1     11) SIGSEGV     12) SIGUSR2
4) SIGPIPE     14) SIGALRM     15) SIGTERM     16) SIGSTKFLT
```

#### 2.5.2 常用信号说明

```bash
# 常用信号及用途：
1  (SIGHUP)    重新加载配置（不终止进程）
2  (SIGINT)    键盘中断（Ctrl+C）
9  (SIGKILL)   强制终止（无法被捕获或忽略）
15 (SIGTERM)   优雅终止（默认信号）
18 (SIGCONT)   继续运行已停止的进程
19 (SIGSTOP)   停止进程（无法被捕获或忽略）
```

#### 2.5.3 信号发送方法

```bash
# 使用kill发送信号
$ kill -15 1234       # 发送SIGTERM到PID 1234
$ kill -9 1234        # 强制杀死PID 1234
$ kill -HUP 1234      # 重新加载配置

# 使用pkill按名称发送信号
$ pkill -9 nginx      # 强制杀死所有nginx进程
$ pkill -HUP nginx    # 重载nginx配置

# 使用killall按名称发送信号
$ killall -9 firefox  # 强制杀死所有firefox进程
```

## 4. 实用监控脚本示例

### 4.1 系统健康检查脚本

```bash
#!/bin/bash
# system_health_check.sh

echo "=== 系统健康检查报告 ==="
echo "生成时间: $(date)"
echo ""

echo "1. 系统负载情况"
echo "----------------"
uptime
echo "CPU核心数: $(nproc)"
echo "1分钟负载: $(cat /proc/loadavg | awk '{print $1}')"
echo ""

echo "2. 内存使用情况"
echo "----------------"
free -h
echo ""

echo "3. 磁盘使用情况"
echo "----------------"
df -h
echo ""

echo "4. 前10个CPU占用进程"
echo "---------------------"
ps aux --sort=-%cpu | head -11
echo ""

echo "5. 前10个内存占用进程"
echo "----------------------"
ps aux --sort=-%mem | head -11
echo ""

echo "6. 系统服务状态"
echo "---------------"
systemctl list-units --type=service --state=failed
```

### 4.2 进程监控脚本

```bash
#!/bin/bash
# process_monitor.sh

# 监控特定进程
PROCESS_NAME=$1
LOG_FILE="/var/log/process_monitor.log"

if [ -z "$PROCESS_NAME" ]; then
    echo "Usage: $0 <process_name>"
    exit 1
fi

while true; do
    PID=$(pgrep $PROCESS_NAME)
    if [ -z "$PID" ]; then
        echo "$(date): Process $PROCESS_NAME is not running!" >> $LOG_FILE
        # 自动重启示例
        # systemctl restart $PROCESS_NAME
    else
        CPU_USAGE=$(ps -p $PID -o %cpu | tail -1)
        MEM_USAGE=$(ps -p $PID -o %mem | tail -1)
        echo "$(date): PID:$PID, CPU:$CPU_USAGE%, MEM:$MEM_USAGE%" >> $LOG_FILE
    fi
    sleep 60
done
```

## 5. 最佳实践建议

### 5.1 监控策略

1. **定期检查**：设置cron定时任务进行系统健康检查
2. **设置阈值**：对关键指标（CPU、内存、磁盘）设置报警阈值
3. **日志轮转**：配置logrotate防止日志文件过大
4. **集中日志**：考虑使用ELK栈或Graylog进行集中日志管理

### 5.2 故障排查流程

1. **快速定位**：使用top/htop快速识别问题进程
2. **深入分析**：结合ps、strace、lsof等工具分析进程行为
3. **日志追踪**：查看相关服务日志和系统日志
4. **资源监控**：检查系统资源使用情况

### 5.3 性能优化建议

1. **合理设置进程优先级**：对关键服务使用较高优先级
2. **避免僵尸进程**：确保程序正确处理子进程终止
3. **监控内存泄漏**：定期检查内存使用趋势
4. **I/O优化**：对高I/O应用考虑使用更快的存储设备

通过掌握这些系统监控和进程管理技能，你可以有效地维护Linux系统的稳定性和性能，快速定位并解决系统问题。
