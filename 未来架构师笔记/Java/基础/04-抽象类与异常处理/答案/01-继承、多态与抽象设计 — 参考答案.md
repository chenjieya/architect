## 2. L2 原理应用

### 2.1

**答**：

- **现象**：`d.eat()` 仍走父类「正在吃东西」。
- **原因**：`eat(String food)` 与父类 `eat()` **参数列表不同**，是**重载**而非**重写**；无参调用匹配父类方法。
- **修复**：`@Override public void eat() { ... }`（与父类同名同参）。

### 2.2

**答**：

- **编译期类型**：`Shape`（引用 `s` 的声明类型）。
- **运行期类型**：`Circle`（实际对象）。
- **实际调用**：`Circle.area()`，因实例方法 **运行期绑定**，不是 `Shape.area()` 返回 0。

### 2.3

**答**：

- 第一行：`false`（实际是 `Cat`，不是 `Dog`）。
- 第二行：`true`。
- `(Dog) a`：**编译可通过**（编译期类型是 `Animal`），**运行期**抛出 **ClassCastException**（对象是 `Cat` 不能当 `Dog`）。

### 2.4

**答**：

- **`final`**：`generate()` 不可被子类重写。
- **模板意图**：流程（头→正文→尾）固定在父类，子类只实现 **`exportBody()`** 钩子。
- **应改**：实现/重写 `exportBody()`，不要重写 `generate()`。

### 2.5

**答**：**不需要**改 `checkout` 签名或方法体。参数已是 `Payable`，第二次传入 `WechatPayment` 仍满足接口；多态调用 `p.pay(amount)` 会走微信实现。体现面向接口编程。

### 2.6

**答**：

- **is-a**：`Car extends Engine` 表示「车是一种引擎」，语义错误。
- **has-a**：车 **有一个** 引擎，应用成员 `Engine` + 委托 `engine.start()`。

### 2.7

**答**：**不发生**实例多态。`static` 方法按 **声明类型/类名** 解析；子类同名 static 是 **隐藏（hide）**，不是 **重写**。`a.info()` 若通过实例调用，仍绑定 `Animal.info()`（推荐用类名调用 static）。

### 2.8

**答**：循环只依赖 `Shape.draw()`，运行期按各元素实际类型绑定。新增 `Triangle` **不必改循环**，只需新类重写 `draw()`——对扩展开放、对修改关闭（开闭原则直觉）。

### 2.9

**答**：**编译失败**。接口新增方法后，实现类必须提供 **全部** 方法实现，否则不满足接口契约。

### 2.10

**答**：

```java

    super(title);
    // ...
}
```

（首行 `super(title);` 调用父类构造。）

## 3. L3 场景实战

### 3.1 [面试]

**答要点**：

- **重载**：同类，方法名同，**参数列表不同**；编译期绑定。
- **重写**：子类与父类 **同名同参**，改实现；运行期多态。
- **约束示例**：子类访问权限不能更窄；`final` 不可重写；实例方法；建议 `@Override`；`static` 不算重写等（任列 3 条）。

### 3.2 [面试]

**答要点**：

- **多态**：同一父类引用，不同子类对象，调用重写方法表现不同。
- **编译期类型**：`Shape`。
- **运行期类型**：`Circle`。
- **运行时绑定**：`s.area()` 执行 `Circle.area()`。

### 3.3 [面试]

**答要点**：

- **抽象类**：`abstract class`，可有构造器、字段、具体+抽象方法，单继承；**模板/共性** → `AbstractReport.generate()` + `exportBody()`。
- **接口**：`interface`，类 **多实现**，定义能力；**解耦替换** → `Payable` + `AlipayPayment`/`WechatPayment`。

### 3.4 [面试]

**答要点**：

- 依赖 **接口类型** 声明变量/参数，不依赖具体实现类。
- 换支付渠道只换 `new` 的实现类，业务方法签名与逻辑不变，降低耦合、便于测试与扩展。

### 3.5 [面试·扩展]

**答要点**：

- 继承仅为 **抄代码**、非 true is-a 时不应 extends。
- **`Car` 与 `Engine`**：has-a，用成员 + 委托；换引擎不改 `Car` 继承链。
- 继承使子类与父类 **强耦合**；组合更灵活。

### 3.6 [面试]

**答要点**：

- Java 避免多继承带来的 **菱形/歧义** 问题；用 **接口多实现** 表达多能力。
- Python 多继承灵活但 MRO 复杂；Java 用 **单继承树 + 接口** 换更清晰类型系统（编译期检查）。

### 3.7 [工作]

**答要点**（OOP 层面，任列 3 条）：

- 引入 **`AbstractReport` 或统一父类型** 声明，而非写死 `PdfReport`。
- 用 **工厂/配置** 选择 `PdfReport`/`TextReport` 具体类（本章可不写工厂名，说「创建处可替换」即可）。
- **`generate()` 调用** 只依赖抽象类型；新增 HTML 子类不改调用代码。
- 或 **面向接口** 若报告能力用接口表达（与文档一致即可）。

### 3.8 [面试]

**答要点**：

- 需要 **子类特有方法** 时，先 `instanceof` 确认再 **向下转型**。
- 不做检查强转可能 **ClassCastException**（运行期）。

### 3.9 [面试]

**答要点**：

- **模板方法**：父类定义算法骨架（固定步骤），子类实现变化步骤。
- `generate()` 固定头尾，**公共流程一处维护**；`exportBody()` 子类差异化；符合 **开闭** 直觉。

### 3.10 [工作]

**答要点**：

- **is-a**：`MiniCar extends Engine` 表示「迷你车是一种引擎」，语义错误；应是 **车 has-a 引擎**。
- **耦合**：继承使 `MiniCar` 与 `Engine` 强绑定，父类 `Engine` 改动影响子类；仅为复用 `start()`/`getPower()` 不应 extends。
- **方向**：定义 `Car`（或 `MiniCar`）**持有** `Engine` 成员，通过 **委托** 调用 `engine.start()`（同 `CarDemo`）。
