## 2. L2 原理应用

### 2.1 版本分裂

**推理**：

1. `java` 与 `javac` 来自 Path 中**不同路径**；Path **先匹配先生效**。
2. 验证：`where java`、`where javac`，对比是否同一 JDK 的 `bin`；查看 `-version`。
3. 常见：`javapath` 或旧 JRE 的 `java` 靠前，JDK 17 的 `javac` 仅在 `%JAVA_HOME%\bin`。
4. **修复**：统一 `JAVA_HOME` 为 JDK 17 根目录；删除或后移冲突 Path 项；`%JAVA_HOME%\bin` 靠前；新开终端复测。

### 2.2 PATH 顺序

**推理**：

1. 第 1 项 `javapath` 先被搜索，其中 `java.exe` 常指向旧版 1.8。
2. 验证：`where java` 第一行是否在 `javapath`；`where javac` 是否在 JDK 17。
3. **修复**：后移或删除 `javapath`；保证 `%JAVA_HOME%\bin` 优先；重启终端。

### 2.3 编译目录

**答**：**第 4 层**（源码与命令/目录）。

**步骤**：

```bash
cd hello-java/src
javac HelloWorld.java
java HelloWorld
```

### 2.4 main 缺 static

**答**：

- 编译：`public void main` 是普通实例方法，javac 合法。
- 运行：JVM 启动器查找 **`public static void main(String[] args)`**，不会创建 `Test` 实例去调实例 `main` → 运行失败。

### 2.5 JAVA_HOME 未配置

**推理**：

1. Path 配好可使命令行 `java`/`javac` 可用，但 **`JAVA_HOME` 未设时，IDEA 等工具可能无法正确定位 JDK 根目录**——`JAVA_HOME` 是业界约定，指向 JDK 安装根目录，不仅服务于命令行 Path。
2. 表现：命令行短期「看起来正常」，打开 IDEA 配置 Project SDK 时可能失败。
3. **验证**：`echo %JAVA_HOME%` 或 `echo $env:JAVA_HOME` 是否为空；与 `where javac` 路径对照。
4. **修复**：设置 `JAVA_HOME` 为 JDK 17 **根目录**（非 `bin`）；Path 含 `%JAVA_HOME%\bin`；新开终端与 IDEA 验证 Project SDK。

## 3. L3 场景实战

### 3.1 [面试] JDK/JRE/JVM

**要点**：

- **JVM**：执行字节码的虚拟机
- **JRE**：JVM + 核心类库，只能运行
- **JDK**：JRE + 开发工具（含 `javac`、`java` 等）
- 关系：**JDK ⊇ JRE ⊇ JVM**；开发必须 **JDK**

### 3.2 [面试] 源码到运行 + JIT

**要点**：

1. `.java` → **`javac`（编译期）** → `.class` 字节码 → **`java` 启动 JVM（运行期）** → 加载并执行字节码 → 输出
2. **`javac`**：编译期；语法与主要类型检查；生成字节码
3. **JIT**：**JVM 运行期**对热点字节码编译为本地机器码；与 `javac` **阶段不同、作用不同**

### 3.3 [面试] main 签名

**要点**：

- **`public`**：JVM 从外部调用入口，须可访问
- **`static`**：启动时无实例，须类级别调用；缺 static 则典型「编译过、运行挂」
- **`void`**：入口不向 OS 返回 C 风格 int 状态
- **`String[] args`**：接收命令行参数，如 `java App a b` → `args[0]="a"`

### 3.4 [面试·扩展] 编译型与跨平台

**要点**：

- 二分法**不够准确**：Java 也有 JVM **运行期**工作（解释 + JIT）；Python 等也可能有编译/缓存步骤
- 更准确：**Java 有独立 `javac` 编译步骤 + 编译期类型检查**；Python 多数场景直接由解释器处理源码
- **「一次编译，到处运行」**：指 **字节码 `.class` 与 OS 无关**，在各平台 **JVM** 上运行，无需为每个 OS 重新编译源码

### 3.5 [工作] 终端与 IDEA 不一致

**可能原因**：

- 系统 Path 正常，但 **IDEA Project SDK 未配或配错**
- 改 Path 后 **IDEA 未重启**，与终端环境不一致（较少见，但文档有提及）

**排查步骤**：

1. 终端：`java -version`、`javac -version`、`where java`
2. IDEA：**文件 → 项目结构 → 项目设置 → 项目** → **SDK** 选 JDK 17（即 Project SDK）
3. Language level 与 SDK 一致；必要时 Restart IDE
4. 统一安装 Temurin 17，设 `JAVA_HOME` 与 Path

**IDEA 与 Cursor**：

- **IDEA**：Java 后端系统学习、Project SDK 配置、Run/Debug、工程化支持较强，适合作为**主 IDE**
- **Cursor**：可编写 Java，轻量、AI 辅助体验好，但复杂 Java 工程的 IDE 集成弱于 IDEA，适合辅助编辑；**正式编译运行建议在 IDEA 中验证**
