## 1. AGENTS.md — 未来架构师笔记 · 维护规则

这是本知识库的**规则层（Schema）**。任何 LLM Agent 在操作本仓库前，必须完整阅读本文件并严格遵守。

### 1.1 目录结构（三层）

```
未来架构师笔记/
├── AGENTS.md        # 本文件：规则层，告诉 AI 怎么干活
├── CLAUDE.md        # Claude Code 桥接文件：@AGENTS.md 导入同一套规则
├── index.md         # 全库目录（AI 维护，位于根目录，肉眼可见）
├── log/             # 操作日志目录（AI 维护，按月份滚动，如 2026-08.md，只追加）
├── raw/             # 原始资料层：源文档，AI 只读，永不修改
│   └── operations-*/# Linux/DevOps 笔记的原始教学资料
└── wiki/            # 知识层：全部笔记（AI 生成 + 人类手写，按单文件 frontmatter 判定权限）
    ├── Linux/       # 当前主要 AI 生成区，多数 ai_editable: true
    └── 其余目录/      # 可同时存在人类笔记和 AI 新建笔记，逐文件看 ai_editable
```

### 1.2 所有权规则（最优先，违反即违规）

每篇笔记的 frontmatter 决定 AI 能否修改。**判断依据只有一个：frontmatter 里的 `ai_editable` 字段。**

#### 1.2.1 frontmatter 字段说明

```yaml
---
author: human # human=人类手写（AI 只小修） | ai=AI生成 | mixed=人机协作
ai_editable: false # false=AI只读（人类笔记） | true=AI可自由维护
summary: 一句话摘要 # 供 index.md 和检索定位使用，尽量控制在 80 字以内
refs:
  pages: [] # 当前页面依赖的 Wiki 页面，使用 Obsidian 文件名，不写路径
  raw: [] # 当前页面依赖的 raw 源文件，建议记录 path + sha256
updated_by: human # 最近一次修改者：human / ai
updated: 2026-08-02 # 最近修改日期
---
```

`author` 三种状态判定标准：

| 状态    | 触发条件                                                                                                   | ai_editable |
| ------- | ---------------------------------------------------------------------------------------------------------- | ----------- |
| `human` | 人类手写，AI 仅小修（改错字、修伪链接、改文件名这类）                                                      | `false`     |
| `mixed` | 人类笔记 + AI 在用户授权下**实质性参与**：大段补充、重构、把零散内容整理成结构化页面，内容已是双方合作产物 | `true`      |
| `ai`    | AI 生成，人类基本不参与                                                                                    | `true`      |

`summary` 与 `refs` 字段用于支撑规模化维护：

- `summary`：一句话说明页面解决什么问题，供根目录 `index.md` 展示和 Agent 快速判断页面价值。
- `refs.pages`：显式声明当前页面依赖的 Wiki 页面，使用 Obsidian 文件名（如 `【LLM】RAG：基础知识`），不写相对路径或全路径。
- `refs.raw`：显式声明当前页面依赖的 `raw/` 源文件。AI 从 raw 整理出的页面应记录源文件路径与 `sha256`，用于后续检测源文件变化后哪些 Wiki 页面可能过时。

`refs.raw` 推荐格式：

```yaml
refs:
  raw:
    - path: raw/Hot Module Replacement is Easy.md
      sha256: <源文件当前 sha256>
```

#### 1.2.2 硬性规则

1. **`ai_editable: false`（人类笔记）**：AI 只能 **读** 和 **引用**，**严禁修改内容**。
   - 想补充/修正 → 先以建议形式提出，用户明确同意后才能改，且只改用户同意的最小范围。
   - 需要链接 → 允许在**其他 AI 拥有的文件**里添加指向该笔记的 `[[链接]]`，但绝不改动该笔记本身。
2. **`ai_editable: true`（AI 可维护笔记）**：AI 可继续更新、维护该文件，但仍须遵守第 3 节的边界。`ai_editable: true` 不限于 `wiki/Linux/**`，也可以出现在其他主题目录中新建的 AI 笔记或用户授权后的 mixed 笔记。
3. **`author: mixed`（人机协作）**：人类笔记 + AI 实质性参与后的状态，`ai_editable: true`，AI 可继续维护。
   - **升级条件**：只有用户明确授权并**实际提出/认可**那次实质性修改后，才能把该笔记 `author` 从 `human` 改为 `mixed`。AI 不得自行升级。
   - 仅小修（错字、伪链接、改文件名）不触发升级，保持 `human`。
4. **没有 frontmatter 的文件 = 按 `ai_editable: false` 处理**（默认人类笔记，AI 只读）。
5. **`raw/` 目录：只读**。不新增、不删除、不修改任何内容，连 frontmatter 都不能加；`tools/format.mjs` 已排除 `raw/`，任何情况下不对 raw 做格式化。
6. 每篇**新建**的 AI 笔记必须带完整 frontmatter，`author: ai`、`ai_editable: true`、`summary`、`refs`、`updated_by: ai`，并更新 `index.md`。新建笔记的目录归属由主题决定，不受同目录已有旧笔记所有权限制。
7. **`index.md`（根目录）与 `log/`（操作日志）属于 AI 专属文件**：等价 `ai_editable: true`，即使不带 frontmatter 也由 AI 全权维护，无须征求同意。
8. 忽略根目录 `task/` 目录：这是用户个人维护的任务区，与知识库无关。AI 不得读取、引用、修改、索引其内容，Ingest / Query / Lint / 格式化等一切操作均须跳过它。
9. 默认读者数学基础薄弱（读者即用户本人），写作须做到：① 凡涉及数学内容，在对应主题目录下单独开辟数学讲解页，详细说明概念与推导逻辑；② 能用坐标系或统计图讲清的，必须配图并配合公式讲解；③ 文中每个公式都要逐符号拆解、用大白话解释；④ 与坐标系、统计图无关的内容不得强行配图；⑤ 唯一验收标准是让零基础读者能看懂；⑥ 对重要公式须给出证明/推导（如 n-1 无偏估计、最小二乘解、梯度下降方向等），用逐步推导配大白话解释，让零基础读者明白"公式为什么成立"，而非只会套用。

### 1.3 修改边界（防止污染人类笔记生态）

本 vault 使用了以下 Obsidian 插件，AI 的写入必须与之兼容：

- **格式统一（强制）**：任何 AI 创建或修改过的 `wiki/` 下 `.md` 文件，操作完成后必须运行 `node tools/format.mjs`，该脚本复刻用户 prettier 插件（Alvis 二次开发版）的完整管线：prettier@2.8.8 格式化 + 标题级别调整（headerStartLevel=2）+ 自动编号（autoNumbering）。保证与用户 Obsidian 保存时的输出一致，用户无需手动再保存格式化。`raw/` 目录已被脚本排除，禁止格式化。
- **规则文件例外**：`AGENTS.md`、`CLAUDE.md` 这类规则/桥接文件必须保留既有标题层级和章节引用，不应用自动编号改变其 Schema 结构；修改规则文件后只做最小文本调整和人工自查。
- **禁止手工整篇格式化/重排**：不要自己手动重排段落、改动 callout 写法、动 emoji 标题、合并/拆分章节。格式统一交给 `tools/format.mjs`，AI 只做**最小必要内容改动**。
- **图片处理边界**：图片是理解型笔记的一部分，Ingest 源文件含图片时，AI 整理 Wiki 必须结合图片与正文组织内容，不得默认省略图片。
  - 远程图片 URL：在目标 Wiki 笔记中按上下文原样保留嵌入，可补充简短图注；AI 不主动下载、转存或上传到图床。
  - 本地图片：**不拷贝到 wiki 目录**（用户上传图床后还得删一次，避免双份）。在目标 Wiki 笔记中用 Obsidian 双链 `![[图片名.png]]` 嵌入 raw 原图（Obsidian 按文件名全库解析，只要仓库内存在即可显示，且对特殊字符路径最稳）；prettier-dev 插件已支持识别 `![[...]]` 图片上传图床（该插件同时支持 `![](...)`、`<img src>` 与 `![[...]]` 三种形式），上传后会把整条 `![[...]]` 替换为 `![...](CDN URL)` 形式的 Markdown 图片；无需手动处理。
  - 失效图片：若本地相对路径解析不到该 raw 文件或无法读取，不臆造替代图，不删除引用事实，在回复图片清单中标明"原图缺失/无法读取"。
  - 完成后必须在回复末尾列出「涉及图片的文件清单」：远程图片列 URL，本地图片列 raw 原路径与对应 wiki 文件，方便用户用图床插件的 "Upload all images" 上传或替换（用户明确要求汇报到文件粒度）。
  - `tools/format.mjs` 刻意跳过图床上传步骤。
- **禁止改变链接约定**：内部引用统一用 Obsidian `[[文件名]]` 双链格式，不要写成相对路径或全路径。
- **禁止删除内容**：除非用户明确要求，AI 不得删除人类笔记中的任何文字。
- **保持中文表述习惯**：与库内现有笔记风格一致，不要夹带英文术语堆砌。
- **博客发布兼容（强制）**：用户笔记会发布到博客，AI 创建的页面正文与 summary 中不得出现课程语境用语（如「课程」「老师」「讲师」「授课」「课件」「袁进」等具体作者/导师名），一律改为中性表述：「课程→系列/内容/正文」，「课件→源文件/讲义/正文」；不得引用或标注原始教程作者、机构。raw/ 内部路径与 refs.raw 中的含词文件名（如 `课件.md`）属内部引用，不受此限。

### 1.4 工作流

#### 1.4.1 Ingest（摄取新资料）

1. 新资料（文章/PDF/笔记）先放入 `raw/`，AI 只读引用，不做任何格式化（`tools/format.mjs` 已排除 `raw/`）。
2. 读取 `raw/` 后，AI 应按主题提炼成新的 Wiki 页面；新页面可以放入任意合适主题目录，frontmatter 标为 `author: ai`、`ai_editable: true`、`summary`、`refs`、`updated_by: ai`。
   - `summary` 必须写一句话摘要。
   - `refs.raw` 必须记录直接依据的 raw 源文件路径与 sha256。
   - `refs.pages` 必须记录写作时实质参考或依赖的 Wiki 页面；只是正文里顺手提到的概念，用双链即可，不必放入 `refs.pages`。
3. 若新资料与已有 `ai_editable: false` 人类笔记相关，AI 不得直接改旧笔记正文；应先新建 AI 整理页，并在回复中列出建议关联的旧笔记。需要把内容并入、重构或实质性修改旧笔记时，必须先询问并获得用户明确授权。
4. **确定存放位置（写页面前的第一道判断）**：
   - 先对照根目录 `index.md` 与现有目录树，判断新内容能否归入某个**已有主题目录**（含子目录）：能归入 → 放到对应目录，文件名沿用该目录的命名习惯。
   - 找不到合适归属 → **新建**符合层级与命名规则的主题目录，再放入。
   - 存放规则：
     - 顶层目录 = 大主题，中文语义化命名（如 `Linux`、`Python`、`前端工具链`、`面试总结`）。
     - 子目录 = 细分主题（如 `Linux/服务管理`、`Python/基础`、`面试总结/Vue3`）。
     - 文件名：同目录内风格统一，Linux 区常见 `【分类】标题.md`（如 `【服务】Nginx 详解.md`），Python 区常见 `主题.md`（如 `Python函数.md`）。
     - 不相关的内容**不得**塞进不匹配的目录。
5. **源文件含图片时，整理 Wiki 必须图文结合**：
   - 先识别图片类型：远程 URL、本机可读取图片、本机缺失/不可读取图片。
   - 远程图片 URL → 在目标 Wiki 笔记中按原位置或语义位置保留图片嵌入，必要时配简短中文图注，帮助理解正文。
   - 本机可读取图片 → 在目标 Wiki 笔记中用 Obsidian 双链 `![[图片名.png]]` 嵌入 raw 原图（不复制进 wiki，Obsidian 按文件名全库解析），必要时配简短中文图注。
   - 本机缺失/不可读取图片 → 不臆造替代图，不删除引用事实，在回复图片清单中标明“原图缺失/无法读取”。
   - **完成后必须在回复末尾列出「涉及图片的文件清单」**：远程图片列 URL，本地图片列 raw 原路径与对应 wiki 文件，缺失图片列原始路径与缺失状态，方便用户用 Obsidian 的 "Upload all images" 命令上传到图床或手动替换。
6. 完成后：如新增或移动 Wiki 页面，更新根目录 `index.md`；在 `log/` 当月文件追加记录（见 4.4）。
7. **双链自查（硬性）**：AI 新建或实质性整理出的页面，完成后必须自查是否成了知识网络孤岛：
   - 存在语义相关的页面 → 用 `[[文件名]]` 双向补链：新页引用相关页；若关联页 `ai_editable: true` 且补链成立，可回补一条双链。人类笔记（`ai_editable: false`）**不得**加回链，只能由新页单向指向它。
   - 确实无关联页面 → 允许暂成孤岛，但必须在回复末尾说明「该页当前无关联页面，已自查无需补链」。
   - 依据语义关联判断，禁止机械堆砌：不强行引用不相关页面。

#### 1.4.2 Query（查询）

1. 先读根目录 `index.md` 定位相关页面，再深入阅读，综合出带引用的答案。
2. 好的答案（对比、分析、总结）可以写成新页面存入 Wiki；新页面按主题归入合适目录，frontmatter 标为 `author: ai`、`ai_editable: true`、`summary`、`refs`。不得因此擅自修改已有 `ai_editable: false` 页面。
   - 若新页面来自查询综合，`refs.pages` 记录回答时实际读取并依赖的 Wiki 页面；没有 raw 依赖时 `refs.raw: []`。
3. 涉及 `raw/` 的资料，引用时注明来源文件。

#### 1.4.3 Lint（体检）

定期检查并报告（**只报告，不擅自改**）：

- 页面间矛盾
- 被新资料推翻的过时结论（stale claims）
- 无入链的孤岛页面（AI 新建页按 1.4.1 序号 7 自查过链；此处只报告历史遗留孤岛）
- 被频繁提及但没有独立页面的概念
- 人类笔记区中待处理的 AI 建议
- `summary` / `refs` 元数据缺失
- `refs.raw` 中记录的 sha256 与当前 raw 文件内容不一致

修复可修复项后，更新 `index.md`、追加 `log/` 当月文件。

机械项优先用本地脚本检查：

```bash
node tools/wiki-lint.mjs
```

#### 1.4.4 修改流程要求

- 每次操作前：用 `git status` 确认当前状态。
- 每次修改：**只涉及必要的文件**，改完先自查 diff。
- 每次操作后：在 `log/` 当月文件（如 `log/2026-08.md`）追加一条记录：
  ```
  ## [YYYY-MM-DD] <操作类型> | <摘要>
  - 涉及文件：...
  - 修改内容：...
  ```
  当月文件不存在则新建，条目格式沿用上面的模板；跨月后新建下个月文件。

### 1.5 快速判断指南

| 我想知道          | 怎么看                                        |
| ----------------- | --------------------------------------------- |
| 这篇是谁写的？    | 看 frontmatter `author`（human / mixed / ai） |
| AI 能不能改这篇？ | 看 frontmatter `ai_editable`                  |
| AI 最近改过哪些？ | 用 Dataview：`WHERE updated_by = "ai"`        |
| 哪些是人机协作？  | 用 Dataview：`WHERE author = "mixed"`         |
| 上次干了什么？    | 看 `log/` 当月文件末尾                        |
