# AGENTS.md — 未来架构师笔记 · 维护规则

这是本知识库的**规则层（Schema）**。任何 LLM Agent 在操作本仓库前，必须完整阅读本文件并严格遵守。

## 1. 目录结构（三层）

```
未来架构师笔记/
├── AGENTS.md        # 本文件：规则层，告诉 AI 怎么干活
├── raw/             # 原始资料层：源文档，AI 只读，永不修改
│   └── operations-*/# Linux/DevOps 笔记的原始教学资料
└── wiki/            # 知识层：全部笔记（AI 生成 + 人类手写）
    ├── index.md     # 全库目录（AI 维护）
    ├── log.md       # 操作日志（AI 维护，只追加）
    ├── Linux/       # AI 生成区：ai_editable: true
    └── 其余目录/      # 人类笔记：ai_editable: false，AI 只读
```

## 2. 所有权规则（最优先，违反即违规）

每篇笔记的 frontmatter 决定 AI 能否修改。**判断依据只有一个：frontmatter 里的 `ai_editable` 字段。**

### frontmatter 字段说明

```yaml
---
author: human        # human=人类手写 | ai=AI生成 | mixed=人机协作
ai_editable: false   # false=AI只读（人类笔记） | true=AI可自由维护
updated_by: human    # 最近一次修改者：human / ai
updated: 2026-08-02  # 最近修改日期
---
```

### 硬性规则

1. **`ai_editable: false`（人类笔记）**：AI 只能 **读** 和 **引用**，**严禁修改内容**。
   - 想补充/修正 → 先以建议形式提出，用户明确同意后才能改，且只改用户同意的最小范围。
   - 需要链接 → 允许在**其他 AI 拥有的文件**里添加指向该笔记的 `[[链接]]`，但绝不改动该笔记本身。
2. **`ai_editable: true`（AI 笔记，当前为 `wiki/Linux/**`）**：AI 可自由创建、更新、维护，但仍须遵守第 3 节的边界。
3. **没有 frontmatter 的文件 = 按 `ai_editable: false` 处理**（默认人类笔记，AI 只读）。
4. **`raw/` 目录：永远只读**。不新增、不删除、不修改任何内容，连 frontmatter 都不能加。
5. 每篇**新建**的 AI 笔记必须带完整 frontmatter，`updated_by: ai`，并更新 `index.md`。

## 3. 修改边界（防止污染人类笔记生态）

本 vault 使用了以下 Obsidian 插件，AI 的写入必须与之兼容：

- **禁止整篇格式化/重排**：不要重排段落、不要改动 callout 写法、不要动 emoji 标题、不要合并/拆分章节。只做**最小必要改动**。用户的 prettier 插件会在 Obsidian 内统一格式，AI 不介入。
- **禁止新增、替换、删除图片**：图片都托管在用户自己的图床（PicGo COS），AI 一律不碰。需要配图时，引用已有的图片地址，或写 `TODO: 需要配图`。
- **禁止改变链接约定**：内部引用统一用 Obsidian `[[文件名]]` 双链格式，不要写成相对路径或全路径。
- **禁止删除内容**：除非用户明确要求，AI 不得删除人类笔记中的任何文字。
- **保持中文表述习惯**：与库内现有笔记风格一致，不要夹带英文术语堆砌。

## 4. 工作流

### 4.1 Ingest（摄取新资料）

1. 新资料（文章/PDF/笔记）先放入 `raw/`，AI 只读引用。
2. 若资料属于 AI 可编辑区（如 Linux），读取后提炼成 Wiki 页面，更新相关页面并做交叉引用。
3. 若资料属于人类笔记区，AI **不写页面**，只向用户提出整合建议。
4. 完成后：更新 `index.md`，追加 `log.md`。

### 4.2 Query（查询）

1. 先读 `wiki/index.md` 定位相关页面，再深入阅读，综合出带引用的答案。
2. 好的答案（对比、分析、总结）可以写成新页面存入 Wiki，但仅限 `ai_editable: true` 区域；其余以建议形式给出。
3. 涉及 `raw/` 的资料，引用时注明来源文件。

### 4.3 Lint（体检）

定期检查并报告（**只报告，不擅自改**）：
- 页面间矛盾
- 被新资料推翻的过时结论（stale claims）
- 无入链的孤岛页面
- 被频繁提及但没有独立页面的概念
- 人类笔记区中待处理的 AI 建议

修复可修复项后，更新 `index.md`、追加 `log.md`。

### 4.4 修改流程要求

- 每次操作前：用 `git status` 确认当前状态。
- 每次修改：**只涉及必要的文件**，改完先自查 diff。
- 每次操作后：在 `log.md` 追加一条记录：
  ```
  ## [YYYY-MM-DD] <操作类型> | <摘要>
  - 涉及文件：...
  - 修改内容：...
  ```

## 5. 快速判断指南

| 我想知道 | 怎么看 |
|---|---|
| 这篇是谁写的？ | 看 frontmatter `author` |
| AI 能不能改这篇？ | 看 frontmatter `ai_editable` |
| AI 最近改过哪些？ | 用 Dataview：`WHERE updated_by = "ai"` |
| 上次干了什么？ | 看 `log.md` 末尾 |
